# M2 — Chromium 进程标志代理（`--proxy-server`）验证（2026-10-29，负结果）

机制：M1 全部向量（应用内 `http.proxy` + 进程 env）之上，追加 Electron/Chromium 进程标志 `--proxy-server=http://127.0.0.1:8888` 启动 WB，验证「模型请求是否走 Chromium 网络栈」。

## 结果（负结果，可发布）

- 探针会话 `b62e6a25`（WB 5.9.3，13:59:26.4 发题 → 13:59:33.3 completed，7 秒）。
- 监听捕获 254 个 CONNECT，全部为服务面主机（www.workbuddy.cn×174 等 8 个主机）；**模型面零流量进监听**。
- 任务窗口内（13:59:26–31）Electron 进程再次出现 **4 条新的直连 `119.147.114.214:443`**（本地端口 60543/60544/60545/60564，见 [m2-lsof-chain.redacted.txt](<m2-lsof-chain.redacted.txt>)）。
- 结论：**Chromium 栈假设被实证排除**——若模型请求走 Chromium 网络栈，`--proxy-server` 必然生效；它没有。模型客户端是进程内原生 Node 类 HTTP 栈（后续 M3 采样证实为 daemon 进程 worker 内的 Node TLS 连接）。
- 附带价值：跨版本（5.8.3 → 5.9.3 同日自动更新）模型面行为一致：同样的直连、同样的目标 IP。
- 版本事件披露：M2 启动时 WB 自动更新器触发 5.8.3→5.9.3 升级并接管重启一次（update-20261029.log，私有日志仅叙述）；之后全部探针在 5.9.3 上进行，M1 证据产生于 5.8.3。
