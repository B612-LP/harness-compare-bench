# 2026-10-16 批次方案：CLI 赛道（Codex / DSH × GLM 各两份）

> 本批为课题"表现现场"的首批正式采集：**两个自建用例 × 两个有 CLI 的 Harness × 同一 GLM 模型**，产出四份可复核的完整测试现场。工具链见 `工具链/`，成绩汇总见 `../3-表现现场/README.md`。

## 一、范围与对照组

## 二、控制变量清单（对照实验公平性）

1. **模型与通道**：同模型 glm-5.3-flash；Codex 走 `wire_api="responses"`，DSH 走 `openai-responses`——**协议对齐**（DSH 三协议任选中特意取与 Codex 同款）。
2. **联网能力**：Codex `disable_web_search=true`；DSH patch 禁用 web 工具。排除"一边能搜一边不能"的不公平变量。
3. **权限形态**：Codex `--dangerously-bypass-approvals-and-sandbox` ≡ DSH `DSH_PERMISSION_MODE=danger-full-access`，均为无人值守批跑形态。
4. **版本锁定**：Codex 0.162.1 / DSH 0.2.0-rc.2，装机版本不符即拒绝跑。
5. **环境同构**：同一 Docker 任务镜像、同一代理 overlay（v2）、同一超时倍率（3×）、同一评分器。
6. **模型标注**：DSH headless 无 `--model` 覆盖（官方设计如此），模型经配置层（`cordis.patch.yml`）锁定，`-m` 仅作轨迹标注——两边模型身份在各自配置快照里可查证。

## 三、评分与闸门

每用例正式评分前先过 **nop=0（空跑准入）** 与 **oracle=1（参考解门）**，四道闸门全过才收产品分。判定标准与陷阱设计见 `../4-打分细则/打分表.md`。

## 四、已知口径缺口（写报告前需处理）

1. **成本**：LiteLLM 无 GLM 定价，`cost_usd=null`，按智谱费率离线换算（注明取数日期）。
2. **缓存计费**：智谱 cached token 计入口径需在报告披露（cached 占比高）。
3. **每 trial 环境安装**：Codex 装 node22+CLI、DSH 装 node24+CLI（各约 3-6 分钟）是时间方差来源；正式大批量跑可做预装基础镜像降方差。
4. **DSH 模型元数据**：手写 `glm-5.3-flash` 条目继承默认上下文/输出上限（262,144 / 32,768），非智谱官方数；Codex 侧同类 fallback（"Model metadata not found"）——两边同为估算，横向对比公平，绝对数值慎引。

## 五、环境实况（2026-10-16）

- WSL→智谱**直连中断**（IPv4/IPv6 均超时），代理链路正常 → overlay v2 改为智谱走代理（Ubuntu 源仍直连）。
- dsh 0.2.0-rc.2 在 Node 22 下**静默零输出**（`import.meta.main` 入口守卫），必须 Node 24+。
- 已知反复故障点：portproxy 监听丢失（Windows 下 `net stop iphlpsvc && net start iphlpsvc` 修复）；排障顺序：先确认 WSL 出网（`curl -sS -m 5 https://open.bigmodel.cn` 超时即代理/转发问题），再查 overlay 代理链路（`docker compose` 内 `curl` 端点），最后才是凭据与版本。
