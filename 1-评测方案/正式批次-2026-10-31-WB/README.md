# WorkBuddy 正式网关产品轨（2026-10-31）

## 评测对象与决策

本批补齐公告要求的 WorkBuddy 五题正式产品评测。2026-10-31 用户明确授权补齐；这是开启网关产品轨的新决策，不推翻[此前不准入同模型 A 组的裁定](<../准入预检-2026-10-29/裁定-2026-10-30-wb-正式轨道.md>)，不将历史观察分追认为正式成绩。

- 新组 `W_gateway`：WorkBuddy 桌面端 + 产品网关 + DeepSeek V4.1-Flash 标签（`deepseek-v4.1-flash`）、思考档 low、fullAccess、craft；不注入评测者技能或自定义 session settings。产品自身身份上下文、内置工具/技能按实际轨迹披露，不宣称已剥除。
- 分数描述**该配置下整体产品交付表现**。后端实际模型、网关参数映射/系统注入/重试不可证，保留为未排除的同模型归因局限；既不填零，也不伪装已验证同模。
- 不加入 A_same_model 或 B_native，不作五款总排名、不声称纯 Harness 因果优势。CLI 与桌面分列；同题结果仅作描述，不从 CLI 反推桌面能力。
- 新合同、新计划、新批身份，五题各一场，n=1；旧代正式 20 行、历史观察及失败裁定均不改写。

## 前瞻协议

[注册计划](<registration-plan.json>) 在真实发送前登记全部五场，后由[独立冻结合同](<../../4-打分细则/可信冻结-20261031-wb-v1/README.md>) 绑定计划、题目、判卷器和准入规则。每槽仅一次发射，本批不自动补跑、不择优；已注册尝试全量导入，污染、证据不足、发射失败均如实保留但不伪装产品零分。有效失败按原 checker 判分。

沿用五道现行用例，不增加题量。实际时限取各 case.json；完成按产品 DB 终态且轨迹稳定，或末条 assistant 已回答且无未回应工具调用并稳定 60 秒；超时冻结当时产物，不把后续写入混入判卷。五题串行执行，避免同时共享负载制造额外混杂。

工作区在仓库外且每题独立，仅复制输入、题面与运行清单；不放 truth、参考解或 checker。运行中不干预答案、不告知判分结果。
