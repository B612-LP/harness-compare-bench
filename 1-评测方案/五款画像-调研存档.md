## 一、Codex app（OpenAI）

**形态**：官方名 "Codex app"。macOS（Apple Silicon/Intel）2026-02-02 首发；Windows 2026-03-04 上架 Microsoft Store（MSIX 自动更新，原生沙箱+PowerShell，可切 WSL）。桌面 UI 壳闭源，核心与 `codex app` 启动器在开源仓（github.com/openai/codex，Apache-2.0，128.9k stars）——app 经 app-server JSON-RPC 协议驱动开源核心。**品牌注意：2026-07-09 起显示名/文件名/入口并入 "ChatGPT"（Windows 包身份仍 `OpenAI.Codex`、可执行入口 `ChatGPT.exe`，产品身份不变）**；MS Store 条目显示名即 "ChatGPT"。无 Linux 独立 app（弱证据：统一 ChatGPT 桌面 Linux Preview 含 Codex，2026-08-11 起，deb/rpm）。
来源：developers.openai.com/codex/app · github.com/openai/codex README · DisplayCatalog API（9PLM9XGG6VKS，2026-10-13 实抓）

**模型可换（A 组关键）**：✅ 但**通道收窄（重大变化）**——官方原文 app 与 IDE/CLI 共享同一配置，编辑 `~/.codex/config.toml`：
```toml
model = "example-model"
model_provider = "example"
[model_providers.example]
name = "Example"
base_url = "https://example.com/v1"
env_key = "EXAMPLE_API_KEY"
wire_api = "responses"   # 唯一可选值；"chat" 已移除（反序列化直接报错，指向 discussions/7782）
```

来源：github.com/openai/codex codex-rs/model-provider-info/src/lib.rs（一手源码）· releases 0.161.0 notes

## 二、DeepSeek Harness Desktop（DSH）

**形态**：官方定性"完整 dsh Web 应用的 Electron 壳"（仓库 `apps/desktop`），与 `@deepseek-ai/dsh` **严格同版本发布**（"A dsh upgrade is a Desktop release"）。打包 macOS + Windows，无 Linux（下载页仅两包）。developer preview。整体开源（MIT，248.6k stars）。

来源：deepseek.com/download/（一手，直链已验证）· apps/desktop/README.md（应用内签名更新单元自更新）

**模型可换（A 组关键）**：✅ 且是 GUI 级支持，**本轮复核机制无变化**（providers.md 近两周零提交）——Settings → Models → **Custom model API**：Provider ID（小写永久）+ base URL + 协议三选一（OpenAI Chat Completions / **OpenAI Responses** / Anthropic Messages）+ key + 模型名；落盘 `$DSH_HOME/profiles/desktop/cordis.patch.yml`（key 在 `~/.dsh/.credentials.yaml`，write-only）。内置第三方卡片含 **zai（GLM）**，填 key 即用；国内 bigmodel 走 custom provider + compat 开关。注意：`desktop` profile 名被 Electron 独占（CLI 拒绝 boot 它），跑批用独立 profile。
来源：docs/user/guide/providers.md（一手）

**会话取证**：每会话一个 append-only JSONL（默认 checksummed Zstandard 帧，`compression: 'none'` 得明文行）；**存储 `root` 必须显式配置且无默认值**；每批 append 带 fsync、崩溃时撕裂尾帧只保留完整记录。机制无变化；新增治理层：**V4 格式允许"评审记录 + reader-compatibility"前提下的同版本 schema 变更**（docs/session-format-status.md）——评测脚本解析会话文件时留意小版本差异。崩溃日志：Win/Linux 在 Electron userData/logs，保留 10 份。
来源：packages/session/session-persistence-jsonl/README.md（一手）· docs/session-format-status.md

**能力边界**：workspace 读写、持久 bash/pwsh、侧栏浏览器（Electron WebView）、**办公是桌面版一等公民**（捆绑离线 Python：numpy/pandas/python-docx/python-pptx/openpyxl/XlsxWriter）、插件/子代理/定时任务。权限=按 policy 弹批准；官方 SAFETY.md 明示沙箱不构成安全边界。alpha 线变化：alpha.1 桌面端默认改 OS 分配端口（规避 Windows 保留端口段，破坏性）；alpha.2 升 Electron 44.7.0 + Windows PTY 清理/图片预览/安装器修复，Windows 安装包 CI 仍在补建。
来源：releases dsh-v0.2.1-alpha.1 / alpha.2 notes（一手）

**自动化**：`dsh --profile headless "<job>"`、`--profile acp`、`--profile sdk(-minimal)`（JSON-RPC over stdio）、Python SDK `deepseek-harness-sdk`。**SDK 漂移警告：PyPI latest 仍 0.1.5rc1（2026-09-10），仓库已新增 `get/set_working_directory` API 未发 PyPI**——锁 PyPI 版本会缺新接口；`dsh_home`/`DSH_HOME` 必填、`DEEPSEEK_BASE_URL` 契约无变化。alpha.2 破坏性变更若干：Agent Team 消息改直投 Inbox、SDK 默认 profile 改通用身份、移除工具展示 both 模式。
来源：PyPI deepseek-harness-sdk/json · python/sdk/README.md（一手）

**版本**：release dsh-v0.2.1-alpha.2（2026-10-09）；npm latest=0.2.0-rc.2，均无新版本。评测建议锁 0.2.0-rc.2（break 风险），直接用下载页直链（当前即 rc.2 构建）。

## 对评测方案的影响（2026-10-13 两轮后结论）

1. **A 组锁 GLM 在桌面端仍成立，但 Codex 通道收窄（本轮最重要变化）**：Codex `wire_api="chat"` 已移除，**只剩 responses 一条通道**——GLM `/api/v1` responses 端点此前实测可行，但装机第一步必须先验（这是 Codex 接 GLM 的唯一路径）；DSH 三协议任选（建议 openai-responses 对齐 Codex）；WorkBuddy 走 chat completions（OpenAI 兼容）。三款协议不对称照 WorkBuddy Bench 格式披露。
2. **取证分层设计（含本轮新增取证面）**：Codex/DSH/WorkBuddy 有结构化本地证据（JSONL/日志 zip/workspace）；Codex 评测脚本需兼容 `.zst` 压缩 rollout 与 `thread_history_1.sqlite`；豆包按官方口径本地模式"不持久化"→ 产物证据以会话内展示+云盘+录屏为准（企业版日志是升级项）；元宝只有导出+录屏。评分脚本以"产物文件"为统一判分面，轨迹证据分级使用。
3. **"桌面端口径"要定义**：Codex/DSH 桌面端与 CLI 同核心——评测驱动 GUI（人工/半自动+录屏），还是用同核心 headless 跑批+披露"同核心不同入口"？建议：正式实验以 GUI 为主（公平），headless 只作链路调试。WorkBuddy 无 headless，本身就是"纯 GUI"对照组。
4. **五款均大陆网络直连可用**，无需科学上网。安装渠道统一走官网直下（WorkBuddy MS Store 渠道滞后到 5.0.2，勿用；Codex MS Store 即官方渠道可用）。
5. **待实测清单（装机后第一周，2026-10-13 第二轮更新）**：
   ① 元宝 PC 端有无专家模式（联网两轮均无 PC 一手证据，画像已倾向"移动端功能"；实测定生死）
