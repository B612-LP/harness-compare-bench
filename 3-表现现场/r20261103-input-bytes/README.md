## 公开件如何复算

仅需 Python 标准库；**不调用模型、网络、产品或真实凭据**。在仓库根目录执行，输出名必须是未存在的新目录：

```bash
python3 -B 3-表现现场/r20261103-input-bytes/recompute.py \
  --root 3-表现现场/r20261103-input-bytes \
  --output /tmp/input-byte-recompute-new
```

[复算程序](<recompute.py>)逐场读两次请求及 SSE、真实工具文本、退出状态，输出指标与判定。公开复算得到 14 条 live 场记录（两 pilot 分开），6 对确认；[另 8 场 mock](<batch-events.json>)只公开分账摘要，不作为确认或产品正确性样本。原始捕获保存在私档，不能从这些派生件倒推原件封印“全部通过”。

## 脱敏与哈希

[派生说明](<derivation.json>)逐请求登记原件与派生件的输入/body 大小相等。7 个输入字符串中的私人文件路径，替换为**相同 UTF-8 字节数的 ASCII P**，其余输入结构及字段保留；因此原件和派生件的内容哈希不同，但主字节指标不变。SSE 解析成事件 JSON 后重新分帧，明确不是原始网络流。上游编码失败的二进制响应只公开大小、哈希和失败原因，不猜测算法。

每次捕获元数据中的原始 body/SSE 哈希仍指向**私档原件**，不是旁边派生文件的校验和。公开文件本身以[公开派生清单](<publication-manifest.json>)校验；清单分列 source / derived 哈希与大小，source 不可公开时明确标记。公开重算的 6 对主数值、有效性和双键端点均与私档原件复算一致；这是一项技术复算，不是真实第三方签名。

公开材料保留失败 pilot、第二 pilot、全部确认、预算和 unknown，不公开私人运行器、内部计划、代理分工记录、配置凭据、无关用户信息。source hashes 是内容身份，不是签名；当前没有可声称的真实第三方核验人、时间或签名。

## 辅助用量与缓存

每场提供原生 usage 事件摘录，例如[inline 块1](<runs/confirm-b01-inline/reported-usage.json>)、[块2](<runs/confirm-b02-inline/reported-usage.json>)、[块6](<runs/confirm-b06-inline/reported-usage.json>)及[bounded 块1](<runs/confirm-b01-bounded/reported-usage.json>)。逐事件保留，不假设各事件可以相加或无重复。

原生 cache 报告随场次不同，不能当作已控制变量；独立 reasoning token 字段缺失仍为 unknown。请求 UTF-8 字节、usage token 和费用不是同一个量，**本批不比较 tokens / 费用 / 缓存因果效应**。

## 仍然不能回答

- native / instrumented 差异：相同的 relay 处理两条件，但它全缓冲、规范化编码头，不能证明原生透明或比较时延。
- 归因：支持同 DSH 工具结果序列化/外溢策略的局部干预；不是五款产品的纯 Harness 优劣结论。
- 信息：双键端点正确不代表中部信息无损；bounded 确实省略了夹具中段。
- 服务端：只能直接观测客户端序列化请求，不能确认服务端最终模型输入、实际 reasoning 或私有缓存状态。
- 执行器：本批完整数据复核无漂移，不代表所有失败条件都有完备实时停止守卫；具体缺口见[研究合同](<../../1-评测方案/请求侧输入字节-2026-11-03/README.md#停止纪律及其机械保证边界>)。
- 核验与桌面：内部复算不是第三方见证；这些 CLI 配置也不是五款桌面产品的操作系统隔离证据。
