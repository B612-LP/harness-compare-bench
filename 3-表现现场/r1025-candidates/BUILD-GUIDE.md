# r1025 候选用例：构建与检查方法摘要

> 本文是对既有构建规范的后期公开方法摘要，**不是旧封印文件的原文或替代封印**，也不代表这些用例或判分器已经按本文在当前环境重新运行、复验或通过。具体用例的实际版本、运行记录及判定应以对应原始证据为准。

## 用例构建

将选定的公开题或自建题改造为自包含用例，区分参与任务的输入与仅供检查的参考答案。原规范建议的结构如下，具体存在与否以各用例文件为准：

```text
cases/<case-id>/
  instruction.md       任务说明、输入输出要求及相对路径
  spec.md              判分模式、观察项与权重、运行约定、负例、来源和许可
  truth.json           期望值、输入 SHA-256、来源、许可和版本
  checker.py           确定性判分入口
  inputs/              供任务执行方读取的素材
  solution/            自测使用的参考产物，不复制给任务执行方
  task.toml            任务名称、版本、描述、时限和产物元数据
  case.json            输入复制方式及运行时限
  selftest.stdout.txt  自测原始输出（如实际保存）
```

任务说明应独立可读，写清必要约束和输入输出格式，避免泄露参考答案或不必要的判分细节。使用相对运行目录的路径；若运行器将用例的 `inputs/` 复制到运行目录的 `inputs/`，题面应相应使用 `inputs/...`。用例元数据可用 `{"inputs":[["inputs","inputs"]],"timeout_s":1800}` 表达这一复制约定与示例时限；实际时限以对应用例配置为准。

## 判分契约

原规范约定以下调用形式：

```text
python3 checker.py <run_dir> [--json]
python3 checker.py --selftest
```

正式判分结果的最后一行是 JSON；使用 `--json` 时只输出这一行，包含用例标识、二值 `reward`、0–100 的 `weighted` 分数和逐项 `checks`（标识、通过状态、说明）。二值奖励可按预先写入 `truth.json` 的达标阈值判定，`weighted` 表示实际得分率乘以 100。自测全部通过时退出码为 0，否则为 2。

判分应由确定性程序完成，不使用模型裁判。检查对象限于运行目录中的产物，参考配置和标准答案从判分器同目录读取；不联网、不安装包，不依赖 `/tmp` 或仓库其他路径中的数据。判分器只使用 Python 标准库。

输入完整性检查包括：参考配置中记录的输入 SHA-256 与用例输入不符时报告错误并以退出码 2 结束；运行目录中的输入副本若被修改，应令 `reward=0` 并记录完整性检查失败；参考配置与判分器常量不一致时报告错误。自测中的临时目录可使用标准库创建，结束后清理，不污染用例目录。

## 自测、负例与证据

在正式使用前，保存可追溯的自测原始输出，并至少检查：

1. 空运行目录（nop）得到 `reward=0`。
2. 将参考产物复制到临时运行目录（oracle）得到 `reward=1`。
3. 至少六组独立的近正确负例各自得到 `reward=0`，例如遗漏、格式错误、修改输入、冗余或缺失内容、阈值边界及误用数据列；具体选择应覆盖该用例的关键约束。
4. 篡改用例输入时，完整性守卫返回 0 或报告错误。

记录用例版本、来源及许可、依赖、观察项与权重、达标线、自测结果、输入体积和未决问题；保留原始输出，而非仅保存通过结论。自测、参考答案回归与产品实际运行是不同证据，不应互相替代。正式比较还应核对规则冻结、题面及证据有效性和污染情况；未知项应说明影响、下一步和停止条件，不能直接当作失败或自动折算满分。

## 适用条件与来源

原规范以 Python 3.9 标准库及基础 shell 为环境基线，不要求第三方 Python 包；为支持不提供真实终端的产品，任务应能通过读写文件完成，允许直接计算或手工生成产物。输入目标为每例不超过 25 MB；超过时应在规格中说明裁剪方案。这些是构建约束，不是对各产品实际环境或兼容性的保证。

记录来源名称、URL、许可证、读取日期及是否改写，并核实实际许可是否允许所采用的改写和数据使用方式。第三方题面用自己的话重写，同时保留必要约束、输入输出格式及应有署名；若移植官方判分器或测试，应在相应文件注明来源与许可。具体授权条件以来源许可证为准。
