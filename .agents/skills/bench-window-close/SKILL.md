# bench-window-close：until 窗口收尾判断

## 触发

- 定时收尾轮（时间门预留时段开始的调度消息）；
- 用户说「收尾」「能收了吗」「结束这个窗口」；
- 目标收口前必须先跑完本技能。

## 判断顺序（先判后动，不许跳）

1. **实跑时间门**（不许用缓存结论）：
   ```
   python3 .agents/skills/research-loop/scripts/time_gate.py \
     --deadline "<合同截止>" --reserve-seconds <预留> --estimate-seconds <估时> \
     --completion-check
   ```
   - exit 0：到点且余量合规，允许进入收尾执行。
   - exit 3：未到点 → 输出剩余时间，不收尾；若所有合同项已闭环，如实说明"无事可做、等下一轮/等调度"，禁止 sleep/轮询空转，结束回合。
   - exit 2：参数错，修正后重跑一次；仍错则报告。
2. **逐项核对窗口合同固定清单**（读合同原文，逐项标 ✅/❌/未知，未知不得写✅）。典型项：授权范围内实验是否闭环并落档、公开仓是否已推、规范是否升版、冻结边界（正式25格/冻结原件/历史分数/周报）是否未动、遗留缺口是否如实登记。
3. **分支**：
   - 全部 ✅ 且 completion-check exit 0 → 执行收尾。
   - 有 ❌ → 只做**封存类**动作（补文档、补裁定、补提交），不开新实验；补完重跑第 1-2 步。
   - 有「外部依赖未完成」（如第三方验收）→ 如实写入遗留缺口，不冒充完成，照常收尾（缺口清单是收尾产物的一部分）。

## 收尾执行（全过才做）

1. 写 `<私档窗目录>/WINDOW-COMPLETION.md`，五段：
   最后实质封存时点；completion-check 实跑时戳 + exit code + 命令原文；窗口提交数与最终 HEAD；产物清单（报告页/规范版本/裁定文件路径）；遗留缺口清单（含未执行项与原因）。
2. `update_goal` complete（仅当 exit 0 且清单核毕）。
3. 如有本会话专属调度任务（收尾轮本身），完成即止；不删除其他任务。

## 纪律

- 预留时段内禁止新实验、新发射、新提交内容（封存类文档/提交除外）。
- 收尾产物必须可复核：命令、时戳、HEAD、路径全部实值。
- 不发周报，不做合同外承诺。
