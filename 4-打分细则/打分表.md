## 一、评分总则：三道闸门（oracle-gating）

任何用例进入正式评分前必须先过两道准入闸门，否则用例作废：

| 闸门 | 观察项 | 判定标准 | 不达标处置 |
|---|---|---|---|
| 1. 空跑准入（nop） | nop 空操作 agent 跑本用例的 reward | 必须 = 0 | 用例作废：存在"白给分"路径，改任务或改测试 |
| 2. 参考解门（oracle） | `solution/solve.sh`（gold patch）跑本用例的 reward | 必须 = 1.0 | 用例作废：完成条件不可达或评分器有误 |
| 3. 正式评分 | 待测 Harness × 统一裁定模型的 reward | 按用例细则判定 | 进入归因：模型层 / Harness 层 / 环境层（见 `归因定责.md`） |

原则：

1. **headline 分数只认确定性 verifier**（脚本逐项检查）；LLM judge 不进 headline。
2. **每份"表现现场"必须连同评分证据入库**（`reward.txt` / `test-stdout.txt` / `trajectory.json`），结论可复核。
3. **评分器离线自足**：测试执行期禁止联网下载工具。教训案例：v1 演示跑（2026-10-13）——verifier 现场联网下载 uv 失败，测试未跑即判 0，属环境层失误而非模型层失败；该次原始日志未入仓，作为方法教训记录在 `5-评测报告/未知登记.json` 的 `env-v1-verifier-download`。**任何 0 分先读 `test-stdout.txt` 确认"测试到底跑没跑"，再谈模型行不行。**

## 二、用例级细则

### int-sum-sort（hello 级 · 流水线验证）

任务：读 `/app/input.txt`（6 个整数逐行），产出 `/app/output.txt`：第 1 行求和、第 2 行个数、其后升序逐行整数、末尾换行。

| 观察项 | 检查点（tests/test.sh） | 赋分 |
|---|---|---|
| output_exists | `/app/output.txt` 存在 | 必要条件，缺失直接 reward=0 |
| sum_line | 第 1 行 = 输入整数之和 | 二值 |
| count_line | 第 2 行 = 输入整数个数 | 二值 |
| sorted_block | 其余非空行 = 升序序列 | 二值 |

判定：4 项全 PASS → reward=1；任一 FAIL → reward=0。不做部分分（terminal-bench 二值口径）。

> **v0.3 起**：正式评分入口为 `2-用例/int-sum-sort/checker.py`（观察项见同目录 `spec.md`：产物存在 / 输入完整性守卫 / 严格格式 / sum / count / sorted）；上表 `tests/test.sh` 为 v0.2 历史实现。二值与「不做部分分」口径不变。

### word-freq-report（中等级 · 指令精度 + 平票陷阱）

任务：按分词规则（去首尾 11 个标点字符、含数字 token 丢弃、内部连字符保留、大小写归一）统计 `/app/corpus.txt`，产出 `/app/report.txt`：总 token 数、去重词数、Top-5 词频（频次降序，**平票按 ASCII 升序决胜**）。

| 观察项 | 检查点（tests/test.sh） | 赋分 |
|---|---|---|
| output_exists | `/app/report.txt` 存在 | 必要条件 |
| total_line | 第 1 行 = 总 token 数 | 二值 |
| distinct_line | 第 2 行 = 去重词数 | 二值 |
| top5_block | 第 3-7 行 = Top-5 词频行，含平票决胜 | 二值（整块比对） |
| trailing_newline | 恰好 7 行且末字节 0x0a | 二值 |

判定：5 项全 PASS → reward=1；任一 FAIL → reward=0。

> **v0.3 起**：正式评分入口为 `2-用例/word-freq-report/checker.py`（观察项见同目录 `spec.md`：产物存在 / 输入完整性守卫 / 严格格式 / total / distinct / top5）；上表 `tests/test.sh` 为 v0.2 历史实现。二值口径不变。

**陷阱设计**：语料中 `a`/`dog`/`tests` 三词同为 5 次，平票组恰好卡在 Top-5 边界——只按频次排序、不做词序决胜（或排序不稳定）的 agent 会把 `tests` 错排进 Top-5 而挂掉 top5_block。期望值由评分器按与参考解相同的规则**现算**（非硬编码），评分器与参考解是同一规则的两份独立实现，oracle 闸门验证其一致性。

## 三、token 与成本口径

- **token**：以各现场 `trajectory.json` 的 `final_metrics` 为准（prompt / completion / cached 分列）。**计价口径必须先统一再比较**：Codex 的 prompt 含缓存读，DSH 的 prompt 不含（cached 单列）；统一口径为 `input + cached`，复算与恒等式验证见 `5-评测报告/复算/token-recompute.py` 与阶段报告 v1.0 §5.2（2026-10-21 更正：直接比较原始字段会得到「6–20 倍」假象，统一后为 1.18–2.09×）。
- **成本**：LiteLLM 无 GLM 定价 → 各作业 `cost_usd=null`。按智谱费率 × token 离线换算后回填（费率取官方价目，注明取数日期）。
- **LLM judge**：本批两用例为确定性评分，无 judge 参与。

## 四、轻量判卷（v0.3，2026-10-21）

> 适用：桌面端手工执行、行为探针题、快速加题。完整说明见 `轻量判卷/README.md`。

1. **产物判分**：`python3 2-用例/<题>/checker.py <run_dir>`。逐项 PASS/FAIL + 权重 + `RESULTS_JSON`；binary 模式 headline 不变（全 PASS=1，任一 FAIL=0），partial 模式按权重给部分分（单题上限 10）。
2. **行为判分**：`spec.md` 的 0–3 锚点，人工填入运行记录（模板见 `轻量判卷/运行记录模板.md`，§5.1 为机器可读 JSON schema v1）；自动批跑记 N/A。填完跑 `python3 轻量判卷/validate_run.py <运行记录.md>` 校验（`--strict-evidence` 校验证据路径存在）。
3. **判卷器自测**：`--selftest` 必须全 PASS；负例至少覆盖 空目录 / 缺产物 / 格式违规 / 错值 / 篡改输入 / 未附输入副本。
4. **三个守卫**：输入完整性（运行目录输入副本 SHA-256 = `truth.json` 记录，不一致直接 0）、truth 交叉校验（现算 ≠ truth → 用例作废，退出码 2）、未知不硬判（证据不足记 `unknown`，不补 0/不补满分）。
5. **评分器与参考解互证**：`checker.py` 与 `solution/solve.sh` 是同一规则的两份独立实现；改任何一份都要重跑 `--selftest` + oracle 回归。
6. **历史衔接**：v0.2 的 Harbor `tests/test.sh` 保留；旧现场按 v0.2 记录，v0.3 只做只读复算，不静默改历史分。

## 四·三、B 组统一禁检索与历史档位披露（2026-10-26）

适用对象为产品默认闭源模型的豆包办公／元宝专家模式；不是将异模型 B 组改成 A 组同模型对照。

1. **统一禁止**：被测端不得调用搜索、浏览／抓取外部网页、通过 Bash／HTTP 等旁路取得题面外材料，包括官方 editorial、他人题解、参考实现与答案。题面自带来源 URL、本地输入／测试、模型内部回忆不单独构成 live 检索；出现 URL 后仍须核对调用及返回。平台推理通信、已提供附件读取与交付文件回收不当作外部知识检索，但不得借此获取题外内容。
2. **关闭优先，但不得冒认完成**：运行前写明禁止约束，能关闭则关闭并保存可复核收据。元宝以发送消息的 `internetSearch` 实值为准：`closeInternetSearch`、`autoInternetSearch`、`openInternetSearch` 分开；预检文字、偏好值、任务书禁止或扫描无命中不能替代发送实值。豆包缺少实际开关收据的历史行记「产品默认／实际档位未证实」，不得补写「已关闭」。
3. **三轴独立落表**：① 档位及证据；② 检索行为（已观察到／归档范围未见／证据不足）；③ 有效性与纳入范围。auto／open 不自动证明检索发生，close 也不自动证明没有旁路。未见检索只能描述已存轨迹，不能升级成全面 clean 或离线隔离证明。
4. **按整场约束，不按得分题豁免**：任何子题／关联作答会话观察到禁用检索，整场不纳入统一禁检索结果；检索子题零分、声称未采用或其他题得分均不能冲销。原判卷分数和原 V／X 保留为历史，另列本次检索复核结论，不改历史现场、不补 0。r1031 的 50 分有两个关联会话检索的直接证据，不能再称整场无检索。
5. **历史与新协议分层**：历史默认／auto 档但未见检索的行，只能作为披露配置差异的有限历史观察，不与有发送层关闭收据的新运行混作「技术离线」对照。证据或产物谱系不完整则列未决，不靠无命中、原分、原 clean／V 补齐。旧 paused 计划格不计运行；已落盘的新四案例不能继续当作 paused。
6. **复核及保密**：逐行核对调用结构、Bash 网络旁路候选、档位字段、会话选择／重试及产物收据。机器扫描仅供定位候选；私有原件留私有区，公开文档只含路径、SHA-256 与必要非敏感结论。详见[历史逐行审查与未决项](<检索口径-2026-10-26.md>)。
