# 冻结对照中，客户端累计字节不能保证响应自报输入同向

## 问题

[端点支持与请求字节](<../端点支持与请求字节-2026-11-23/README.md>)确立了同一批对照的端点字节口径（E2 累计 14/14 正差：13/14 由 E1 负差转正、另 1 对在 E1 已为正；去会话日志投影后仍 14/14 正差）；[首回包与累计请求字节](<../首回包与累计请求字节-2026-11-22/README.md>)显示首结果更短不等于请求字节更少。本页问下一个问题：**客户端捕获的累计请求字节，方向上是否跟随响应自报的用量字段？** 第五周反馈（[第 1 轮验收条款](<../../反馈/2026-11-18-第五轮/验收条款-公开版.md>)相关条目）明确字节不等同于 token、费用或服务端实际摄入；本页用一个可复核的冻结对照把这句边界落成数字。

## 样本与仪器

- 全部输入为既有冻结捕获（R106 锁定批次）重算，零新增运行：**65 个绑定包**（52 主＋13 标题），响应声明 ID、请求/响应 SHA 各 65 种；**14 对组内比较**（R38 4 对、R52 4 对、R53 6 对），比较 4 个端点 × 2 个范围 × 7 个字段＝**784 项差值，零错**。
- 每包解析用量前，请求/响应正文字节先各自对照独立盲账收据（双 SHA-256），来源不符先拒绝再解析（65/65 相符）；五种已审格式近错在现行格式门下全部拒绝（v1 门曾放行，已修订并登记）。
- 端点：E1＝首次成功目标读结果交到下一主包，E2＝新回包中的同一挑战值首次可见，E3＝最后主包；E0 是未交新结果的负对照。**累计＝主首包至该端点所有已绑定主包的逐包上报次数之和**——同一历史在多包可重复计量，既非唯一 token 也非费用。方向＝缩短侧−内联侧。

## 读法

- **E2 累计**：三家族的原请求字节全部增加（R38 +8,033…+10,226 B、R52 +6,551…+61,736 B、R53 +36,394…+44,513 B），但响应自报 input 方向三家族不同——R38 全减少（4/0）、R52 以减少为主（3 减 1 增）、R53 全增加（6/0）。**字节同向增加不保证自报输入同向**，这就是标题结论。
- 具体反例（R52，剂量档标签）：d500 对 E2 累计 raw +6,551 B 而自报 input −8,215、cache read +6,784，可加的三字段和 −1,431；d1000 对 raw +61,736 B、input −6,794、cache read +15,104，条件和 +8,310——同是「raw 增、input 减」，条件和方向仍可相反。
- R53 六组 E2 累计 raw +36,394…+44,513 B、自报 input +5,021…+9,742，而条件 `input−cached` −6,862…−4,492：条件算术量与字节方向也可以相反。
- **E0 负对照**：三家族自报输入与缓存字段各对均相等，终端 output 14/14 已变——差异不出现在没有新结果交到的端点。
- E1 单包 raw/input 全减少（14/14），E1 累计 input 全减少而 raw 在 R52 出现 1 对增加；E2 单包的 raw 与 input 也均 14/14 减少，与累计 raw 14/14 增加形成同一端点内的口径翻转。R38 的条件和在 E3 累计有两格翻为增加（4/0 → 2 减 2 增）——不能用 E3 回填 E2，也不能拿一个家族的条件式当另一个家族的同一逻辑指标。

## 它不能说明什么

- 自报字段的语义（服务端如何计 input/cache/reasoning）、实际 token、费用或后端摄入均不在本页可证范围；`input−cached` 只是兼容该子集口径的算术差。
- 不认证思考、缓存或后端真实行为；对储存响应没有第三方真实性认证，内部非作者审计不构成受控外部第三方核验。
- 本页不给出任何成本或稳定排名，不改正式 25 格与历史分数。
