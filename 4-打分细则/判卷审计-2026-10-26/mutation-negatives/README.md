## 1. 方法

1. **精读判分入口**：五题均为 `python3 checker.py <run_dir> [--json]`（dab 另有
   `--scoring official-compat|strict-contract` 双轨，负例逐组双轨各跑一次）。
2. **程序化变异正确答案**（[gen_negatives.py](<gen_negatives.py>)，只读 `2-用例/`，产物落
   `negatives/<case>/<neg-id>/`）：变异家族覆盖 数值±1 / 删行 / 重复行 / 列与字段翻转 /
   多余列·缺失列 / 乱序 / 伪造成功标记（"OK passed" 等）/ 多语句 / 阈值与舍入变异 /
   大小写翻转 / 参数互换 / BOM 格式注入。每个字符串变异带 `sub()` 断言：**替换必须命中且
   改变原文**，防止变异落空造成假负例。变异清单与预期见
   [negatives-manifest.json](<negatives-manifest.json>)。
3. **真实执行**（[run_negatives.py](<run_negatives.py>)）：以子进程调用 `2-用例/<case>/checker.py`
   原样判分，逐组留存原始 stdout（[logs/](<logs>)），解析末行 JSON 提取 reward / weighted /
   判红项，与生成时登记的预期自动比对；**任何不符都会打 UNEXPECTED 标**，本轮最终 UNEXPECTED=0
   （首轮 16 处不符全部查因修正后重跑，见 §8 过程记录）。
4. **判定口径**（两层，避免把「阈值设计」误报成漏洞）：
   - **逐项拦截/放行**：目标观察项（题/练习/断言）判红 / 判绿；
   - **整场拦截/放行**：reward 0 / 1。
   单题打穿但整场因达标线（bird ≥12/15、dab ≥8/10、exercism ≥5/6、lcb ≥2/4）仍 reward=1 的，
   记「拦截-逐项（整场按阈值放行）」，并如实计入整场放行统计。

执行环境：macOS，Python 3.9.6，仓库 git HEAD `9a85ea5`（只读探测，未提交）；
时间 2026-10-27T00:16:46+0800（results.json `meta`）。
