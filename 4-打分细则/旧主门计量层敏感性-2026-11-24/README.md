# r1109 日志观测重复性：旧门对计量层的敏感性

**旧主门不变：0 通过、6 失败、4 不可核。** 沿用 [v1.1 公开复核](<../机制重复口径澄清-2026-11-12/README.md>) 已绑定的 30 槽（Codex、DSH 各五场景、各三次）。以下是同一批日志的事后投影对照，响应 [Issue #17 第 2 条](<../../反馈/2026-11-18-第五轮/验收条款-公开版.md#L36>)：能检验字节诊断对计量对象是否敏感，不能检验 Harness 处理效果。没有重跑、重判或补判。

## Codex：每层重新在三槽内找极值

`T` 是所有 `response_item` 的规范 JSON payload UTF‑8 字节（不计外层事件）。`M` 是 assistant `message`、`reasoning`、`function_call`（不是 R4）；`F` 是 `function_call_output`。`K` 只取前导 developer、环境 user、任务 user 三条完整 payload；以公开 role+content 与任务摘要的组内相等限定「共同」，**不是**按同长度认定同内容，也不是客户端请求。首 usage 段取首次 `token_usage_record` 前的 payload，且三条前导必须出现在该段。全 R3 不因尾段未闭合而丢字节。[既有 R3 分解](<../R3不稳定来源分解-2026-11-16/README.md>)给原极值对的带符号贡献；这里对每个投影重新选极值，亦不重复[既有单字节残差定位](<../Codex输入面残差定位-2026-11-16/README.md>)。

下表为各场景三槽 `max−min`（B），括号为最小→最大槽号。每列独立用 `≤100 B` 作**辅助**诊断，不参与旧主门。

| 场景 | T 全 R3 | T−M | T−F | K 启动核 | T−M−F | 首 usage 段 |
|---|---:|---:|---:|---:|---:|---:|
| bird | 154301（1→2） | 9725 | 144576 | 0 | 0 | 2726（2→3） |
| dabstep | 296848（3→1） | 49682 | 247167 | 1 | 1 | 1893（1→2） |
| exercism | 31431（2→1） | 27407 | 4025 | 1 | 1 | 895（1→2） |
| lcb | 165538（1→3） | 9223 | 156314 | 1 | 1 | 1305（2→1） |
| tb | 471897（3→1） | 49972 | 421925 | 1 | 1 | 2306（2→3） |
| **通过 / 5 组** | **0** | **0** | **0** | **5** | **5** | **0** |

- **只去一类不翻门，也不换极值**：两种单扣分别保留原 R3 的极值槽（各 5/5）。联合扣减才全过；剩余字节与 `K` 在 **15/15 槽逐槽相等**，5/5 组的极值集合也因重选或并列而变。也就是说保留两族中的任意一族和这些启动消息，日志诊断仍不过线，不能把全部失败归给其中一族，更不是把两种机制的因果贡献分开了。
- **只看早段仍不过，但 5/5 组换极值**。bird 首段三槽为 `8164 / 8102 / 10828 B`；沿用原 R3 的 r1/r2 只差 **62 B**，会误报通过，重选 r2/r3 是 **2726 B**。Exercism 的最小、最大甚至互换。15/15 首段已含 `reasoning` 或 `function_call`，仅这两类就有 **739–3390 B/槽**：首次 usage 是日志边界，不是首请求。启动核相等也不证明请求相同。

## DSH：定位到事件类型，不能补齐序列或请求

DSH 的 S3 计 `user/message`、`request/header`、`request/context` **整事件**的规范字节；它与 Codex R3 不是等价单位。S3 只有 dabstep 过不了 100 B：r1/r2/r3 为 `28062 / 27106 / 27106 B`。差 **956 B** 全落在 `user/message` 类型合计（`9977 / 9021 / 9021 B`、`5 / 3 / 3` 条）；header/context 各自计数和字节相等，不证明正文相等。其余四组 S3 极差虽为 0，旧白名单在 15/15 槽都只剩 `session`，五组窄边界序列相等、较宽步进/工具/助手序列均不相等；这些诊断不填旧序列子门。

两侧都没有用这些投影重新绑定完整客户端首请求；首请求正文、后端实际摄入与同控干预效果均为 **unknown**。不作成本、token 或产品排名推断。

## 离线复算

仓库根目录运行（Python 3.9+ 标准库）：

```bash
scope='4-打分细则/旧主门计量层敏感性-2026-11-24'
python3 -B "$scope/recompute.py"
python3 -O -B "$scope/recompute.py"
python3 -B -m unittest discover -s "$scope" -p test_recompute.py
python3 -O -B -m unittest discover -s "$scope" -p test_recompute.py
```

[复算器](<recompute.py>)直接读三件固定公开派生、先核 SHA，再交叉核对身份、覆盖与账面字节；逐槽输出长度、并列极值、独立通过/失败/未知计数，不重建原件或首包。事件四元组没有 message role，按已绑定的分解派生取 role 分账并对齐 subtype；复算范围不是新的原档认证。缺投影锚点报该层 unknown，错绑/摘要不符拒绝输出。[测试](<test_recompute.py>)涵盖固定 30 槽、bird 真实反例、同长不同摘要、阈值边界、错绑和缺段。
