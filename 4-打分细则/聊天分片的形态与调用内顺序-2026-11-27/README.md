# Chat 分片：终态闭合、首锚和调用内顺序各自证明什么

在[同一组客户端捕获](<../同日观测支持集与派生分母-2026-11-27/README.md>)里，21 个 Chat 响应共 525 个 JSON 派发和 21 个 `[DONE]`，含 6 个 gzip 流。7 个响应各有两个工具调用，实见 395 个工具条目，均是索引 0 整段后接索引 1 整段；没有观察到这 7 个响应交错输出。以下重排是对这批条目的离线副本，不是新运行或真实并发。

## 闭合之外，还可检验首锚；但不能补齐续片

- 固定档案内流标识稳定，单选择索引 0，最后一个 JSON 同时给唯一停止原因和非空用量对象。角色恰一次且在首帧仅 6 流，5 流只在末帧，10 流重复出现。工具类型在 5 个流的续片上复述同一个值，其余两个流不带该成员。原候选误拒同值复述，后续候选允许该值或真正缺席；独审发现显式 `null` 被误当缺席，另版定点排除。两次修改均不把规则推广为通用供应商协议。
- 从每个已派发块各删一次得 546 个派生。旧有限闭合拒 42；余 504 中，形态门再拒 14 个删除工具声明首片的例子。剩余 490 仍过两门，其中包含 381 次非空参数续片删失、103 次非空正文片删失。门通过不是文本完整；已知原件时比摘要是另一轴。与[终态、序号及内容完备的分账](<../SSE终态与内容完备分账-2026-11-27/README.md>)共用捕获，不能额外加样本。

## 跨调用换位与调用内换位不是同一件事

以固定七条双调用响应构造派生，替换工具阵列的原字节区间，保留其余解压层外壳与非工具帧；不重压缩、不判原 HTTP 帧。结果按索引、首锚及原片次序比：

| 对照 | 数量 | 可见结果 |
| --- | ---: | --- |
| 保持每个调用的局部片序，只改变跨调用出场 | 195（含 7 恒等） | 每索引的 ID、名称、参数原串和严格值均保留。旧按首次出现须 `0→1` 的组门拒 21；不是参数丢失。 |
| 不分索引，直接按到达全局平拼 | 同一 195，不新增 | 59 同，其中 52 确实改变了解压体：两个父的空参数首片左移不改变平拼。另 136 平拼异，调用内参数仍不变。 |
| 同一个调用内相邻互换 | 381 | 14 使首锚晚于前片，保持物理闭合但不可绑定；其余 367 保持形态和旧组结构，原参数串均异，其中 323 严格值异、44 在固定候选下拒解析。 |

另一个内部独审的等宽复制近错保持体长、闭合和结构，却改变严格值。不用在晚片看到声明来事后接纳前孤片。**这不回改[已核工具承接](<../工具承接的首续与缺档边界-2026-11-27/README.md>)原有的全序资格**，也不证明产品实际调度、源头真实性、工具执行、服务端摄入或一般协议正确性。已内部非作者从原档分别复核；无受控外部复验，正式 25 格、旧分和冻结状态不变。
