# 精确数词：自己生成的规范字节不一定能再读

**结论：** [此前的精确候选 C](<../精确数字与字符串域隔离-2026-11-27/README.md>)在已接受的旧支持上二遍稳定，但原始数词入口上限 1024 不对自身输出闭合。合法 `1.` 后接 1022 个 `1`，规范形由 1024 字节增长到 1029；第一遍接受，第二遍明确拒绝。这是入口预算与输出形态的问题，不是两实现读出不同值，也不是任一产品的失败。

## 证据与对照

| 固定范围 | 输入 | 一遍拒绝 | 二遍同字节 | 一遍过、二遍长度拒 |
|---|---:|---:|---:|---:|
| 前次有限支持的重放（含真实、公开与前次构造） | 2256 | 18 | 2238 | 0 |
| 本次长度／符号／指数边界构造 | 1568 | 523 | 972 | 73 |

原支持含同一批私档 1569、公开 235、旧构造 400 和固定例 52，不是新增捕获。边界 73 是格点数，不估真实发生率。项目内非作者先固定独立构造，再对照作者结果并复核两候选；不是受控第三方原件复核。

## 长度为什么会增长

去除公用的可选负号后，设 `q` 是原小数点占位（0 或 1），`H` 是原指数整个后缀的长度，`Z` 是规范化去掉的前导零和尾零位数，`E` 为输出指数。对已接受的非零十进制词，长度差为 `1 + len(str(E)) − q − H − Z`；`1` 来自重新写出的 `e`。没写指数的非整数必有小数点；有指数时 `H ≥ 2`。在 `|E| ≤ 6144` 下增量至多 5。整数词保持原样；十进制零归一也不增长。因此**已接受**且每个原始数词 ≤1019 的对象在旧长度帽内一定能读回；1020 已存在反例。

| 合成词（`1×k` 指重复字符） | 入口长度 | 输出长度 | 旧入口再读 |
|---|---:|---:|---|
| `1.` + `1×1017` | 1019 | 1024 | 同字节 |
| `1.` + `1×1018` | 1020 | 1025 | 拒绝 |
| `1.` + `1×1022` | 1024 | 1029 | 拒绝 |
| `1×1024`（整数词） | 1024 | 1024 | 同字节 |

另一个**反事实**：如果只把原始数词帽改成 1029，保留系数帽 1024，闭包仍不成立。`1.` + `1×1023` 规范成 1024 个 `1` 加 `e-1023`，长度 1025→1030；加负号则 1026→1031。早先的 `1029→1034` 见证越过固定系数帽，不成立。若只考虑数词长度，固定系数帽时输出绝对上界是 `1（符号）+1024（系数）+1（e）+5（有符号指数）=1031`，由负例达到。这里是数学判断，未安装或运行改帽版。
