# 投递回执不是请求正文覆盖

只读两批旧档，分别回答两个问题：**本地回执的游标能否在本地事件中对上；有客户端请求正文时，声明的区间实际带了什么。** 两批不是同次会话，不能互补缺档。这里的投递是客户端日志机制，不是服务端接收证明。

## 判定要分三轴

1. **回执指针**：同一会话、格式版本、有效序号；向前或持平都不证明对应范围已发送。即使右端相同，空窗 `(k,k]` 不携带第 `k` 行。
2. **正文覆盖**：先核逐体摘要与长度，再比对声明范围和逐行序号、顺序、会话；有重叠须逐事件核相等，有冲突报不可核。同一范围和条数仍可有重号、错会话或同序号改值。反过来，把窗口乱序拿到仍可能拼成相同覆盖，不能据并集还原捕获时序。
3. **正文字节与去重覆盖**：重复窗口确实出现在不同客户端正文里，算捕获请求体不得扣除；计唯一事件覆盖只能记一次。合成的两个相邻窗再重现首窗，可使出现端点呈 `2→4→2`，而去重覆盖不变。回执、载体、完整请求字节、token、计费分列。
