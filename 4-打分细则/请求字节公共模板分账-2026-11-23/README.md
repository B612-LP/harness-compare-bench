# 连续历史之外：主请求里的公共模板如何贡献字节差

[既有端点字节复核](<../端点支持与请求字节-2026-11-23/README.md>)把 E2 定为同对象的新工具结果首次在主请求中携带完整校验值；此前已分账连续重复的历史项。本页接着分账剩余字节，不增加样本。

仍只看同一批截至各自已绑定 E2 的 **37 个主请求、14 个组内比较**。检查每对两臂每个已捕获主请求包，选取不含主历史数组、且**同名顶层成员值的原始 JSON 字面逐包完全相同**的成员，按值 token 的原始 UTF-8 字节加总。顶层键和值 token 之外的标点、空白另账，不把整个请求说成同模板。每对有 8 个这样的成员；严格 JSON 等值法忽略对象键序和等值转义，保留数值字面与数组顺序，本批也选出同一集合。

- 差额统一为短臂减内联臂。算术扣除连续重复历史后，公共值净差（两臂包数净差乘以每包公共值宽）在 **14/14** 个比较中均为正，并分别超过该对剩余正差的一半。每包公共值宽在两个 DSH 组为 **27,504 B**，在 Codex 组为 **17,370 B**。只在组内记账，不拿两种协议做大小排名。
- 再扣这笔模板字节，差额由 **14 正**变成 **13 负、1 正**。唯一仍为正的比较余 **+6,810 B**。逐值账不把零净差解释为没有变化：相反的转义差可以相消；两臂严格公共性未知但原字节可计的值宽也可净为零，仍要分别保留。

这是同一历史链上的记账，不是可以独立移除的因果分量，不证明去掉这些字段仍会抵达同一 E2，也不推缓存、token、费用、实际执行或服务端摄入。内部非作者复算逐包和逐对账目，并复跑固定对照和合成反例；这里只披露聚合，不披露原件，也不构成受控第三方核验。
