# 从公开逐包表重算请求字节（11-23）

[端点字节台账](<../端点支持与请求字节-2026-11-23/README.md>)的原命令检查逐包恒等式，并统计已发布配对差值的方向。本页再进一步：**不使用已发表的累计量或差值作为计算输入**，只取公开逐包数值、包角色、端点和配对标签，从头累计主请求，再计算相同请求序号及各侧余包。

从 18 场的 65 份捕获记录（52 个主请求、13 个标题请求）复算出 **89/90 个运行端点、56/56 个配对阶段、336/336 个阶段×字节指标**。唯一没有标签的端点属于非配对场景，保留未知。E2（携带完整目标校验值的约定端点）仍是 14/14 原始正文正差，范围 +6,551 至 +61,736 B；逐对截在共同请求序号处，累计原始正文差均为负。派生表对读的数值和结构无差异。独审用一处相抵的 ±1 B 临时改动，在所有端点累计与配对总差不变时，仍检出 6 个逐包重复登记值、9 个共同前缀差和 9 个单侧余包值不一致。

在本目录运行下列命令，只读公开数据，不启动产品或模型：

```sh
python3 -IB rebuild.py '../端点支持与请求字节-2026-11-23/evidence.json'
```

加 `--arithmetic-only` 则只重算分母、阶段和方向摘要，不对读已发布累计及差值。如果对读不一致，命令返回非零；没有端点的配对不会从旧差值补算，也不记成零。命令确认的是公开逐包数字加公开标签足以重建这些算术：**角色、端点及配对标签本身是输入，未从未公开原件重新推断。** 这是内部非作者的公开材料复算，不是受控第三方原件核验，也不是新的比较场次或费用估计。原命令、原证据和历史成绩不改。
