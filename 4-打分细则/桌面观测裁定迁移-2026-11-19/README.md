# 统一观测规范：桌面局部关联试行附录

[0.3 共同规范](<../Harness统一观测规范-2026-11-19/README.md>)不要求各产品使用同一种事件语法。本附录只检验一个迁移问题：**在已公开、已分别复核的两个桌面派生中，能否用共同裁定规则分开「已有局部归属」「顺序恰好吻合」「只有顺序、归属不可核」？** 这是对已知档案的事后重算，两份归档的统计不合并，不增场、不作产品排名。0.3 原页与旧门保持原样，附录也不冻结。

| 固定材料 | 局部归属 | FIFO 与已声明归属相符 | LIFO 与已声明归属相符 | 直接前驱 |
|---|---:|---:|---:|---|
| [WorkBuddy 四个窗口](<../WorkBuddy前驱与完成边-2026-11-19/README.md>) | 7/7 | 7/7 | 1/7 | 1 条同调用、3 条另一调用、3 条非调用（先前结果） |
| [豆包 A，两个有唯一归属的块](<../豆包同名调用归属-2026-11-19/README.md>) | 7/7 | 7/7 | 1/7 | 本派生未比较 |
| [豆包 B，另一既有档案](<../豆包同名调用归属-2026-11-19/README.md>) | **不可核** | 不可核，无分母 | 不可核，无分母 | 本派生未比较 |

**适用规则。** WorkBuddy 先使用固定来源及同会话、请求、步骤的 `callId` 关联声明；豆包 A 使用受检块内唯一调用标识的关联声明。公开复算输入是它们各自的匿名序号派生，不是原始标识。先核同来源、同段、调用/结果角色、一一关系及调用在先。FIFO 和 LIFO 只是每条结果依次选当前未消费调用的最早或最晚项，不给身份加证。豆包 B 只知附近同名调用及相邻 tool 行的数量和位置；若假设这些 tool 行都是对应块成员，且没有其他配对限制，则两个块分别有 6、24 种一一排列。这不是实际候选概率，也不是已知发生乱序。

**能区分什么。** 两个已绑定子集在这里都恰好 FIFO；不表示 FIFO 在产品里是身份字段、普遍有效或足以补 B。判断先后顺序也不等于用每条结果的直接前驱作为调用。保留同一记录角色顺序、改动合成身份对照时，FIFO 可变而合格局部关联仍在；反过来，抽走一条独立归属声明、借另一段同号、添加额外矛盾声明，仅有顺序仍给不出归属分母。两条错误（截断多余声明、布尔冒充行号）仅在适配器的内存对照发现，修订后拒绝；固定已发布派生的结果不变。

**复算与边界。** `python3 -IB verify.py --self-test` 只从公开仓库读三份固定派生，通过相同的局部规则重算表及内存反例；`-O` 结果一致。它核对已经记录的关联声明，不认证原始档案，也不自动解析新桌面格式。这里没有 W 或 H 的独立捕获比对；产品状态 `completed` 不是任务成功、操作系统实读或完整请求得到重建。两产品原始身份的复核范围仍以各自证据页为准；未替代第三方核验。
