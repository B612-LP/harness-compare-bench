# 豆包工作：同名工具调用的结果归属

**完整轨迹的两个同名调用块都能按标识符等值唯一归属，与 FIFO 一致；另一份任务的公开投影无法判定归属或是否重排。** 这里的块是同一条 `assistant` 记录中的调用数组及其结果，不是同时执行的证明。FIFO 只指把结果记录顺序与调用数组顺序逐一对应。

| 观测面 | 证据分母 | 裁定 |
|---|---|---|
| A：完整轨迹的限定窗口 | 9 行，2 个同名调用块，3 + 4 条结果 | 2/2 块有唯一归属；结果对应的调用序号分别是 `[1,2,3]`、`[1,2,3,4]`。7/7 边与 FIFO 一致，0/7 边不一致；不外推为普遍 FIFO。 |
| B：另一任务的公开投影窗口 | 9 行，2 个同名候选块，各有 3、4 条相邻 `tool` 行 | 0 次可做的归属/FIFO 比较，2/2 块为 `unknown`。这不是“观察到零处不一致”，也不是观察到重排。 |

A 的等值匹配只接受当前块中唯一、先出现且尚未消费的调用锚点；遇到缺失、重复或错绑不回退到 FIFO。B 的严格解析规则因 7/7 条 `tool` 行带有一种助手调用摘要键，未将它们接纳为结果锚点；规则只看键是否出现，没有判定它是空占位还是实际声明。因此，这是解析准入规则的结果，不证明原轨迹有角色冲突，也不证明原生标识符不存在。

**单独的条件计数：**如果假定各块里所有相邻 `tool` 行都属于前面的调用块，且没有其他区分约束，则同名调用分别允许 `3! = 6`、`4! = 24` 种一一归属。FIFO 与非 FIFO 都是可能的排列。这一假设不是对成员归属的裁定，计数也不改变 B 的 `unknown`。

内部非作者从限定窗口独立投影后，两源各 9/9 行的共有序号字段和两块裁定一致；不是外部第三方认证。A、B 来自不同归档任务，不是同一任务删字段前后或因果对照。公开[序号证据](<evidence.json>)只保留行号、位置、名称等价类与裁定，不公开原生标识符值。[复核脚本](<verify.py>)仅核验序号、一一对应、计数和不确定性声明，不接触原档，也不能从公开材料重证原生标识符的等值关系。
