# 首轮工具组：等值、真变化与不可核（双线离线校准，未冻结）

同一套判定在 **DSH Chat 与 Codex Responses 各两个既有归档**上区分了三件事：**8/8** 次等价重编码不翻判；**2/2 对**真实归档在已绑定的首响应和首续请求两面均见工具组变化，另有 **4/4** 次同长改值的离线对照；**25/25** 次缺段、错绑、不严格或只剩部分工具组的对照报不可核，仍保留未受影响的已知证据。四个原始运行、两组线内比较、37 个派生对照分开计数；没有新模型或产品运行，也不把对照当独立重复。

## 先绑来源，再比较内容

- **固定对象。** `W` 是归档第 001 包闭合响应中的**完整有序工具调用组**；`H` 是同运行第一个预定主续请求中承接这组调用与结果的位置。DSH `t3-r1/r2` 的 `H` 是 003：002 虽编号在中间，却是无工具的辅助标题请求，且实际起始早于 001，不能按序号解释时间。Codex `t1-r1/r2` 的 `H` 是 002；不是 Codex 深链 `t3`。只认指定首端点、不向后挑可匹配包。
- **身份门。** 归档槽位从既有摘要定位，逐包校验捕获元数据中的请求与响应长度和 SHA-256；首响应闭合早于首主续请求开始。续请求须保留原输入前缀，并按位置和调用 ID / 工具名核对整组调用及各自结果。Responses 另核 thread/session/turn 与 `added → arguments delta → arguments.done → item.done → completed` 的组承诺；Chat 限本样本的单 choice/单工具模式，要求 `tool_calls` 结束与 `[DONE]`。本规则不验证整个协议、结果正文真伪或执行进程。
- **三层分账。** ①物理捕获正文的 SHA-256 与字节数；②拼接后参数字符串的 UTF-8 字节；③工具名和严格参数对象的有序值。对象键顺/空白可归一，数组次序、字符串字符和类型不归一。沿用有符号、整数与小数/指数分型的十进制比较候选：如 `1.50` 与 `1.5` 同，`1` 与 `1.0` 不合并；此处不保证超界数值，也不定义跨线通用规范字节。非法 UTF-8、重复键、非有限数和不支持的形状不猜判。只对③判同与异；②可以不同而③相同。任一目标缺来源、组缺成员或对象不严格，③不可核；不把缺失当成不同。跨运行不拿生成 ID 当内容，也不按内容等值反推身份。
- **来源等级。** DSH 两档与 Codex r1 使用旧摘要核定固定包；Codex r2 的请求和响应核对旧公开摘要，捕获侧元数据本轮才固定，不能宣称同等级旧封记。E/N 等派生从原件副本计算；从不把派生当原件或沿用原件字节签名。

## 原始归档：哪一面变了

| 同线原档对 | r1 W→H | r2 W→H | 跨档，两面各自观察到的变化 |
| --- | --- | --- | --- |
| DSH Chat `t3` | 1 项 `bash`，85 B；W/H 严格值与原参数相同 | 1 项 `read`，66 B；W/H 相同 | 工具名与参数对象均变；r1 缺要求的 `command`，不是 H 投影把它丢掉 |
| Codex Responses `t1` | 1 项 `exec_command`，255 B；W/H 相同 | 2 项 `exec_command`，254 / 284 B；W/H 全组相同 | 首项工具同名、参数对象已变；组数 1→2 也变。只找第一项会漏掉 1→2 |

DSH 两档首请求原字节相同（32,937 B），Codex 两档首请求同长但原字节不同（37,568 B），故不设跨产品或跨任务对照，不据此归因给 Harness。样本早已选定；形状探查发现 Codex r2 超出原单调用候选域，原判仍是不可核。表中数值是改用完整组规则后对同一批档案的**事后**校准，既没换档，也没改旧判。

| 对照 | 每个档各做一次，除非注明 | 结果 |
