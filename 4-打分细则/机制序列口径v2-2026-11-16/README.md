## 1．问题：旧序列子门为什么不可核

旧门（[机制独立重复预注册](<../机制独立重复预注册-2026-11-08/README.md>)）为「输入侧字节 max−min ≤ 100 B **且** turn 边界事件类型序列一致」。v1.1 已诊断两点：旧白名单与 v4 真实类型不匹配（15 份投影退化为 `session` 伪影）；两种事后诊断互相矛盾——狭义 `turn/start`/`turn/end` 序列五组 DSH 全同，加入 step/tool/assistant 后五组全不同，且该页明确拒绝事后二选一。

本页对矛盾根源给出可冻结的语义解释：**旧门名字是「输入侧」，宽义诊断却把输出侧交互事件（step/assistant/tool）混入同一条序列。** 输入侧与输出侧的重复性本就应分开观测——这正是[请求侧观测规范](<../请求侧观测规范-2026-11-08/README.md>)把 S3（输入）与 S4（输出）分列、并记录「S3 高度稳定 / S4 1.21–1.93× 波动」的原因。v2 因此把两个被旧门混在一起的问题拆成两个命名观测：输入重复性（主门）与交互骨架形状（描述性）。

## 2．定义（冻结，执行前写定）

事件按语义分区（以 v4 归档事件 `type` 字段为准）：

| 分区 | 类型 | 角色 |
|---|---|---|
| 输入侧 I | `user/message`、`request/header`、`request/context`、`system/message`、`agent/inbox/spliced` | 构成或送入模型可见请求的事件（含历史拼接标记） |
| 交互骨架 K | `turn/start`、`turn/end`、`step/start`、`step/end`、`assistant/message`、`tool/call`、`tool/result` | 模型调用与工具交互的形状（输出侧） |
| 会话配置/传输 M | `session`、`session/title`、`permission/preset`、`sandbox/mode`、`approval/policy`、`session-log-deepseek/delivery-accepted` | 不入任何序列；运行配置一致性已由 a1 逐字节门另行覆盖 |

**v2.1 分区增补（2026-11-16，冻结于任何组内 v2 裁决计算之前；上文分区表为 v2 原文，本增补不改写、不追认任何 v2 结论——v2 下未计算任何组内裁决）。** 首轮分区覆盖率校验枚举 15 个 DSH 槽共 2345 个事件、类型并集 20 种，发现两种 v2 表外类型，按「未知类型报错」规则中止并在此事先定版：

- `session/title-llm-request`（9 条：exercism/lcb/tb 每槽各 1 条）→ **M**。会话标题生成的内部请求日志，与 `session/title` 同族；既非模型可见任务输入（I），也非模型调用/工具交互事件（K）。
- `subagent/catalog`（1 条：仅 dabstep r1）→ **M**。子代理委派的目录登记记录，非模型调用或工具交互本体。该类型仅存在于 B1 已必不过的阴性对照槽，其归属不影响任何组的 v2 主门结论（dabstep 在 B1 即失败）。

增补后 20 种类型全覆盖（覆盖依据：v1.1 evidence.json sha `925470d3…` 逐槽投影与公开聚合 `per_file` type_counts 双层一致）。表外未知类型报错规则不变，适用于未来新增类型与防篡改。

序列 = 归档顺序下过滤到该分区的 `type` 投影；字节 = 分区内完整事件 canonical UTF-8 JSON bytes 之和（与 v1.1 同一 canonical 规则：键排序、无额外空格、非 ASCII 不转义）。归档中出现上表之外的未知类型时校验直接报错（exit 2），不静默归类。

四个观测与主门（逐组，同场景同臂 n=3）：

- **B1**：S3（`user/message`+`request/header`+`request/context`）max−min ≤ 100 B——复用 v1.1 已算值，不重算改值。
- **S1**：输入侧 I 序列三次一致。
- **B2**：输入侧 I 完整事件字节和的 max−min ≤ 100 B。**比 B1 严格强**：覆盖 S3 选定之外的全部输入侧事件，关闭「字节门只查选定事件」的选择漏洞；这正是旧序列门存在的本意。阈值沿用 100 B 以保持同族可比——歧义在序列定义而非字节阈值。
- **D**（描述性，非门）：交互骨架 K 序列与 K 字节和的三次差异，用于把输出侧形状变化如实记录（预期随生成波动，与 S4 文档一致）。

**主门 v2 = B1 ∧ S1 ∧ B2。** 裁决范围仅 DSH 5 组：Codex 5 组字节子门 0/5 已使 AND 门不通过，序列子门无裁决价值，预注册即排除。dabstep（DSH）B1=956 B 已不过，保留在裁决表中作为阴性对照。

## 3．反证分支（冻结）

- **某组 B1 过而 B2 不过**：存在 S3 选定之外的输入漂移（首要嫌疑 `agent/inbox/spliced` 拼接点差异）→ 该组 v2 主门不通过，「输入字节全等」表述必须收窄为「S3 选定事件字节全等」；选择漏洞被证实，重复性升级被否决。
- **S1 不过而 B2 过**：类型结构漂移但字节近似相等 → 判不通过并逐槽记录漂移位置。
- **某组 D 序列同而 K 字节异**：交互骨架稳定、输出字节波动 → 该组可作更强表述「骨架稳定 + 输出字节波动」，与 S4 既有文档一致。
- **全部通过**：v2 主门 DSH 4/5（dabstep 阴性不过）→ 报告表述为「v2 口径下 DSH 输入重复 4/5、四组被测输入观测量全等」；不升 10/10、不涉 Codex、不支持 M1 inline/spill 效果或成本结论。
