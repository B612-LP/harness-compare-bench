# 请求原字节扩展：有限跨解析器通过与确定反例（2026-11-27）

> **结论：真实档的有限支持集通过，不等于通用序列化器通过。** 零新增产品运行；分析既有请求/SSE与合成反例。候选不是已冻结的新规范，不改[现行 v1.5](<../Harness统一观测规范-2026-11-19/README.md>)、旧主门、正式25格或历史分数。

## 1. 问题与认识变化

[R1](<../规范不产值实现一致性与跨解析器-2026-11-27/README.md>)的820载荷未出现浮点，Python/Node字节全配不足以检验浮点词型。扩展至另10个既有捕获目录后，原始JSON中的`1.0`、`0.0`经过普通JS数值解析和`String()`序列化变为`1`、`0`，使**规范字节**不同；这不是产品行为变化。

进一步独立复核发现：候选虽然对真实档全配，却会吞特殊键、损失大整数，而且最短浮点表示有确定反例。修订后保留浮点反例作为**未闭合缺口**，不以有限样本全配宣布规范校准完成。

## 3. 确定反例：有限全配不能证明通用实现

以下为纯合成输入，未混入真实运行样本。原候选的问题与本页修订后的状态分开：

| 输入 | Python规范输出 | 原typed候选／修订状态 |
|---|---|---|
| `{"__proto__":{"x":1},"a":2}` | 两个键均保留 | 原候选吞`__proto__`；修订为空原型字典后配 |
| `{"v":9007199254740993}` | 原整数 | 原候选变为9007199254740992；修订以BigInt精确处理整数后配 |
| `{"v":1000000000000000000000}` | 完整十进制整数 | 原候选变指数形式；修订后配；整数`-0`规范为`0`亦有回归 |
| `{"v":1000000000000000.2}` | `1000000000000000.2` | **仍不配**：typed输出`1000000000000000.3`；负号对称例也不配 |

最后一项来自最短往返十进制表示的平局选取：`toPrecision(p)`首次往返成功，不保证等于CPython的选择。两个十进制字符串可指向同一binary64数值，但规范字节仍不同。**“完整实现CPython repr”承诺为NO-GO**；416个确定性样本全配不能抹掉这两个反例。尚未采用经完整验证的替代算法，不以补丁数量冒充已闭合。

## 4. 公开复算与验收框架

Python3.9+标准库、Node≥18；不访问网络、账号或私档，不执行产品产物／checker：

```sh
python3 -IB verify2.py
python3 -IBO verify2.py
python3 -IB test_verify2.py
python3 -IBO test_verify2.py
```

- [verify2.py](<verify2.py>)：A1八个词型载荷；A2固定种子的400个伪随机有限double＋16边界；A3完整合成基座三种篡改；A4十个事后近错，**明确预期两项float mismatch**、重复键拒绝及其余修订回归；B为[11-25现场](<../../3-表现现场/r20261125-five-lcb/>)三份公开源的235行（DSH78、Codex84、豆包73）。B先核整文件SHA与行数，再把**原始行字节**交给Node，不先重序列化清洗。公开235行无浮点，不能替代私档24浮点帧的验证。
- [crossparse2.mjs](<crossparse2.mjs>)：String基线与typed候选并列；后者修复特殊键／精确整数，新增重复键拒绝。**它仍不是完整规范加固器或通用CPython canon实现。** 本页实测Node v24.22.0。
- [test_verify2.py](<test_verify2.py>)：18项验收框架负对照。拒空、缺失、额外、重复ID、无效verdict、源SHA错绑；60秒子进程上限；缺Node为`INCOMPLETE`且exit2，不显示全通过。JSONL只按LF分段，合成U+2028／9不拆成多行。

本页两档实测：A1／A2／A3符合各自有限预期；A4如实保留2／2已知float不配；B两模式235／235配；单元测试普通／优化各18／18。`ALL EXPECTED CHECKS PASS`只表示**预期的通过和预期的失败均被复现**，不是解析器通用正确性PASS。
