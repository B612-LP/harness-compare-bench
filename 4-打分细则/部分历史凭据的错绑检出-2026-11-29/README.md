# 部分历史凭据：能检出换槽，不等于能定位或认证原档

**固定旧档的离线派生。** 旧[原档盲验的错绑门](<../留出原档盲验-2026-11-29/README.md>)仍未通过。后来用先存账确认请求 2、3 的位置互换，见[错绑与终态复核](<../盲验错绑与终态覆盖复核-2026-11-28/README.md>)。这次问的是：**当核验者只能核一部分位置，究竟能保证检出什么？** 分开看异常检出、条件定位、原件校验；不改旧门，不冻结规则。

## 1. 先限定交换的是哪一面、能换哪些槽

用[29 对既有捕获](<../捕获旁证与内容归属-2026-11-27/README.md>)和[三槽早期账](<../DSH请求侧最小捕获-2026-11-16/evidence.json>)作两张对照；三槽都与 29 槽中的既有双体摘要重叠，不累加样本。先存的可信账列出固定槽和预期摘要；待核方自报的清单不算先存账。分别看请求原字节摘要 R、响应原字节摘要 S、或同槽两体元组 P。下面每次只交换一对固定槽在所选观察面上的值；两槽同值，位置虽交换、该观察面没有变化。

| 允许范围、投影 | 名义对 | 可见交换 | 同投影不可见 | 保证检出可见交换的最少逐槽锚 |
| --- | ---: | ---: | ---: | ---: |
| 29 槽可任意两两互换；R | 406 | 384 | 22 | 24 |
| 同一全池；S 或 P 各自 | 406 | 406 | 0 | 28 |
| 29 槽仅允许既定捕获目录内互换；R、S、P 各自 | 28 | 28 | 0 | 19 |
| 三槽队列；R、S、P 各自 | 3 | 3 | 0 | 2 |

**为什么是最少：**允许组内若有两个未核位置值不同，恰好交换它们就漏检。反过来，只留下同一内容类不验，所有异值交换至少打中一个已验位置。取每组最大类留下，再加总，最少锚数便是各组的「槽数减最大类大小」。逐个从选出的最小集再去一锚，每次都有漏检见证。**19 个锚只覆盖目录内的 28 对**，不是用更少锚覆盖原来的 406 对。24 或 28 是逐槽核验位数，不是存储预算、事故概率或随机抽查把握。

## 2. 一处报警和唯一定位的差别

在全池 R 的最小方案中，留一个 5 槽同值类不验。只读核验位时，384 次可见交换全报警，其中 **264 次可唯一定位、120 次仍有多个候选**。这 120 次是一验一未验的交换（24×5）。若同一时刻还能查看完整当前名单的值，在**恰好一次异值交换**的假设内，可以查出唯一一个收到报警位旧值的未核槽，384 次都能定位。无警仍不证明没错。三槽若只验第 1 槽，2↔3 一定无警；另外两对会报警，只看验位仍有两个候选。

定位结论不能倒过来证明确有一次对换。合成旧值 `(a,b,c)` 变成 `(b,c,a)` 是三循环，无序值账仍一样。只锚第 1 槽、但查看完整的当前三槽时，一对换模型会唯一指向 `(1,3)`，但真实变化不是那一次互换。另一对照把真旧值 `(a,b,c)` 两处替换成 `(x,a,c)`；同一局部锚配完整当前名单会唯一指向 `(1,2)`，先存的真实无序账却能拒绝这个替换。若这两例只看核验位，各有两个候选；也不能把部分当前名单中恰好看见的一个候选当作唯一。

## 3. 判断原件还缺什么

- **局部位置锚**可报警，但未锚槽可换一个新值、连同候选自报摘要一起换，局部校验仍会过；固定全池 R 最小集的 5 个未锚位置分别替换，5 次都如此。删去未锚槽也不能被「验位都相等」补成完整覆盖。
- **先存无序多重集**比较完整当前池时能发现上述单槽改值，不能检出保留多重集的整对换位。旧盲包实际是只对调两份请求，响应未在待核包内；不能用 S 的整对交换模拟来替它认证据。三槽另做离线对照：只换 R 而 S 留位，S 面不变；若另持完整且先存的 R/S 配对多重集，会看见配对变化。整对一起换则连它也不变。
- **带槽的先存全量承诺并核全名单与正文摘要**，才能回答这批所测正文是否与该承诺各槽一致。摘要一样不认证物理运行身份，采集自报侧车也不认证服务端、时钟或实际输入。实档关系只在两份固定支持集内复核，不外推到其他版本、产品、来源或更复杂的错误方式。

[公开复算](<verify.py>)仅用已匿名化的类大小和目录组大小，重算上表和最小锚集的定位计数；不读取原件、不认证账本来源。项目内非作者从锁定旧档独立投影后才对照，另用合成对照核定位前提，不是外部第三方核验。本次无新增产品、评测模型或读取运行，冻结规范、旧盲验、正式 25 格及历史成绩不变。
