# 同一首请求何时看见不同分支（11-23）

只用两份既有 DSH Chat 档案。两个主任务首请求已绑定原始捕获，正文均为 32,937 B，逐字节相同。代理转帧后的响应从第 1 个实际派发的记录就不同，**两端可见候选工具名也已经不同**；如果只看对齐 `delta` 的字段和类型形状，要到第 22 个记录才出现首差。这三项观察的单位不同，都不是供应商实际选分支的内部时刻。

| 所见阶段（派发序号，从 1 起） | 归档一 | 归档二 |
| --- | ---: | ---: |
| 首次候选名称 | 1 | 1 |

| 关联的工具调用结束记录 | 28 | 22 |

两端都有完整线侧工具调用结构，也在合格续请求中找到有序的调用与结果。辅助请求仅核元数据，不作为承接对象。一端的已捕获参数缺一个同包工具声明要求的成员，另一端不缺；首包候选名或最后标记不能单独证明这一点。结果文本不作为承接条件，末尾标记的字节若未形成完整派发也不能补封口。

这是两个已见真实运行的客户端观测，输入相同不代表模型、服务端状态或全部变量都受控。对照为离线变换，不是新的调用；不推 Harness 因果、稳定性或任务成功，不改历史成绩。参见[此前 DSH 观测校准](../DSH观测口径校准-2026-11-19/README.md)。
