## 2. 差异究竟在哪一面

对13个可对齐配对完整枚举每个 I 事件的 JSON 差异叶（不是只看前几个差异），**仅发现两类值变化**：

- L0：全部104个对齐 I 事件的顶层 `/time`；以及65个消息出现项的 `/data/inserted/0/id`、`/data/message/id` 或 `/data/id`。
- L1：仅上述65个消息 id 出现项，去掉顶层信封仍不相同。
- L2：没有差异叶；冻结投影包含所指定消息的 role/content、系统 turn/step、inbox 位置及**全部** request/header、request/context data，不是事后见到差异再逐项删字段。

这里104与65是**对齐事件配对出现次数**，不是独立实验数，也不是104个不同事件或65个独立消息。L0与L1会重复覆盖同一 id 变化，不相加为样本量。公开只给长度、哈希、结构路径和布尔，不给这些 id、时间或消息正文的值。

因此，对“完整输入事件逐字节全等”的否定是直接原档比较结果；对“指定内容/schema投影稳定”的支持同样来自实字节比较。不能跳到“任务语义完全等同”“实际请求完全相同”“实际思考/缓存受控”或“只有模型导致差异”。本结果补足的是日志面认识边界，而不是 HTTP 请求、token/成本或跨产品因果。
