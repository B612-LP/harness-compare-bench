# 输入事件等长与同一性（2026-11-16）

**预注册：检验 DSH r1109 输入侧事件的等长观测，是否足以支持“逐字节相同”。** [机制序列口径v2](<../机制序列口径v2-2026-11-16/README.md>) 的 B2 是完整事件 canonical 字节**长度之和**，S1 是事件类型序列；二者相等不在逻辑上蕴含事件内容相等。本页新增同一性检验，不改 v2 主门、不回写旧分或冻结原件，不增加产品/模型运行。

## 一、问题、范围与先验接触

[当前整合报告 v1.57 §4.32](<../../5-评测报告/竞品评测报告-v1.57.md#432-重复槽输入逐字节全等的-v2-序列口径裁定>) 曾将四组 B2=0 表述为输入侧逐字节全等。本页检验这一较强表述，而不是用新指标追认原主门。完整覆盖 5 case × 3 rep = **15 DSH 槽、5 组、每组 3 个两两比较，共15对**；dabstep 保留作序列不同分支，不挑除异常槽。

先验接触如实披露：立题前已读 v2 实现；仅查看 bird r1 的 I 事件 schema（没有跨槽内容比较），观察到顶层 seq/time/type/data 及部分 surfaceOp，data 含消息 id、source、content。本页冻结在新跨槽同一性结果计算之前；属于基于已有观察面的事后分析设计，不是新的独立产品预测。

## 二、定义（执行前冻结）

- 原件：沿用[口径澄清 v1.1 的 evidence.json](<../机制重复口径澄清-2026-11-12/evidence.json>) 中 15 个 DSH 槽的相对原件路径与完整 SHA-256。每个原件解码后全部事件的 `[type, canonical长度, null, 0]` 必须逐项等于该投影；与 v2 result.json 的 I 类型序列、字节和、B1/B2/S1及主门逐项硬等。失败 exit 2。
- I 类型固定为 `user/message`、`request/header`、`request/context`、`system/message`、`agent/inbox/spliced`，与 v2 相同。
- canonical 固定 `json.dumps(ensure_ascii=False,sort_keys=True,separators=(',',':'),allow_nan=False)` 的 UTF-8 bytes。相等以**实字节比较**裁定，SHA-256仅提供公开承诺；有序流以 canonical 的事件数组序列化，不以拼接歧义编码。
- **L0 完整事件面（主要终点）**：I 事件完整 canonical 有序流三 rep 是否实字节相等。另列完整流长度、逐事件 canonical 长度向量、逐事件 SHA，以区分总长相等和每项等长。
- **L1 载荷面（诊断）**：按相同 I 顺序取每个事件 `data` 完整对象，不去掉 id/source/路径/时刻等字段。缺 data 或非对象 exit 2。
- **L2 指定内容/schema面（诊断，非“真实模型输入”）**：按类型机械取字段，**不再事后删字段**：
  - `agent/inbox/spliced`：保留 `start`、存在时的 `removedCount`、`target`，`inserted` 中每项只取 `role`、`content`；缺少所需字段/对象结构 exit 2。
  - `system/message`：保留 data 的 `turn`、`step`，message 中的 `role`、`content`。
  - `user/message`：仅取 data 的 `role`、`content`。
  - `request/header` 与 `request/context`：保留 data **全部**字段（不挑工具/schema/配置叶）。
- 逐对对齐：仅当两槽 I 类型序列逐项相同，才按 I 序号对齐和枚举各层所有差异 JSON 叶路径（RFC6901；缺失/类型/列表长度变动亦登记）。类型序列不同，仍可比较整体流是否相等，但逐项差异记 `not_aligned`，不强猜对应。各层相等均比较实字节，不由差异路径列表为空反推。
- 内容纪律：公开相对原件标识、类型、序号、字段路径、长度、哈希、相等布尔和差异种类；不公开消息正文、工具/schema文本、id/时刻/运行路径的**值**。键路径本身若含任意数据键，使用固定结构键与数组索引为主，非结构动态键散列去标识，不以此遗漏变化。不执行任何归档内代码或工具命令。

## 三、反证与结论分支（冻结）

对旧 v2 主门通过的四组逐组报告：

- **IDENTICAL**：L0 三 rep 相同，原“完整输入事件逐字节相同”在该日志面获得补证。
- **ENVELOPE-OR-PROVENANCE-DIFFERENCE**：L0 不同而 L1 或 L2 相同。分列到底哪层相同，只允许称该指定投影相同，不称完整事件同一。
- **CONTENT-FACE-DIFFERENCE**：L2 也不同。只定位所定义内容/schema面有变化，不自动称任务指令语义变化、实际模型上下文变化或 Harness 因果。
- **NOT-ALIGNABLE**：I 类型序列不同，停止逐项配对，整流不等如实记账。

全局主要终点为旧门通过四组中 **L0相同组数/4**；同时完整列出其余组与15对，不能将一次相等或某一规范化层的相等代表全输入。旧v2的4/5结果仅为原观测门，不被本页推翻或升格。
