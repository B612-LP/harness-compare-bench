# Codex Responses 流、原生轨迹和续请求的工具参数复核（2026-11-19）

## 观察

同一份既有 Codex CLI 捕获中，响应流（W）、原生会话（N）及下一请求体（H）的记录结构三者不同，受检工具参数却逐字节相同：三层解出的参数字符串各 255 B，规范对象各 236 B。用不同空白和键序把 W 参数写成 277 B，判定仍为等值；在形状相同而值确实改变的对照中，W 的规范对象变为 254 B，N/H 仍相等。如果关联到了同一次会话中另一条真实的同名调用，即使响应捕获自身完整，也不输出等值或差异。

## 证据与判定

复用[既有三对 Codex 捕获的来源记录](<../Codex响应侧计数与缓存抖动-2026-11-17/README.md>)与同次原生轨迹。受检的是 Responses SSE，不是用 Chat SSE 的结束约定来推断；顺序号、终止事件、项类型、调用 ID 以及参数完成和终止副本分别核对。主请求从同一线程和轮次以及任务消息绑定，不把另一个 `user` 记录当任务。第一个响应共 234 帧，受检项有 90 条参数增量；合并后的参数与三处完成记录相同。N 中的调用和结果与 H 中的有序记录相匹配，结果字符串在 N/H 相同。基于该请求的工具声明，受检参数 `cmd` 在三层都存在且是字符串；不等于通过整套 schema、工具执行或任务成功。

| 证据单元 | W/N/H 解出 UTF-8 字节 | W/N/H 规范字节 | 裁定 |
| --- | ---: | ---: | --- |
| 原档同一调用 | 255 / 255 / 255 | 236 / 236 / 236 | 值相同，外层结构不同 |
| 只改 W 参数写法（离线） | 277 / 255 / 255 | 236 / 236 / 236 | 值相同，原字符串不同 |
| 只改 W 参数值（离线） | 254 / 255 / 255 | 254 / 236 / 236 | W 值不同，N/H 仍相等 |
| 强绑另一条同名真实调用，或只改下一请求中的结果指向 | — | — | 关联不可核 |
| 缺失、错序的参数完成事件或矛盾的事件/项类型 | — | — | 流不可核 |

原字符串长度按从外层 JSON 解出的参数文本计数，不计外层转义和 SSE 帧头。规范字节按本臂解析 JSON 对象再作单行紧凑 UTF-8 序列化：键排序，数组次序保留，不做 Unicode 正规化；重复键、非有限量或不可编码字符串拒绝。这里实际检验的是字符串参数对象的重编码和单值修改；原臂数值按本臂 JSON 解码器处理，不宣称它与 [DSH 试用规范](<../DSH观测口径校准-2026-11-19/README.md>)的精确十进制规则等价。

## 哪一层出了错

初版可以误收一条真格式近错：完成事件的冗余 `call_id` 指向真实的另一条同名调用，而该事件其余索引和项标识正确。同一帧有两个相冲突的归属，不能只相信其中一个。追加修订要求受检生命周期包装若提供 `call_id` 或 `name`，必须和绑定目标相符；真正缺省或一致的冗余仍合法。原先十项用例判断和原档数据不变。十四项增补中，四项保留原有完整投影、十项矛盾仅报不可核。内部非作者从原档另行投影，并另改首个参数增量的冗余 ID，保持名称正确、其他帧不变；修订工具和独立判读都拒绝，无值指标。初版的规则缺陷不因此次修订而追认。

## 外推边界和复核

这只是一条历史会话内的局部参数链和软件对照。客户端捕获有历史承诺；此次持有的原生轨迹和辅助元数据另作固定，不把后来的本地承诺当作历史独立见证。未新增 Codex、模型或网络试验；没有完整重建请求、核验上游身份或后端处理，不估 token、缓存、读取真值、Harness 因果或排名。旧门、历史分数及正式 25 格不变。受控第三方原档核验未完成；独立复投影指项目内部非作者，不是外部审计。私有原档及解析入口不在公开包中。

[公开派生](<evidence.json>)不含请求、结果、身份原值或档案路径；`python3 -B verify.py --self-test`（也可加 `-O`）只核这些派生字段、固定关系和离线拒绝例，不能重新取得或认证原档，不等于再次执行原档解析器。[第五周验收依据](<../../反馈/2026-11-18-第五轮/验收条款-公开版.md>)。
