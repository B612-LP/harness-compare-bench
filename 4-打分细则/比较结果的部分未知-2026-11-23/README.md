# 比较结果的部分未知：同一口径下也可能只能核原字节

已有工具历史和参数复核遇到过这种组合：两份已绑定的参数原字节都可取、也已确认不同，但其中一份未通过严格 JSON 判读。**这是 `raw 不等 / strict 不可核`，既不是两者皆不可核，也不是已经证明严格语义不同。**

对[现行冻结基线](../Harness统一观测规范-2026-11-19/README.md)的实际比较函数离线枚举 648 个决策输入组合，20 个可接受、628 个按输入合同拒绝。指定同视图同算法时，上述组合无合法表示；把它改标异算法虽有一个可接受组合，却歪曲了未知原因。冻结函数和历史数据均未改动。

试行的补充记法将原字节和所选严格对象分列，分别记录已知或不可核，并独立校验引用与目标的绑定。缺段、算法不同和严格解析拒绝不能用同一个理由代替。独立复核用旧 20 个可接受组合回查兼容性，并分别测试了同视图下 strict 不可核、异视图同时引用错绑。这里验证的是**决策行表达能力**，不代替原件绑定、覆盖核验，不为全局冻结或外部第三方审查作背书。
