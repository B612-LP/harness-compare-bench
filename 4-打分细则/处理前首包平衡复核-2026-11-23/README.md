# 同一任务提示，不等于处理前首包平衡（11-23）

固定此前一组 DSH 内联／外溢归档的四份主任务首请求，分别早于该档案首次可见的目标工具结果进入后续请求。顺序依据前期已封投影，本次不重新读取响应。四份首包都是 **56,188 B**，六个组内／跨臂组合中，原始正文与严格 JSON 对象 **0/6 相同**。只剔除客户端的会话日志字段后，剩余正文与对象仍 **0/6 相同**。

内部非作者从封定四件独立定位：注册任务提示词的原始 JSON 字符串字节与解码值都相同（解码 **281 B**），剩余唯一严格差在同一用户正文中的另一文本块（每份 **703 B**，六对全异）。日志值本身是 **27,462 B**，不是整包；其中 14 个事件的有序类型和字段形状都相同，但只遮掉预先指明的会话标识、创建时间后，严格日志值仍全异。不能从形状、长度或任务提示词相同推导整个输入相同，也不把那一文本块归因给某个进程或实际用户输入。

这限制了该组的干预前平衡主张，不把[后续端点字节差](../端点支持与请求字节-2026-11-23/README.md)升级成单变量 Harness 效果。仅公开已有捕获的派生计数，不改旧判、原件或正式成绩。实际 v2 与独审在四个固定包、六对及 24 个预定控制的共同投影上一致；上述两文本块的拆分来自独审。带额外接缝空白、只含部分日志字段的对象不在本次确认范围。未做受控第三方原件核验。
