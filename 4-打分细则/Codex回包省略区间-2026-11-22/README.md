# Codex 回包省略的字节区间与失败归因边界（2026-11-22）

**归档中有七次实际的呈现省略；这不足以判定失分原因。** 复核 [r1030 Codex 的五个既有正式格](<../../3-表现现场/r1030-formal-a1/README.md>)，在 146 条已归槽的工具回包中，四格有七条该格式截断提示，且七条都能与同次本地聚合结果的保留头尾逐字节对齐。第五格在所查面没有本格式提示，不等于没有其他裁剪。无新增运行，不改变正式成绩。

区间以已解码的本地聚合文本 UTF-8 字节为基准，零起点、含左不含右；不量 JSON 信封、请求体或 token。Bird 注记的 4,854 是字符数，不是 5,844 字节。事件数不表示遗漏信息的分量。

- **Bird q27：** 内部原档复核显示，完整题目对象已在首次截断回包的保留后缀内，未通过的是 q27；[公开批次记录的结果矩阵](<../../3-表现现场/r1030-formal-a1/README.md>)仍为 14/15，不提供上述两项原档细节。这排除「这次省略删掉了 q27 题目对象」，并不证明模型收到、理解了该对象，或省略对失分没有别的影响。
- **Dabstep q2697：** 被省略的是手册的一段；另一次工具调用读了题目文件，完整题目出现在该回包中。两次调用来自同一归档，不是独立采集。不能把「题目在回包中」写成「模型收到全部相关规则」，也不重估这个省略的评分影响。

**复核口径。** 在 Codex 0.163.0 现有格式中，同会话和轮次内，以唯一调用 ID 绑定执行调用、完成时聚合结果和工具回包；检查三端轮次、工作目录、顺序、成功退出及头尾字节。不剥离计数行之后、正文之前的额外 LF 时，保留头匹配 0/7、保留尾匹配 7/7；恰剥离一枚后，头尾均匹配 7/7。这是事后发现并限定在本批格式的规则，不是预注册的产品定律。出现多解、缺端或轮次矛盾则不判断；改写已经保留的等长字节能被头尾比对发现，改写被隐藏的等长字节则不能，仅靠回包不能复原隐藏文本。两个本地记录面同在一份日志，不能彼此独立认证实际进程输出、线上发送或后台摄入。
