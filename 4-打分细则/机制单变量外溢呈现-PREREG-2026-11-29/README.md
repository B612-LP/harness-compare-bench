## 1. 研究问题

**同一 Harness（DSH CLI）、同源同字节 payload、只改 inline/spill 呈现（单变量：`maxInlineTokens`）时，工具结果外存化是"省下输入开销"还是"把开销推迟到后续请求"？**

先导证据（[spill 单变量干预-2026-11-20](<../../5-评测报告/spill单变量干预-2026-11-20/README.md>)）：5+5 槽、16,000B 同源 fixture，两臂标记答案 5/5；外溢臂出现"多一步 grep 重读原文件"而未读外存文件的现象；当时无客户端请求捕获，不能判恢复链与端到端字节成本——本实验补齐请求面捕获后重做。

- H_defer（推迟开销）：外溢臂累计输入侧捕获字节 ≥ inline 臂（外存化省下首请求字节，但后续请求经工具读取把内容重新携带回请求面）。
- H_save（真省开销）：外溢臂累计输入侧捕获字节 < inline 臂。
- H_none（无差/不定）：落在预设等价带内。
- 旁证假设（恢复链）：外溢臂若完成任务，必须发生对外存文件的工具读取，且其后请求 history 字节回升。

## 3. 固定材料与臂

- 模型：DeepSeek V4.1-Flash（`deepseek-official` 路由，`deepseek-flash`，reasoningEfforts 最低档；凭据经本机 vault 注入，密钥不入任何记录）。
- 臂 A（inline）：`maxInlineTokens=12500`（DSH 默认）；臂 B（spill）：`maxInlineTokens=500`。两臂配置逐字段 diff 仅此一项（diff 收据入档）。
- fixture：复用 11-20 先导的 16,000B 同源文件与 5 事实 TASK.md（发射时登记字节 SHA；fixture 本体与 checker 私存）。
- 槽位：n=5/臂，A/B 逐槽交替（A1,B1,…），每槽全新会话与全新工作区（仓外目录，只放 inputs+TASK.md；checker/truth 不入工作区）。
- 预算：10 槽 + 2 次预检往返，不追加。

## 4. 两臂等控清单（发射时逐项验收，全过才发射）

1. 同一 DSH 二进制与版本号（记录）；同一 spill 插件构建（记录）；两臂配置 diff 仅 `maxInlineTokens`。
2. 同 provider/model/思考档位；发射前各自一次微型预检往返并回读有效配置。
3. fixture 字节 SHA、TASK.md、工作区布局、cwd 模板完全一致。
4. 请求面捕获夹具就位（复用既有 DSH 请求面捕获形式：每请求 body+meta，含 seq、请求/响应 SHA、字节数、HTTP 状态、framing）；预检验证捕获完整性（SHA 硬等）。
5. 运行顺序交替；同槽两臂时间窗相邻；失败槽登记为失败，不重试替换。

## 5. 端点与判定

- **E1（主）**：每槽累计输入侧捕获字节 = 该槽全部主任务请求体字节和（不含标题请求）。判定：逐槽配对比值 r_i = B_i/A_i；median(r) > 1.1 → H_defer；< 0.9 → H_save；否则 H_none。逐槽 r_i 全部披露。
- **E2（主）**：恢复链分类（逐槽）：外存文件是否被工具读取（事件/请求面可见）；读取后下一请求 history 字节相对首请求的回升量。
- **E3（辅）**：源级估算 tokens（`ceil(chars/4)+4` 启发式）逐请求披露；明确标注非分词器真值。
- **E4（门槛）**：两臂各槽以同一冻结 checker 判 5 事实答案（只读判卷）；两臂任务完成度均达标才允许机制归因措辞，否则只报观测差并登记。
- 读取对：阳性=外溢臂对外存文件的工具读取且请求面/事件面同窗可见且答案正确；阴性=inline 臂同路径不存在，检测面命中>0=假阳性如实登记；配不上=该槽恢复链未知，不估召回率、不报污染上界。

## 6. 护栏与停止规则

- 任一臂等控清单失败、捕获缺口（主任务请求无 body/meta）、模型路由与申报不符、工作区出现 truth/checker → 立即停止发射、登记 NO-GO 与原因，不修补重跑当槽。
- 未知三件套照常登记；私档轨迹含请求正文全部私存，公开只发布哈希、长度、比值、分类与恢复链布尔。
