# 借用其他归档的适配模板，能否复建请求？（11-23）

在三组既有 DSH Chat 归档里，每组选首个主请求和辅助标题请求。每折留出一整组，用目标本地日志与另两组的客户端请求学习有白名单的适配字段、工具包装和序列化模板。先构造并锁定两种角色的候选，才打开目标请求及其元数据验收；训练请求的消息正文、工具名、描述和参数不进入模板。**与捕获请求相比，严格 JSON 整树等值和原始 UTF-8 字节等值两项，只用本地日志均为 0/6；加入其他归档模板后均为 6/6。** 只用本地日志时，主、辅助每包分别投影到 289/315、7/11 个叶，已投影叶无值差。

但六个目标只有四种请求字节。4/6 的目标在另一训练归档里已有同字节请求；剩下的 2/6 虽与两份训练请求均不同，但该折的两份训练请求彼此同字节。**没有一个目标同时满足「目标字节未见过」和「两份训练请求字节互异」。** 因此只说明物理留档外、固定模板已知时这六次复建成立，不证明遇到新请求形态仍可复建，不回填更严格的[只用原生日志](../原生日志请求重建边界-2026-11-23/README.md)的结论。此处的只用原生日志也额外投影了标题直接档位，不能把两个分母合并。

同值不同原始 token 的适配字段不能当作模板共识；两训练里同时出现不合格式的适配字段也不借用。相反，只改训练外层顺序可以生成与目标严格值相等、但原始字节不同的候选。例如 `thinking.type` 只验字符串类型、不限预定义取值；两训练臂同值同 token 的字符串仍可随模板进入候选。这是模板依赖，不是原档正文泄漏证据。内部非作者先盲算，再以正常和优化模式复跑；动态检查确认目标请求不提前打开。未重新发射请求，没有外部受控原件核验，不修改历史分数或冻结状态。
