# 较晚完整的工具历史，不能补证首次承接

**判断。** 同一个调用 ID 在后续请求出现，只能定位候选。首次出现调用或结果的请求，必须有唯一且有序的一对，才能确认该请求含有对应结构；若同组较早的合格请求正文缺失、无法排除它才是首次，则首次不可核，即使稍后有完整对也不能回填。然后分别比较工具名、参数原串和严格 JSON 值；有序对不因参数不可解析而凭空消失。

## 原件复核

只重算两种既有客户端捕获，不新增运行。先独立绑定运行归属、源响应和请求覆盖，再在实际角色位置中按 ID 对照。Chat 中无工具的标题请求不属于主任务；捕获索引也不等于摘要写入顺序。

| 固定范围 | 首次有序对 | 有自然较晚对的来源 | 首次名称／参数串／严格值 |
|---|---:|---:|---|
| Responses：12 包中按五组首响应 | 5/5 | 2/5 | 5/5 三项同 |
| Responses：固定 12 包所有带调用的源响应（扩展核查） | 7/7 | 2/7 | 7/7 三项同 |
| Chat：固定缺必填参数的失败源响应，16 请求 | 1/1 | 1/1，另有 13 个自然较晚对 | 1/1 三项同 |

首响应口径和全包口径并列：多出来的两个调用来自非首响应，均无自然较晚对。不把它们暗计入五组首响应的分母。Chat 原样转发缺必填字段，属于保真，不属于工具执行成功。

## 什么会使旧判断翻车

对同一批原件的内存副本，只改首个已配对请求或掩去该包；任何副本都不作为原件、新跑或频率观测。

| 控制 | 旧比较器 | 按首次接触，区分结构和内容 |
|---|---|---|
| 只剩结果，调用缺失 | Responses 的「任何后续同 ID 结果」仍收 7/7；Chat 的旧调用提取器改取自然晚对 | 8/8 首触结构不完整；仅原来就有自然晚对的 3 个来源仍可另报晚对 |
| 两角色倒序 | Responses 旧判仍收 7/7；Chat 旧提取器拒绝 | 8/8 在首次指出次序错误 |
| 参数串添一个空格／加入一个字段 | 旧的存在判断不回答这两种值变化 | 两组各 8/8 结构不变；前者原串异、严格值同，后者原串与严格值均异 |
| 最早成对的续请求正文不可见 | Responses 旧判仍检出晚结果 2/7；Chat 旧提取器取原有晚对 | 8/8 首次不可核；3 个来源可另报自然晚对 |
| 同一结果在最早成对的续请求中重复一次（独审反例） | Responses 旧判仍收 7/7；Chat 旧提取器拒绝 | 8/8 首次不唯一，不能由晚对补证 |
| 仅把内嵌参数换为不可解析字符串（独审反例） | — | 8/8 仍保留有序对；工具名同、参数串异、严格值未知 |

旧判断具体指 [Responses 早期 ID 链观测](<../CodexResponses观测口径-2026-11-23/README.md>)里的后续结果存在检查和 [Chat 单链取证](<../响应侧工具参数源头-2026-11-17/README.md>)的历史调用提取器；不把反例解释成产品出现过这种行为，也不回判旧结论。源响应中的参数副本一致性另见 [四份参数复核](<../Codex参数副本桥接-2026-11-23/README.md>)。
