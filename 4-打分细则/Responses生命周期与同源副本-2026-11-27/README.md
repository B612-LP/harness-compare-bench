# Responses：生命周期能补缺帧盲点，不能认证同源文本

[上一轮单帧删除](<../SSE终态与内容完备分账-2026-11-27/README.md>)中，8 份既有 Responses 响应有 52 个删项，重编后仍有正常终态、连续序号，且两组内容副本比较均未见异常。问题是：这些删项真没有可查的结构证据，还是当时没有问开头和分片是否存在？本轮复用同一批原档，不新增产品运行。

## 在什么条件下补齐

- **生命周期门。** `created`、`in_progress` 恰在前两条、`completed` 恰在末条。三个响应信封的 id、model、object、created_at 等可见指纹一致，状态符合固定序列。按 output index 和 item ID 绑定条目的 added、增量和 done；条目身份与完成快照一致。三类文本的重组与专门 done 须吻合，且只支持本批非空完成文本。错误、未知形态、失绑或缺证不填成通过。这是参照[旧试行说明](<../CodexResponses观测口径-2026-11-23/README.md>)的新迁移探针，不是对旧 12 包同一实现的重跑。
- **部件扩展。** 对推理及可见正文各部件，另查开端、增量、专门 done、部件 done 和条目 done 的关系，以及条目里的相应内容副本。工具参数没有此类正文部件，另对照专门参数 done 和条目 `arguments`。这是固定形态，不是所有 Responses 事件的协议规范。
- **同源身份。** 以上是可观察的内部一致性。保持原件的锁定摘要与对象绑定，才能判断派生字节不是已知原件；不能仅据计数或多份同源副本认证内容未改。

## 固定八流的结果

8/8 原档通过上面两道结构门。对原 1015 个已派发数据帧逐一删一帧，再仅重编保留帧的顶层序号数字，同一原件作多个反事实，不是 1015 次独立观察。按首个拒绝层互斥分账：

| 对比对象 | 生命周期门拒绝 | 仅部件扩展拒绝 | 两道均未拒绝 |
| --- | ---: | ---: | ---: |
| 1015 个单删重编派生 | 995 | 20 | 0 |
| 其中上轮 52 个盲点 | 32（16 阶段、16 条目开端） | 20（10 部件开端、10 部件末端） | 0 |

内部非作者从原档独立重建并逐项复算。按首个拒绝层一致；在已经由生命周期门拒绝的 26 项上，独立关系区间实现与原状态机的次级部件标签不同。不隐藏这项差异，也不把二级标签不同的项目算作漏过。上述结果只回答这批单删变体，不是全协议误报/漏报率。

**反例：把同一工具参数在增量、专门 done、条目 done 和完成信封四处同步改写。** 构造派生内终态、序号、两道结构门均过，但投影字节不再是已锁原件；该变化甚至能使参数字符串内部不再是合法 JSON，因为本门只比字符串，不负责参数 JSON 或工具 schema。相反，将所有副本同步清空会命中本批的非空准入，不能把这种拒绝都叫作“同源副本彼此不等”。

## 可复算的公开构造

使用标准库 Python 3.9+，在本目录运行 `python3 -B demo.py`（亦可加 `-O`）。[生命周期探针](<lifecycle.py>)接收已经分帧和解码的对象；[演示](<demo.py>)自己构造 9 帧单正文部件，逐删时 7 个由生命周期门拒、2 个只由部件扩展拒；再对照同步替换仍通过、同步清空触发非空约束、已知原表示摘要改变。演示不是私档回源或任意供应商解析器。
