日期：2026-11-23。各口径页声明了结构与数字的门，但「输入是否落在已校准范围之内」此前没有一处显式登记。本页把冻结原件的支持域列成清单，并给出一条出域判定规则；试行不冻结。对应[冻结门清单](<../观测规范冻结门清单-2026-11-23/README.md>)的 G5 门，[未知处置表](<../未知处置表-2026-11-23/README.md>)的出域行为在此获得清单依据。

## 漂移判定规则 v1

- 请求：顶层键集合不在清单内 → `unknown_out_of_support`，不静默收下；在清单内 → `in_support`，域内仍走[DSH 口径](<../DSH观测口径校准-2026-11-19/README.md>)、[Codex 口径](<../CodexResponses观测口径-2026-11-23/README.md>)、[数字口径](<../数字口径定版候选-2026-11-23/README.md>)各自的结构门与数字门。
- 响应流：出现清单外事件名 → 该流 `unknown_out_of_support`（已核实层保留，不填 0）；事件名全在清单内 → `in_support`。
- 升级条件：供应商 schema 演化的证据（官方变更记录，或新捕获整批一致的新键集/新事件名）→ 另环扩清单并重校准；本页不预设漂移阈值。
- 校准与负控：130 份原件全部 `in_support`；合成负控（清单外顶层键、清单外事件名）按规则出域；已知 DSH 基础键集与 7 事件名流按规则入域。判定只回答「入域/出域」，不替代结构、近错与数字门。

## 它不能说明什么

- 清单来自 2026-11-23 前的冻结批；新产品的合法演化会出域——出域不是缺陷判定，而是「当前校准面之外」的登记。
- 入域不等于通过任何结构门；出域层不抬高或拉低任何历史成绩。
- 不冻结；扩清单走另环；不覆盖受控第三方核验（外部阻塞维持）。

## 证据与边界

清单与判定由环内脚本从 R112 封印的 130 份原档抽取（逐锚 SHA 链可复算）；与四份口径页和[验收条款](<../../反馈/2026-11-18-第五轮/验收条款-公开版.md>)第 1 条的对照见环执行记录；非作者复审收据随环登记。

## 11-23 补充：DSH Chat 的已见载体（不并入 DSH messages）

对旧的三个捕获重新按包核对请求与响应的字节承诺，并分开**归档绑定、请求形状、响应载体形状、流闭合**。三个捕获均为代理重分帧；只描述客户端留档可见的 SSE，不推服务端原始分片。主/辅标签来自已有档案的任务边界，不由键形或返回内容反推。

| 原档范围 | 主请求 / 辅助标题 | 同角色的请求＋响应形状命中 | 末帧和 choice 闭合可核 |
| --- | ---: | ---: | ---: |
| 学习：两个捕获 | 17 / 2 | 19/19 | 19/19 |
| 留出：同一历史研究的另一捕获 | 14 / 1 | 15/15 | 15/15 |

两部分合计 **34 对**，字节承诺与传输元信息均绑定；终止为 28 个 `tool_calls`、6 个 `stop`。留出未参与学习，不是独立随机样本。按上文的 **messages** 请求键/事件族对照，Chat 的请求键集合、响应事件族各 **0/34** 命中；这说明旧清单不适用，不是 34 条坏流。

- 请求：主/辅共有 `max_tokens`、`messages`、`model`、`stream`、`stream_options`、`thinking`；主请求另有 `tool_stream`、`tools`，有工具且非空，辅助标题另有 `reasoning_effort` 且无 `tools`。只使用键集合和薄类型，不用形状重新认定任务身份。
- 响应载体：两类均见默认 data-only JSON 帧，顶层为 `choices`（非空）、`created`、`id`、`model`、`object`，有一类另有对象型 `usage`；哨兵为默认 dispatch `[DONE]`，不借用 messages 的事件名。边际形状只比较实际已观察的载体；请求和响应的合取另要求学习到的组合。闭合再核 choice 外层键型、已学习的终止值、唯一末哨兵及无迟来的 choice 内容。形状命中不证明闭合，更不证明参数或语义相同。

| 只改变一项的离线对照 | 结果 |
| --- | --- |
| 请求尾空格 / 加陌生顶层键 | 分别 34/34 保持请求入域、34/34 出域；均不再是原档字节 |
| 互换主/辅请求正文 | 6/6 在混合清单仍入域；按原角色 6/6 不命中，不能借形状补身份 |
| 响应换行表示 / 加陌生顶层键 | 各 9 份：前者形状和闭合均保持；后者形状出域，闭合仍成立 |
| 删末哨兵、只留下未派发末哨兵、重复同 choice 终止 | 各 9 份不能认证闭合；已观察 JSON 载体仍可落在边际支持域 |

独立复核另外验证：可读且有模拟绑定的 JSON 帧缺 `choices` 或类型不符，及只给末哨兵添加显式事件名，均是响应出域；同一正文如果不能绑定到对应包，不把它当成已观测的出域。若保留哨兵但缺 choice 终止，合取形状仍可能命中，闭合仍不可核。公开数字只作聚合复核；受限原件由内部非作者从头重建，尚非受控第三方验收。适用范围不含更深的 `delta` 字段、工具语义或通用 Chat 兼容性；不回写旧结论与成绩、不冻结。

## 11-23 补充：编号、入账与时间准入

同一批 34 个捕获中，31 个主请求作起点。先筛主请求后，按摘要入账与序号各取主后继，均与捕获墙钟裁定一致：28 个有唯一时序合格后继，3 个无后继；197 个同组主主对未见时间倒序、重叠或端点接触。**按序号直接取下一包会误选辅助请求 3 次。** 三个辅助包与各自较低序号主包的捕获墙钟区间均有正长度重叠，而且更早起止；本批按墙钟筛选时，即便不另排辅助，亦不会把它当成已经结束的主请求的后继。不能把这种本批一致性当作编号可靠性的普遍规则。

对照只改现存归档的副本。允许 `后件开始 = 来源结束`，但同一最早开始出现两条候选时不任选；若无法排除缺失槽更早或与已见最早项并列，首次记不可核；如有已见候选则另列。已有绑定开始严格晚于已见最早项的缺损槽，不遮蔽首项。独审近错中，缺开始的较早槽，仅当仍有身份绑定的可信结束**严格早于**来源结束，才可从候选排除；结束等界或更晚不能排除，不用所报时长倒推开始，也不给部分槽完整资格。

内部非作者先从同一批原件独立复算、后比实际实现；数字仅代表本地捕获墙钟与可见范围。时序准入不证明调用与结果的历史身份、服务端顺序或因果，不冻结规范，不新增产品或模型运行。
