# 脱敏视图与缺参核验：能看到缺键，不等于能独立确认原件缺参

从[已复核的 Chat 与 Responses 首轮工具组](<../工具组观测字节重放-2026-11-24/README.md>)固定取四份旧捕获，每份只核首请求和首响应；不另取样。这里问的不是某工具是否执行正确，而是：**只拿到一种公开派生时，可否重新核验「原响应确实漏掉了同请求声明必填的顶层键」？**

| 可接触的材料 | 能重算的事实 | 还不能重算的事实 |
|---|---|---|
| V0：删值且不说明有没有删除目标键，只保留其余键数 | 派生里剩余的计数 | 原对象的目标键存在与否 |
| V1：顶层逐成员标记目标／非目标及重复次数，不公开值或其他键 | 在所给轮廓里，目标键占几位 | 原对象一一对应、嵌套也通过严格 JSON、同一请求声明必填 |
| V2：先从已绑定原件严读对象、在同槽请求选唯一同名工具声明，再只给成员与顶层 `required` 两轴及裁定 | 复查两轴怎样推出该条裁定 | 没见过原件时，不能独立重做原件绑定和严格判读 |

## 固定旧档与近错

- 四对首体全与先存凭据相符，四组首流可重建。在五个调用上，严格参数对象均没有目标键 `command`。唯一同槽声明中的显式顶层 `required` 列表只在一条列出它；另四条的该列表没有列它，**不是四次工具正确，也不等于整个 schema 没有别的约束**。那一条与[先前响应侧缺参结果](<../响应侧工具参数源头-2026-11-17/README.md>)一致，不是新出现的失败或发生率。
- 合成对照中，一个目标成员被删除和它从未存在可产生相同 V0；只看顶层的 V1 可掩掉嵌套重复键，不能证明全树严格。一个值是 `null` 的成员仍然在场；「存在」不等于类型正确。同一轮廓配不同必填清单可以给不同结论。跨位置、跨名字空间或声明没选定时，保留各边能确认的局部事实，不拼出一个联合缺参结论。
- 保持两份 Chat 请求原字节不动而互换不同的首响应，两个目标位置的响应摘要都不匹配。若只忽略这一绑定，再使用对调后的响应，槽级两个判定会互换，但汇总仍是一个必填确缺、一个未列为顶层必填。**公开总数没变，不等于独立核到了相同的两条链。**

## 对复核的要求

公开 V2 可以解释为什么结论成立，并让读者检查规则是否由所报状态推出；它不是原件或可反算原件的凭据。要复做原件判断，受托核验者至少需要同次的首请求及闭合首响应、可核位置锚、相关声明和可严格重建的调用参数。只看脱敏摘要不代替这一步；本研究是项目内非作者从固定旧档独立重投影并另做合成反例，**仍不是受控外部第三方核验**。不改旧盲验、冻结或历史评分，没有新增运行或判卷。
