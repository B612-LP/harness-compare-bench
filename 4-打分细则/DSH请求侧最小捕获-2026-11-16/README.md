# DSH 请求侧最小捕获协议（2026-11-16 冻结）

## 目的与授权边界

老师 2026-11-11 第四轮反馈 P1 要求区分输入减少是"工具外溢、历史截断还是消息重组"。既有研究只证明了最终请求不可从归档观测（2026-11-12），缺少请求侧直接证据。本协议在用户明确授权的**最小范围**内（本地观测层 + 1 次有界真实运行）捕获一次真实 DSH headless 任务的完整请求体，用于观察：系统提示与工具清单形态、多轮历史如何在后续请求中累积（外溢/截断/重组的直接见证）、以及实际请求字节与产品 reported 计数的关系。

- 仅 1 次真实模型运行；不得补跑、不得增加任务数。
- 不修改 DSH 安装包、权限、模型上下文定义；观测层为本地 HTTP 转发代理 + 独立 profile 克隆。
- 请求/响应原文只存仓外私档；公开材料只含派生元数据（字节量、SHA-256、角色/结构序列），不含任何正文、密钥、路径原文。

## 观测方法

1. 复制 `~/.dsh/profiles/headless` 为独立 `capture-r1` profile，唯一 diff 为 LLM provider `baseURL` 改指本地代理 `http://127.0.0.1:8791/api/coding/paas/v4`。
2. 启动本地 stdlib 转发代理（127.0.0.1:8791 → https://open.bigmodel.cn:443），逐请求落盘：请求体原文字节、响应体原文字节、元数据（方法/路径/头——`Authorization` 等敏感头只记 SHA-256 前 16 hex / 字节数 / 哈希 / 状态 / framing / 时延）。
3. 包装器 `~/.dsh/bin/dsh-headless-capture` 以该 profile 启动一次 headless 任务。

## 与日常 headless 运行的已知差异（观测范围声明）

- 捕获包装器不导出 `DEEPSEEK_API_KEY`：机器默认路由 `deepseek-official` 不可用（2026-11-16 晚两次基建验证已实测：无 key 时硬失败 `MISSING_CREDENTIAL`，不回退）。
- 因此捕获运行通过 patch 显式指定默认模型 `zai-coding-cn / glm-5.3-flash`（该 profile 配置注释声明的既定 provider）。系统提示/工具清单/历史组装属 harness 侧行为，不随 provider 改变；provider 身份属于本次观察范围的显式声明，不冒充"全默认"运行。
- 基建验证期间发生过 2 次计划外真实 DeepSeek 调用（key 在环境时默认路由被选中），均为一句"回复 OK"的验证任务，成本约 16k tokens（大部分命中缓存）；已如实记录，不重复发生。

## 任务设计（1 次）

工作区 `~/bench-workspaces/capture-r1/`（仓库外，仅 `TASK.md` 与 `inputs/exercises/dominoes/dominoes.py` 34B 名义骨架）。任务要求先读 `TASK.md`、再读 dominoes 骨架、然后一行作答——强制至少 3 次请求（读→读→答），产生真实多轮历史累积。不使用网络/搜索；无需写文件。

## 分析问题（预登记）

- Q1（外溢）：第 2、3 个请求是否完整携带此前轮次的 assistant 工具调用与工具结果？（历史只增不减 = 无截断见证）
- Q2（截断/重组）：请求间字节差是否恰为"上一响应+新消息"的序列化增量；有无消息被改写/删除/压缩的见证。
- Q3（计量）：请求实际字节 vs 响应 usage reported prompt tokens；两者比值仅在本次运行内描述，不外推。
- Q4（系统提示）：首个请求的系统提示与工具清单的组成层级（只报结构与字节量，不复制正文）。

## 验收

- 捕获目录含 ≥3 个请求体 + 对应响应体 + 逐请求元数据；代理收据 `PROXY-START.json`、`summary.jsonl` 完整。
- 公开包（本目录后续文件）只含：协议（本文件）、从私档重建的派生证据（结构/哈希/字节量）、可复算脚本、执行记录；每条公开数字绑定私档文件 SHA-256。
- 非作者独审后发布；证据不认证 provider 服务端行为、不冒充完整请求侧通用结论（n=1）。
