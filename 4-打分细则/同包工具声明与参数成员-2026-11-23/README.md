# 同包工具声明与可见参数成员（11-23 离线复核）

**跨包声明一致，不代表当前调用在本包有声明。** 复核两种客户端捕获格式：Codex Responses 的 12 个原包（7 个有目标调用、5 个无），以及 DSH Chat 的一个[已知自然失败](<../响应侧工具参数源头-2026-11-17/README.md>)。7 个 Codex 调用各能绑定本包的唯一同名函数声明，且响应含本次所查的必填字符串成员；Chat 这一个也有唯一同名声明，但最早可见响应已缺本次所查的必填成员。两者不是同条件产品比较。

| 只改已捕获请求的离线对照（响应字节保持不变） | 读到的区别 |
|---|---|
| 逆序排列一个包的工具列表 | Codex 旧跨包一致性门逐包试时 12/12 翻转；其中 7 个目标调用的同包声明和参数成员均不变。旧门实际比较有序投影。 |
| 全 12 包都一致地改声明名，保留原响应 | 旧跨包门仍见 9 项一致的声明；7/7 目标响应找不到本包的原名，必填规则不再有绑定。 |
| 本包加一份完全相同的同名声明 | 7 个 Codex 与 1 个 Chat 均不再唯一；响应成员本身照旧可见。 |
| 声明移除目标必填标记／规则换成超出所测范围的形态 | 两类各 7+1；前者可确认派生声明不再要求该成员，后者只确认规则不可核，且两者都不改实见成员。原自然失败不补判。 |

同名还要核外层函数声明形态。响应侧也不能只看选中的一条：独审在 Chat 副本插入一片缺 ID 和名称的孤立参数，旧 Chat 解析仍给出原目标，修订后的局部门则因额外参数键无法绑定而停止判定。若非目标键有合法名称、唯一未复用 ID 且满足终止约束，本对照仍保留目标观察；这一步不要求该非目标键在请求中已有声明。

这是对原捕获支持面和离线反例的内部非作者复核；公开表不含原参数，不能从表重建绑定。范围只及两个示例的固定顶层字段、所见调用和已测试的声明形态，不是完整 Schema 校验、供应商验收或 Harness 因果证据，不代替受控第三方核验。双线试行未冻结，正式格与历史分数不变。
