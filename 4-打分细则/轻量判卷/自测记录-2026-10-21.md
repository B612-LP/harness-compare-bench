## 2. oracle 回归（参考解产物 → 必须 reward=1）

```bash
# int-sum-sort：用 awk 参考解生成 output.txt（与 checker 的 Python 实现互证）
rm -rf /tmp/oracle-runs/intsum && mkdir -p /tmp/oracle-runs/intsum
cp 2-用例/int-sum-sort/environment/input.txt /tmp/oracle-runs/intsum/input.txt
{ awk '{s+=$1} END {print s}' input.txt; awk 'END {print NR}' input.txt; sort -n input.txt; } > output.txt
```

## 3. 旧判分器（v0.2 Harbor test.sh）vs 新 checker（v0.3）——同一攻击样例

| # | 攻击样例（期望：拒绝） | 旧 v0.2 | 新 v0.3 | 说明 |
|---|---|---|---:|---|
| 1 | int-sum 排序块折叠成一行（`8 17 23 42 56 99` 挤一行） | **1（漏）** | 0 | 新增 `format_strict`：每行一个规范整数 |
| 2 | int-sum 排序块中间插空行 | **1（漏）** | 0 | 同上，空行不再被 `sed '/^$/d'` 洗掉 |
| 3 | int-sum 篡改 `input.txt` 后自洽作答 | **1（漏）** | 0 | 新增 `input_integrity`：SHA-256 守卫 |
| 4 | int-sum 缺结尾换行 | 0（碰巧，尾空格不等） | 0 | 新 checker 有**显式**结尾换行断言，报错定位准确 |
| 5 | word-freq 篡改 `corpus.txt` 后自洽作答 | **1（漏）** | 0 | 新增 `input_integrity` 守卫 |

**结论**：v0.2 对 #1/#2/#3/#5 共 4 个攻击样例误判为通过（漏判）；#4 旧版因尾空格不等而"碰巧"判 0，但无显式结尾换行断言；#6 陷阱两版均正确拒绝；#7 正向两版均通过。v0.3 对 4 个漏判样例全部拒绝，且新增显式断言与输入完整性守卫。

## 4. 用例自身一致性（防实现漂移）

- `int-sum-sort/truth.json` 记录 canonical 输入 SHA-256（`3bcc65ec…`）与期望产物行；checker 启动校验，输入被改 → `ERROR` 退出码 2。
- `word-freq-report/truth.json` 记录语料 SHA-256（`b5fc559b…`）与期望值（total=92 / distinct=35 / top5=the 8, and 7, fox 6, a 5, dog 5）；checker 用 Python 现算并与 truth 交叉校验，同时与 `solution/solve.sh` 的 awk 实现互证。
