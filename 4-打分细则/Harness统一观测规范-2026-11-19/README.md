## 1．观察对象、分段与绑定

| 层 | 观察单位与准入 | 不得替代 |
|---|---|---|
| L0 原载体 | 收录标识、角色、实际字节数与 SHA-256；原件、合法重编码副本及公开派生分开。解码前后分别计量。 | 相同摘要可证明相同字节，不能单独证明属于哪个运行、角色或时间。当前持有承诺不是历史独立见证。 |
| L1 本地事件账 | 按解码后的物理顺序保留事件与字段，禁止用时钟重新排序；区分容器字节、解码字节、行数及逐行规范值。 | 不是发送给模型的请求体；本地序列不同，不推出客户端首请求不同。 |
| L2 本地语义投影 | 用各格式的显式任务、轮、步骤及角色边界；本地工具调用和结果用同段、同类型、唯一标识绑定，辅助标题分开。披露选定字段与完整对象的分母。 | 本地事件闭合或产品标记完成，不等于正确执行、操作系统实读、任务成功或结果下游可达。 |
| W 客户端捕获 | 请求与响应分别登记；关联同一运行的元数据、任务、角色和身份，响应经相应流式终止门后才解释一个受检完整项。 | 客户端正文不是全网包、服务端实际摄入、token、计费、真实缓存或实际思考工作。自报用量另账。 |
| H 后续请求历史 | 指首个有证据承接该项的合格主请求；在相应格式下核同调用/结果、类型、顺序与后续阶段。 | 不是任意下一捕获序号或同名下一调用；没有后续捕获就不填 H。 |

关联的必要字段若缺失、矛盾、重复或跨段，先判归属不可核；同名、等时、等长或等字节不能补齐。冗余标识出现时须相符，不允许主 ID 对了就忽略矛盾副本。反过来，一端归属不可核不抹掉另一端独立成立的事实。完整请求重建另须有**绑定的请求正文本身**作参照、有非空全字段覆盖证明，且构造从独立的同目标输入开始，不能从目标捕获复制数值或序列化。报告选定字段命中、全值是否重建、原始字节是否重建三个不同结论。

## 2．格式配置：共享裁定，不共享解析器

| 配置与受检范围 | 事件与分段 | W/H 与专门反例 |
|---|---|---|
| `dsh-v4/chat`：[真实格式校准](<../DSH观测口径校准-2026-11-19/README.md>) | 全部合法 zstd 帧 → 严格 UTF-8 NDJSON；session v4 首行，`seq` 自 0 连续。按该版 I 输入、K 交互、M 辅助字典分族；`turn/start`–`turn/end` 内按不重叠的 `step/start`–`step/end` 分段，已有显式 ID 和内外来源须与活动段相符。标题请求独立登记，不当任务消息。 | Chat SSE 按 choice 和 tool index 拼接，本样本用 `finish_reason=tool_calls` 后验 `[DONE]`。受检首次完整工具项还要连本地响应锚、同段调用和结果，以及主续请求。只改本地末端包装可破坏这个链接，不能倒推出 W 自身无法解析。 |
| `codex-native/responses`：[参数校准](<../Codex响应参数跨层校准-2026-11-19/README.md>) | 严格 UTF-8 JSONL 物理行序；本样本以唯一首 `session_meta` 与 `task_started`–`task_complete` 定界，核同线程、轮次和受检原生 `UserMessage`，不挑第一条 `role=user` 充任务。局部调用和结果分别定位，不宣称全事件字典。 | Responses SSE 按本身的事件/JSON 类型、顺序号、输出索引和项 ID，跟踪 added → 参数增量 → arguments.done → item.done → `response.completed`。受检包装若还带 call ID 或名字必须一致。不套 Chat 的 `[DONE]`。H 按同任务和有序调用及承接结果定位。 |

两个格式配置的历史实现不假装统一了所有数值规则。其余产品或同产品未支持的格式不能默认套用；可保留已知 L0/L1，但缺少相应字段和端点时仍为不可核。

## 3．计量与三个状态

- 报告注明格式配置版、角色/起止锚、视图及选择范围、算法/单位、分子/分母和证据层；容量单位是 B 而不是字符、token 或成本。原始载体或正文字节计实际 UTF-8/文件字节；原始值比较用实际字节或已核摘要，长度只作并列度量。压缩容器、解压日志和 SSE 包装不混算。参数字符串按从外层取出后的 UTF-8 计数，不含外层转义；若比较内嵌对象，再显式严格解析一次。
- 指定规范 JSON：对象按 Unicode 码点排键，无额外空白；数组原序、UTF-8，不做 Unicode 正规化、不删事件字段；逐行合计不含换行。重复键、非法 UTF-8、不成对 surrogate、非有限量及超过算法边界的输入不产值。相同结构的换行、空白、键序、Unicode 转义或合法重压缩可改变原始字节，不改变该算法下的受检值。字段筛选变化不是重编码。
- DSH 校准使用有界精确十进制（对象层整数、小数/指数分型，保留正负零，按固定系数/指数序列化）；Codex 已发布的是其旧对象实现上的局部字符串参数实例。不得跨算法宣称数值或规范字节等值。合成反例显示二进制浮点会合并两个等长但不同的十进制值。既不能据此假定产品接受这种数值，也不能把合成反例写成历史原件实际误判。
- **存在**：合格容器上的值，原始 `null` 或数值 `0` 均是值、两者不可替用。**确认缺失**：目标属于完整而已绑定的对象，字段确实不在其中；两个对象都无该字段也不产生数值等式。**不可核**：源缺、坏格式、错绑定、覆盖不足、比较单位/算法不兼容等；保留原因和必要的非空分母，受影响指标写 `null`（此处是结果账标记），不填 0。真实变化是两个可比较的已知值不同，不把不可核当失败或行为变化。

## 6．读取检测的产品配对与分层（0.4 新增）

- 配对语义沿用非产品校准：真阳=正臂检出预登记对象；真阴=负臂检出灵敏度正控对象且目标全程未见；负臂误见目标即对象错绑；任一未知记配对未知，不折算召回。FD 检出证明「该产品进程在该窗口持有该对象」，读取语义由独立真值层（产品答案中的内容摘要）承担；FD 有无仍不区分实读与仅打开。
- 本批四臂九对：DSH 与 WB（进程内多段读读者）正负配对闭环（含 TP+TN）；Codex（shell 工具链读者）真值成立但检出概率性，配对以未知为主，仅一对 TN；豆包（常驻执行器读者）负臂真阴闭环、正臂真值成立但守护进程内读零观察（7659 全家族 pass）。对象错绑 0/8。
- 检测面可用性按**读者形态**陈述：进程内多段读窗口毫秒级可检；shell 工具链读亚毫秒级存在结构性漏检（非 root 用户态 ~1.1 ms 仪器地板，8 次受控链重放命中 1 次）；常驻执行器读可检性随当次读法分叉（短命 shell 子进程 stdin 重定向可检，守护进程内读低于仪器地板）；尺寸敏感性探测（512B→8 MiB 单变量）把四臂统一为 FD 持有时长主导——毫秒级以上持有可靠可检，亚毫秒持有按地板漏检；纯内容读路径同律且窗口更窄（512B 0 检出、8 MiB 1 检出）；DSH 512B 产品臂检出率 13/20=65%（95% CI 约 [41%, 83%]）证明漏检是常态成分，检测敏感度按产品实测陈述。仪器地板是规范边界事实，漏检如实记 FN/未知，不得写成「未读取」或「无读取风险」。
