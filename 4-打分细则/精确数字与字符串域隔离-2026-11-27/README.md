# 精确数字与字符串域隔离：有限校准，不冻结规范

日期：2026-11-27。承接[请求原字节与浮点反例](<../wire请求面扩展-2026-11-27/README.md>)与[11-23数字候选](<../数字口径定版候选-2026-11-23/README.md>)。本页是事后已见源码的测量实现研究，不是新的产品试验、受控机制效果或正式判分；统一规范冻结基线、旧分数与原封材料不改。

## 1. 研究前判断 → 现在减少了哪项不确定性

跨语言的二进制浮点近似不能冒充完整的精确数字口径。转向精确十进制也不自动安全：旧候选A先把数字变成带NUL的特殊字符串，再对整份序列化文本解引号，未强制检查真实字符串是否与哨兵碰撞。我们要区分：这是只在构造输入出现的潜在缺陷，还是已经影响本次复用的真实档。

结果是：**串域碰撞确实存在；本次复用的1569私档载荷与235公开原行中没有该触发内容，A与新候选字节均相同。** 不能由合成反例推断历史已误判，也不能由真实档全配证明实现通用安全。[旧A原文件](<../数字口径定版候选-2026-11-23/number_profile_public.py>)保留原样；[11-24类型对象参考B](<../工具组观测字节重放-2026-11-24/replay.py>)没有使用字符串哨兵，但其支持边界与A不同，不合并成同一冻结算法。

## 2. 可直接复现的串域反例

下表输入都是真实可解析的合成JSON；`\u0000`表示JSON转义，不是将裸NUL写进JSON。

| 输入 | 旧A实际输出 | 问题 | 新候选C |
| --- | --- | --- | --- |
| `{"v":"\u0000NUM:1\u0000"}` | `{"v":1}` | 字符串变整数，仍是合法JSON | 保留原字符串 |
| `{"v":"\u0000NUM:true\u0000"}` | `{"v":true}` | 字符串变布尔值 | 保留原字符串 |
| `{"\u0000NUM:1\u0000":2}` | `{1:2}` | 键被解引号，产出非法JSON | 保留字符串键 |
| `{"v":"\u0000NUM:wat\u0000"}` | `{"v":wat}` | 产出非法JSON | 保留原字符串 |

52个固定作者输入中，A与C共同接受34个，28个字节相同，另外6个为明确保留的哨兵反例。400个固定seed构造输入故意都带该哨兵，全部不同；这是定向覆盖，不是产品错误率或污染概率。旧A也没有在这些输出后重新验证JSON有效性，`accept`只表示其函数返回了字节。

## 3. 新候选C的精确合同

[Python实现](<exact.py>)与[独立Node实现](<exact.mjs>)使用独立数值类型，不先伪装成字符串；数字值不转为binary64。两实现共用以下**有界候选合同**，不是通用JSON标准：

- 只接受严格UTF-8、外层对象；拒绝重复解码键、孤立代理项、NaN/Infinity和非法JSON。键按Unicode码点排序，不作NFC归一化。
- 数字原词长最多1024字符（包含符号、小数点和指数）；指数数字位数最多5（包含前导零），原指数绝对值最多6144；这些限制在零归一前检查。
- 整数词型保持原词，含`-0`。小数或指数词型用精确`系数e指数`表示，系数去前后零、至多1024位，归一指数绝对值至多6144；零为`0e0`或`-0e0`。
- 根对象深度0，键和子值都加1，最多128；超域就拒绝，不能悄悄降级或截断。
- 因此`1.50`与`1.5`相同；`1`与`1.0`、`-0`与`0`、NFC与NFD仍不同。`1e309`在本精确合同内可接受；这不是对二进制浮点非有限数的放行。

旧A系数上限4096，旧B原指数上限10000，新C采用更窄的显式交集；域外拒绝不算旧实现错，也不能由跨域结果声称算法等同。
