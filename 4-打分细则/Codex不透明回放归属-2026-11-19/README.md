# Codex 不透明回放的跨层对账（2026-11-19）

同一条已留存运行的两个接续点上，**完成响应中的不透明字段，在对应的原生条目与下一条捕获请求的回放位置都出现，字符串值逐接续点相等**。完成响应与原生记录能按类型、顺序和条目 ID 直接对应（2/2）；回放位置的推理条目没有 ID，只能由相邻的调用与结果唯一定位（2/2），**直接条目身份仍不可核**（2/2）。

[此前的回放观察](<../Codex深链与加密推理回放-2026-11-17/README.md#L18-L29>)只核查了请求侧历史，本次补看已留存的完成响应与原生会话。没有发起新运行或回放。

| 完成响应（W）→ 下一捕获请求的回放（H） | H 中新增位置（从 1 起算） | W−原生记录（N）条目匹配 | 不透明字段（W / N / H） | 报告的相等（W=N / W=H / N=H） |
|---|---:|---|---|---|
| W001 → H002 | 5 | 类型、顺序、ID 直接匹配 | 均存在，各 38 个 UTF‑8 字节 | 是 / 是（按位置） / 是（按位置） |
| W002 → H003 | 8 | 类型、顺序、ID 直接匹配 | 均存在，各 38 个 UTF‑8 字节 | 是 / 是（按位置） / 是（按位置） |

**分母：1 条历史运行、2 条首次接续、1 次历史重复。** H003 的第 5 位是 H002 第 5 位的携带重复，报告值相等；它不是 W002 的新增接续，也不是独立样本。没有比较 W001 与 W002 的值；相同长度不表示它们彼此相等。

## 怎样对齐

1. **完成响应 ↔ 原生记录：** 用完整的结束帧、按序的类型化输出与条目生命周期限定候选；在同一原生轮次内按条目 ID、顺序及调用/结果关系对齐，不用字段的值或长度决定身份。
2. **完成响应 ↔ 下一请求：** 三个请求的类型化输入前缀逐次保留，条目数为 4 → 7 → 10。每次新增恰好一个「推理、调用、结果」序列；由同一调用及其结果唯一定位本次新增的推理位置。请求侧推理条目没有 ID，故保留「按位置关联」而非「按条目 ID 证实身份」。
3. **字段值：** 结构匹配后才在内存中比较 JSON 字符串值；UTF‑8 长度不含 JSON 转义或传输帧开销。未解码不透明值内部编码。源侧合成对照区分了同长度改值、同类型错条目、字段缺失与显式 `null`、以及旧调用链复制。

这些证据支持「已观察端点未见字段缺失或值变化」，不支持「同一对象经回放传递已获证实」。等值复制及未捕获的中间处理不能排除；不推断流的生产方、密码学性质、推理内容、服务端状态或下一次运行行为。不是因果干预或稳定性估计。

## 无原件复算

[序号投影](<evidence.json>)仅含序号、类型、状态、长度和比较布尔值。[校验脚本](<verify.py>)从投影重算 H 新增位置、历史携带及分母，并检查报告字段的一致性；它**不会也不能从公开材料重做条目 ID 匹配或原值相等比较**。两种模式使用同一组无原件测试：

```sh
python3 verify.py --self-test
python3 -O verify.py --self-test
```

输出的 `source_value_equality_recomputed` 应为 `false`。测试包括把新接续错绑到旧位置、破坏前缀或调用关系、以及相同长度但报告不相等；后者仍保留首次接续分母。
