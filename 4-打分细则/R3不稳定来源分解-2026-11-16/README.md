# R3 不稳定来源分解（2026-11-16）

**预注册：对 [r1109](<../../3-表现现场/r1109-mech-n3/README.md>) 已归档 15 个 Codex 槽（5 组 × n=3）做逐事件型字节分解，回答「字节子门 0/5 的不稳定到底来自哪一侧」。** 纯事后算法分解，不新增运行、不改任何门判定；[机制重复口径澄清](<../机制重复口径澄清-2026-11-12/README.md>)与[机制序列口径 v2](<../机制序列口径v2-2026-11-16/README.md>) 的结论不回写。本页冻结于任何组内分解值计算之前。

## 1．问题

v1.1 已记录：Codex 五组 R3（逐 turn 重构输入字节）组内 max−min 为 154,301–471,897 B，字节子门 0/5；同页「次要控制观察」记录了稳定核——五组首三条 `response_item` message（developer permissions / user environment / user task）的 role+content canonical 哈希组内一致。但**不稳定的主体成分从未被分解**。R3 的观测定义（[请求侧观测规范](<../请求侧观测规范-2026-11-08/README.md>)）是「上一 usage 边界之后全部 `response_item` 载荷」，其中既含任务/环境面（user/developer message、`function_call_output`、`turn_context` 等），也含**模型自身生成**（assistant message、`reasoning`、`function_call`）——后者随生成波动是预期行为（同 DSH S4 1.21–1.93× 的既有文档），回流进 R3 会使「输入不稳定」的表述混淆两侧。

## 2．定义（冻结，执行前写定）

- 数据源：v1.1 已绑定的同一批公开源（69 源钉定）与归档原件；R3 逐槽总和必须与 [v1.1 result.json](<../机制重复口径澄清-2026-11-12/result.json>) 逐槽值硬等，否则报错。
- 逐槽逐事件分类（以归档 payload 实际内容为准，与 v1.1 投影 `payload.type` 交叉校验）：
  - **模型生成族 M\***：assistant `message`、`reasoning`、`function_call`。
  - **环境/任务族 E**：developer/user/system `message`（按 payload 内 role 区分）、`function_call_output`、`turn_context` 及其余非模型生成项。
- 指标（逐组）：取 R3 总和最大槽 M 与最小槽 m，分解 Δ = R3(M) − R3(m) = Σ_型 (bytes_M,型 − bytes_m,型)——**带符号、可加、精确**；两族各给出净贡献与占比。另列全部三对槽的成对分解作稳健性附注。占比阈值预注册：某族净贡献绝对值 > Δ/2 记为「主导」。
- 附注复验：首三条稳定核哈希组内一致性重演；`message` 按 role 细分单列。

## 3．反证分支（冻结）

- **M\* 在 ≥4/5 组主导**：H1 成立——0/5 的机制解释收窄为「R3 观测面混合模型生成内容；DSH S3 因定义排除该侧而稳定」，两侧不可横比的既有结论获得定量支撑；不改变任何门判定与分数。
- **E 在某组主导**：该组存在真实的环境/任务面输入漂移——逐型逐槽列出漂移事件与字节数，该组表述按「输入面不稳定」如实收窄，并作为后续批次观测设计的反例输入。
- **两族相当（均不过半或互相抵消）**：分列如实报告，不给单一机制解释。
- Δ ≤ 0 或槽位缺失/组数错 → 校验报错 exit 2。
