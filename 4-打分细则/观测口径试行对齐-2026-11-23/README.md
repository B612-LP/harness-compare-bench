# 观测口径试行对齐审读：DSH 0.2 × Codex responses 0.1

[第五周反馈条 1](<../../反馈/2026-11-18-第五轮/验收条款-公开版.md>)要求先有唯一观测规范。现状是两条流式线各有一份试行口径页：[DSH v4 试行 0.2](<../DSH观测口径校准-2026-11-19/README.md>)与[Codex responses 试行 0.1](<../CodexResponses观测口径-2026-11-23/README.md>)。两页独立成稿、并行演化，并读发现**同一套字母在两页间语义不同**。本页是对齐审读：零新运行、零模型/产品接触，逐格登记分叉并给出统一命名建议（草案）。两试行页原文不回改；升版另环。

## 层语义对照

| 层 | DSH 页（试行 0.2） | Codex 页（试行 0.1） | 判定 |
|---|---|---|---|
| L0 | 原件字节与 SHA-256；压缩差异留本层（页 L11） | 同为原件字节与 SHA-256；本样本响应为明文 SSE（页 L11） | **一致** |
| L1 | 事件账：zstd 帧接合、严格 NDJSON、`seq` 连续（页 L12） | SSE 事件账：两行帧、空行 dispatch、13 事件名白名单（页 L12） | 同为"本地事件账"，解析规则随格式分道——与私档统一协议 0.2 候选「共同判定规则，分格式解析」一致 |
| L2 | 分段/本地投影：turn/step 界定、内外引用对齐（页 L13） | **信封与条目门**：阶段帧身份/状态、条目不重复、delta 累计（页 L13） | **撞名**：同名异义 |
| W | 客户端捕获层：绑定的请求体/响应正文（页 L14） | **分组与承接**：call_id 连通分量×前缀双法（页 L14） | **撞名**：DSH 的 W 内容在 Codex 页由 L0+H（逐包双 SHA）承担 |
| H | 后续历史：带同一调用的首个主续请求（页 L14） | **逐包绑定**：请求/响应各自对照元数据摘要（页 L15） | **撞名** |

私档统一协议 0.2 候选（§层与段、§两个限界配置）把 L2 定义为"任务及局部语义"、W/H 定义为"两个限界配置（不是互通 SSE 解析器）"下的格式终止与关联——DSH 页沿用该语义；Codex 页把 L2/W/H 重用为流结构门/分组/双 SHA，偏离了共同基名。

## 发现分级

- **F1（撞名，须统一）**：链字母 A/B/C 跨页异义（证据链类型 vs 一致性检查链）。
- **F2（撞名，须统一）**：层字母 L2/W/H 跨页异义；Codex 页相对统一协议 0.2 候选的共同基名发生重用。
- **F3（实质，声明应加限定）**：Codex 页 L18 称字节规则与 DSH 页"相同"——键排序/无空白/保序/不归一/不删字段确为共享；但**数字子口径并未对齐**：DSH 页 L18 的数字按有界精确十进制处理（整数与小数/指数分型、保留正负零、去尾零系数唯一表示），R110 环实现（私档）用的是臂 JSON 实现的浮点渲染，两者对同一数值可产生不同规范字节。私档统一协议 0.2 候选 §字节口径与状态已明示："统一候选要求新数字 profile 单独定版并经真实格式及离线近错校准；两个旧 profile 数字尚不能直接比较"。R110 受影响的规范 JSON 计算面（工具声明投影/请求规范 SHA/run 指纹）输入侧样本请求零浮点（值均为字符串/布尔），结论数字不受影响；响应信封虽有浮点（如 temperature/top_p=1.0），但只进合成夹具与被丢弃的等值检查，不落规范字节结论。但"相同"二字按全规则读是过强声明。
- **F4（覆盖缺口，下版补）**：Codex 页反例无「真改不被等长掩盖」公开条目（DSH evidence 有对应对照组 `same_size_selected_user_change`）；私档统一协议 0.2 候选 §现有真格式对照记载 Codex 旧样本"等值重编码 277 B 和真实改值可以区分"——旧证据存在但未进 Codex 页反例节。
- **F5（承诺语句分账）**：三条关键承诺中两条两侧齐备——元数据不能单独认领正文（DSH 页 L14、Codex 页 L15）、受控第三方原件核验尚未完成（DSH 页 L45、Codex 页 L37）；第三条「W 不是服务端实际摄入/token/费用」**只在 DSH 页 L20，Codex 页全文未载**，建议升版补入。事件族与 G↔W 属格式差异，不必须统一。

## 统一命名建议（草案，不落实）

1. 证据链与检查链分前缀：E-（证据链：正例/失败/不可核）与 V-（检查链：分组/元数据/流门/逐包双 SHA/工具声明一致性门），或一律改语义名。
2. 层字母回锚共同基名：L0/L1 两页已一致；L2/W/H 回到统一协议 0.2 候选定义，Codex 的流结构门/分组/逐包绑定另配字母（如 S1–S3、P、D）。
3. 数字 profile 单独定版后再谈"规则相同"；升版页应写明本试行数字经臂 JSON 实现，与有界精确十进制 profile 不可直接比较。
4. Codex 反例节补「真改不被等长掩盖」条目（可引旧样本既有结论）。
