# DSH v4 日志观测口径：真实格式校准（试行 0.3）

## 问题

[第五周反馈第 1–3 条](<../../反馈/2026-11-18-第五轮/验收条款-公开版.md>)要求先分清真实内容变化、记录层差异与解析错误，再谈重复性和归因。本页给出 DSH v4 的同一试行口径，用已有正例、自然失败、不可核和一对自然运行检验。**只验收下述已知样本与指定端点，不冻结通用规范**；不把离线派生当新运行，也不追认[旧主门](<../机制重复口径澄清-2026-11-12/README.md>)（6 失败、4 不可核）。

## 观测与判定口径

| 层 | 输入与输出 | 准入与未知 |
|---|---|---|
| L0 原件 | 归档容器原始字节数和 SHA-256；压缩差异留在本层 | 文件、固定来源、长度或摘要不符则原件身份不可核；派生副本不能沿用原件承诺。 |
| L1 事件账 | 接合全部合法 zstd 数据帧，严格 UTF-8 NDJSON；首行 session v4，后按原物理次序取 `seq/time/type/data`，`seq` 从 0 连续递增。分别计解压物理字节、事件行数、逐行规范 JSON 的 UTF-8 字节和 | 不按时钟排序，不抹时间/ID，不忽略未解尾帧。空行、未知类型、非法 UTF-8、重复键、残行或超界则相应层不可核。 |
| L2 分段/本地投影 | 一对 `turn/start`、`turn/end` 界定 turn，内部按不重叠 `step/start`、`step/end` 分段；存在的显式标识须与活动段相符。标题请求另作 AUX，不进任务消息。控制内已知成功的 step 核对 assistant 完成、唯一同段调用与结果、内外引用 | 外层 ID 和结果 `sourceEventSeqs` 对齐仍不够，已知的内层来源也要对齐。遗漏、跨段、歧义不补齐；结构闭合不等于任务成功。 |
| W 客户端捕获；H 后续历史 | W 仅指绑定的客户端请求体/响应正文。SSE 依该格式的边界、choice/tool 索引拼接完整调用，H 只指带同一调用的首个主续请求。分别比较原始字节、严格 JSON 值和所选字段 | 捕获元数据、同工作样本和唯一 ID/段锚须成立；同名、同序号、同时间或同字节都不能单独认领。DSH 此例用 `finish_reason=tool_calls`、`[DONE]`，并核适用的本地响应 ID 及来源；不能套用到其他流式格式。 |

事件族：**I 输入**为 `user/message`、`request/header`、`request/context`、`system/message`、`agent/inbox/spliced`；**K 交互**为 `turn/start`、`turn/end`、`step/start`、`step/end`、`assistant/message`、`tool/call`、`tool/result`；**M 辅助**为 `session`、`session/title`、`permission/preset`、`sandbox/mode`、`approval/policy`、`session-log-deepseek/delivery-accepted`、`session/title-llm-request`、`subagent/catalog`、`session/end-seed`。分族类型序列、完整事件值和选定字段投影分开比较。

规范 JSON 计 UTF-8 字节：对象键按 Unicode 码点排序，无额外空白，数组保持次序，不做 Unicode 归一化，不删字段。逐行合计不含换行。数字按有界精确十进制处理，整数与小数/指数分型，保留正负零；小数/指数采用去尾零系数和十进制指数的唯一表示。跨实现等价已核（0.3）：本页数字口径与[数字口径定版候选 v1](<../数字口径定版候选-2026-11-23/README.md>)同语义，同一批 130 份冻结原档的全部 9,923 个 JSON 载荷在两套独立实现下规范字节逐字节相等；两套越界参数不同，见候选页边界与[冻结门清单](<../观测规范冻结门清单-2026-11-23/README.md>) G2。不把非有限数或孤立 surrogate 当合法值。LF/CRLF、对象键顺序、外层 JSON 空白、等值 Unicode 转义或不改解码内容的合法 zstd 重分帧可以改变物理字节，不应改变受检值。不擅自解析/归一化内嵌 `arguments` 字符串；若另核参数对象，原串与对象分账。

**裁定：**先验来源、完整性与唯一绑定，再比较内容；等长不等于等值，内容相等不能反过来认证身份。必需层不满足时只把涉及该层的结论置 `unknown`，已核实层保留，不填 0。W 不是网络全包、服务端实际输入、token、费用或实际思考量；自报 usage 不参与本页判定。

### 自然运行对：记录已不同，首请求仍可相同

[深链原始运行对](<../请求侧深链与轮间文本-2026-11-17/EXECUTION-RECORD.md>)不是单变量干预。两臂首 assistant 前的完整记录 18/18 行不同；有 `data` 的 17 行里 8 行不同。仅看 I 时，完整记录 9/9 不同，完整 `data` 6/9 不同、差异只在 ID 叶节点；两臂 I 的完整规范长度都为 39,887 B，I-`data` 都为 39,217 B。M 另有生成的标题文本差异：规范 JSON 字符串 51 / 29 B（含引号），因此不能把全部前段差异都叫 ID 或信封差异。

与此同一对运行的 **W001 两臂各 32,937 B 且原始字节完全相同**，标题辅助 W002 各 888 B 也完全相同；辅助捕获与任务在时间上可重叠，不能以编号当时间顺序。响应中第一个完整调用分叉成带缺参错误的 `bash` 与有声明必填字段、带非错误结果的 `read`；两臂各自复核响应、本地事件、后续历史，W003 分别 33,319 / 33,797 B。后者的 `read` 是日志可见工具行为，不是这里的 OS 读取真值。首条请求等字节不等于后续行为相同，也不能认证哪一臂；这两臂不是 Harness 因果证据。

## 反例与待验

- **等价表示不翻判。** E-pos 原事件换成 CRLF、改对象键序/Unicode 转义，或合法重压缩由 11 帧变 1 帧，原始载体可不同，事件值和所测投影不变；W JSON 同值重编码只保留值相同，不再通过原捕获字节承诺。
- **真改不被等长掩盖。** 在 E-pos 的离线副本等长改第二条用户消息：任务消息命中 8→7，标题投影不变。自然运行对也区分「L 已异/W 首条未异」和「以后确实分叉」。
- **错绑与缺失不冒充。** 已试错误标题面、缺/截帧、重复键、未知事件、同 ID 错工具名。非作者另发现：漏工具结果后重新编号、只错内层来源、漏第二个 assistant 完成，旧实现仍给出 L2；增补后均保留可解的 L1、L2 置空。E-nat 另两项——错内层调用 ID、整段 SSE 换成同运行另一响应 ID——初版漏受，增补均改判 unknown；真实原件结论不变。运行对的单块/整段响应错 ID、甩掉末尾重放锚、仅改标题 effort 等反例同原件分账。
- **仍不冻结。** E-nat 增补仅验收上述两项 ID 门；新增近错只把结果来源标签从 `tool` 改为 `model`，保留引用与内容，仍误收。运行对的增补也未拒绝一个近错：保留末尾重放锚内容，只把外层记录类型从 `chunk` 换成 `tool-call-chunks`。这些都是精确原件绑定之外的派生诊断，不会把改写副本认成原件。已知成功样本的局部结构门不能判终止原因或全部会话成功。原件结论与实现缺口分账，不用内部复核代替受控第三方。

### 11-23 订正：上段两个反例指旧门，已有原档范围内的补验

11-19 的后续内部非作者复验表明：**E-nat 的两个固定来源标签**在局部门由 0.2 到 0.3 后，原样判定不变，仅换结果标签 `tool`→`model`、助手标签 `model`→`tool`，以及缺失、错类型等共 12 个离线对照均退为来源绑定不可核。合法 JSON 转义另有 2 个对照，只改载体字节，解码值和裁定不变。结果标签的替换与旧门漏收的派生字节相同。原自然失败依旧是最早可见响应已缺当次必填 `command`；更早的模型意图不可核。

在**自然运行对的两个固定末尾重放锚**上，局部门由 0.2 到 0.3 后，原样 2/2 不变；只改末尾外层 `chunk`→`tool-call-chunks` 的精确对照 2/2 判结构绑定不可核，加上缺失或非字符串共 6/6 判不可核。参数值可保持相同，不能代替末尾来源绑定。仅改较早非末尾类型不在补门范围内；捕获头也不由此核验。

此次订正对账的是既有复核回执，未重跑产品或重投影原件。订正前正文与原派生表保留旧门结果。局部补验不冻结通用规范、不替代受控第三方核验，不改变历史结论或分数。
