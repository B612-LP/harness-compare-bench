# 数字口径定版候选 v1：同一原件的字节规范形（试行，不冻结）

2026-11-23。本页是[观测口径试行对齐](<../观测口径试行对齐-2026-11-23/README.md>)发现的数字口径缺口（其发现 F3：两试行页对"同一数字如何进字节"没有共同答案）的定向闭环：把跨线共用的数字字节规范形（number profile v1）定版并经原档校准。它仍是**试行候选，不冻结**；冻结另环。

## 问题

同一份响应原件，两次"规范化"得到的字节可以不同：`4000` 与 `4e3` 数值相同、字节不同；`1.50` 与 `1.5` 同理；`-0` 与 `0` 符号有无决定字节。若换人重算时渲染规则未定，"同一原件"的复算就对不上。此前两试行页各用各的：[Codex 页](<../CodexResponses观测口径-2026-11-23/README.md>)实现沿用臂 JSON 的浮点渲染，[DSH 页](<../DSH观测口径校准-2026-11-19/README.md>)声明有界精确十进制但数字 profile 未单独定版。

## 规范形 v1（字节层）

| 输入形态 | 规则 | 例 |
| --- | --- | --- |
| 整数 | 原样保留（任意精度通路，不经 float）；`-0` 保留符号 | `256000`→`256000`，`-0`→`-0` |
| 小数/指数 | 系数去尾零，指数改十进制记法 `[sign]coeff e E'`；零（含 `-0.0`）→ `[sign]0e0` | `1.50`→`15e-1`，`0.005`→`5e-3`，`0.0`→`0e0`，`-0.0`→`-0e0`，`4.0e2`→`4e2` |
| 越界 | 系数 >4096 位或指数出 `[−6144, 6144]` → 拒，记 `unknown_number_out_of_bounds` | — |

其余沿用两页既有规则：键按码点排序、无空白、数组保序、不做 Unicode 归一化、不删字段；字符串渲染 `ensure_ascii=False`。NaN/Inf 不可达（解析即拒）。

## 校准与证据

固定输入=四族冻结原档 130 文档（R38/R52/R53/R77 的 65 请求正文 + 65 响应流、合计 9,858 个响应 data 行；各 bin SHA 在环封印内）。结果：

- 数字 token 真值计数（解析回调计数，字符串值不计）：整数 **22,054**、小数 **144**（字面量仅 `0.0`/`1.0`）、指数 **0**；无一越界。
- 130 文档全量规范化两遍逐字节一致；规范化后再解析回读，数值等值（`15e-1`↔`1.5`），`-0` 符号保真。
- 负控六条：等值重编码同形/异形、±0 符号、整数↔小数异形、指数归一同形与翻转、键序重排不改字节、值内数字形字符串改值可见——全部按预期。
- 计数方法透明：探针期 regex 法曾把数字形字符串值误计入整数（23,228），定版计数改解析回调真值法（22,054）；两种方法对小数（144）与指数（0）一致。

完整向量表、负控与修订留痕由环目录与 git 历史承载，不随公开页展开；本页公开面只保留上表与计数。

## 它不能说明什么

1. 位数不是 token 数，不是费用，也不是服务端实际摄入——本 profile 只定义换人复算时的字节规范形。
2. 不宣称 DSH 或 Codex 任一产品已按此渲染；两试行公开页文字不改（Codex 页升版时才采用本 profile）。
3. 不冻结：冻结需跨线等值表示对照扩展与更多原档族。
4. 原档均为冻结批，本环零新发射；样本限于四族，不外推其他批次或产品。
