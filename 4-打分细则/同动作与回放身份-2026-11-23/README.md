# 同样的工具动作，不能识别是哪条响应被带入历史（11-23）

固定此前六对、共 **12** 份 DSH 归档，每对的首请求字节相等。内容比对只用各自首响应和首次续请求，不读第二响应。12/12 个首响应的工具名和严格参数都相同；仅凭这一动作比对任一续请求，12 个首响应全合格为等值候选。有序可见文本也不能保证唯一：12 个目标中仅 1 个唯一、2 个各有 2 个候选、9 个各有 9 个候选。

在此固定范围内，逐个比较工具标识或不透明签名值，12 个续请求各有一个对应首响应；再核末尾助手项、唯一有序的调用/工具结果及该次归档资格，原档 12/12 通过档案内完整附着核对。同值只影响**有限候选数**，不替代封定捕获与自己那一槽的位置和结果关系。没有解码、哈希或发布单个不透明字段。

离线把另一臂的整个助手承载与兼容的结果引用一同换入，可得到唯一但**指向另一臂**的候选；同时换调用和结果的标识，或仅换签名，仍可维持内部调用与结果关系，却不能完整附着到本槽首响应；仅换结果引用则破坏内部标识闭合。缺少或重复结果时，助手候选仍可见，但不能核完整承接。新增独审反例进一步确认：字段形态一样不等于值相等，同槽的路由/时序诊断不能补写请求回执，回执也不能抹去时序矛盾。

这不是第二次执行、真实工具执行或服务端接收的证明。结论限原六对，内部非作者复投影不充当外部原件核验，不改旧判定与双线冻结状态。参见[相同首请求的响应复核](../../5-评测报告/等首请求的处理前响应-2026-11-23/README.md)。
