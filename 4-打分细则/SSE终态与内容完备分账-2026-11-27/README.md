# SSE 正常终态不等于内容齐全

对[请求原字节扩展](<../wire请求面扩展-2026-11-27/README.md>)所用的同一批 29 份既有客户端响应重新分帧：21 份 Chat、8 份 Responses，6 份为 gzip。29/29 通过下述有限终态门，1540 段 JSON payload 与前次派生逐字节相同；另有 21 个 Chat `[DONE]`，合计 1561 个实际派发的数据帧。**相同的 payload 和正常终态，都不能证明原流没有缺少中间内容。**

## 1. 先判物理边界，再判终态

- 物理边界只认 CR、LF、CRLF，空行派发；同块多个 `data` 字段去掉冒号后的至多一个 ASCII 空格，再用 LF 拼合。EOF 未见空行的数据不冒充已派发帧，保留可证的先前派发。Unicode 行隔符不当作物理换行。
- Chat 要有唯一且位于数据末尾的 `[DONE]`，此前至少一个 choice 的 `finish_reason` 为非空字符串。不绑定所有 chunk 的 ID，也不认证每个 choice 都结束。
- Responses 的显式 event 标签须等于 JSON 对象的 `type`；最后一个数据帧须是唯一 `response.completed`，内层响应 `status=completed`、有非空 ID；可见响应信封 ID 不冲突，不接受相竞争的失败/取消/不完整终态。这不绑定所有 delta 的顶层 ID，也不要求已看见完整生命周期。终态后可有不派发数据的注释等，不等于终态后绝无字节。
- 检测真实空行派发后，29 份的 1540 个 JSON payload 均与前次逐字节相同。原实现只剥一个起始 BOM，却可漏掉紧接着的第二枚：第二枚在注释行前时会被当成未知字段跳过，两族都有反例。修订版最多剥一枚，连续多枚单列 `REPEATED_INITIAL_BOM`；原 29 份起始 BOM 均为零，不改历史抽取结果。此处是有限门的约束，不声明所有供应商语法都如此。

本页只做事件分帧和终态见证，不导出或认证 JSON 的数值语义；JSON 词型和数字规范另见[精确数字与字符串域隔离](<../精确数字与字符串域隔离-2026-11-27/README.md>)。

## 2. 每次从原响应删除一个实际派发的数据帧

删项实验只纳入这批真实流中已核实的单 `data` 派发块，按解压后的 SSE 正文连续区间删除一个整块，不重新压缩 gzip。除 Responses 的第二阶段单独重编外，保留字节不动。重编只替换顶层序号的数字词面，不回填任何事件。这里是同源反事实，不是 1561 次独立运行，也不估现实丢包率。

| 删项来源 | 派生数 | 有限闭合 | 原可见序号 |
| --- | ---: | --- | --- |
| Chat | 546 | 504 仍闭合；42 拒绝（21 删终止标记、21 删唯一 finish 帧） | 不适用，不记成零或通过 |
| Responses | 1015 | 1007 个内部删除仍闭合；8 个末尾删除拒绝 | 1007 个内部删除均有断点；8 个末尾删除仍连续 |

- Chat 的 504 个仍闭合派生中，删块各有 103 个含非空可见正文、391 个含非空工具参数片段、14 个含非空工具名称；这些字段类别可重叠，不相加作分母。保留的 `[DONE]` 无法证明被删块内容或用量仍相同。
- Responses 单独重编后，1015 个派生的序号检查均过；删末帧的八个仍无正常终态。就 **1007 个仍闭合的内部删项** 而言，923 个非空文本片段删除破坏重组片段与专门完成副本的吻合（563 工具参数、335 推理文本、25 可见正文）；16 个删去专门完成副本，失去该见证；16 个删去 `output_item.done`，完成信封里仍有对应对象；剩余 52 个在这些有限检查上均未见异常（8 created、8 in_progress、16 item.added、10 part.added、10 part.done）。四类在此数据上互斥归类，不表示所有协议流都具备这种划分。
- 保留原件期望 SHA 时，1561 个删项的原件同一性均被否定；这只在原期望值及其对象绑定可靠时成立。同一个响应中的多个副本不是独立来源；缺一份副本是不可比较，不是自动相同。剩余 52 个也不是生命周期完整。

## 3. 可公开复算的正反对照

只需 Python 3.9 或更高版本，不联网或运行任何记录内代码。从本目录运行：

```sh
python3 -B test_sse.py
python3 -B demo.py
```

[终态门](<sse.py>)和[19 项分帧与终态测试](<test_sse.py>)包括双起始 BOM、未派发尾部、帧后数据、失去 finish、两族格式等。独立的小型[合成演示](<demo.py>)检查七个期望：删末帧可保持连续序号却失去终态；删正文分片后重编可恢复序号而不能恢复文字；删 created 后四个内部门均可通过，却不是已知原件。删专门 done 或中间 item 副本分别得到未知。演示固定一个合成条目，并非通用提供方客户端或私档回源程序。

以上 29 份真实统计是内部从锁定捕获复核后的许可范围派生；公开测试只复算合成对照，不公开原件，也不冒充受控第三方。仍不认证服务端完整性、客户端实际摄入、跨产品因果、分数或冻结规范。旧失败与不可核留在原账。
