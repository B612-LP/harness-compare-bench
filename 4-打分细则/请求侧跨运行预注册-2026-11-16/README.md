## 3. 主要指标（estimands）与判定

1. **比较单元**：请求体原始字节（UTF-8，不含 header/framing）。字节不恒等时先做 JSON 规范化复比：规范化后恒等的差异单列为 **d 类（序列化层差异）**，不影响 H-stable 判定，逐例报告；仍不恒等的才进入差异键清单。
2. **H-stable 三分结局（仅同模型运行可判）**：
   - ① req1 与 capture-1 req1 逐字节恒等 → 支持跨 run 输入组装稳定；
   - ② 不恒等但全部差异键归入 a/b 且证据合格 → 记「组装稳定但含请求时生成字段」，逐键列值与归类证据，不算支持也不算拒绝；
   - ③ 存在 c 类键（含 d 类复比后仍不恒等且无类可归）→ 拒绝。
   - 三种结局在报告中分列，不得混写为「基本稳定」。仅存 d 类差异（规范化后恒等）时按结局①处理，明细逐例报告。
3. **差键分类（先列差异、后分类）**：
   - a) 请求时生成的注入文本（事件层有 source 元数据，由 run 2 自己的溯源映射证明）；
   - b) 请求时生成的动态字段。其「复现证据」限于以下**不需新模型运行**的方式，执行前冻结：①同一 run 内该键在 ≥2 个请求中出现且值不同（证明值随请求生成，非运行级常量）；②该键值与单调时钟/计数器/会话 ID 的函数关系可由本 run 元数据核验；③事件层或 harness 配置中该键的生成路径引用（文件/字段级，不复制正文）。仅「两次运行值不同」本身不构成 b 类证据。
   - c) 无法归类 → 按 H-stable 拒绝处理，**不得**以「预期内漂移」名义放行。
4. **基于 capture-1 先验的预判（冻结内容，执行结果与此不一致时如实分列，不回改预判）**：capture-1 req1 五条消息均已逐字节溯源到事件层静态文本/配置，req1 体内未见时间戳/会话 ID/runtime 变量字段；主要不确定性为 22 个工具声明的数组顺序与内容是否跨 run 确定性（来源为配置事件，预判稳定）。req3 追加的 assistant 消息含模型生成的 tool_calls id，跨 run 必然不同——因此 req3 侧只比较追加的 tool 消息正文与结构，assistant 追加行不做内容级比较。req3 比较为 R-A 的附带描述性检查：结果单列报告、不改变上方三分结局；tool 消息正文按原始字节比较、结构逐字段；tool_calls id 跨 run 不同属本预判内预期差异，不进差异键清单。
5. **R-B 复核**：Q1 前缀扩展在其每个请求对上成立且 Q2 零标记 → 与 capture-1 一致；任一出现截断/重组标记 → 立即推翻「append-only 无截断」的跨 run 外推，如实更新报告。
6. **字节 vs usage 分列**（Q3）：沿用[首条产品计数等值复核](<../首条产品计数等值复核-2026-11-16/README.md>)的口径——product-reported 计数不认证 provider/实际思考/缓存，请求字节单独报告。
7. **结论范围措辞**：「截至当前的全部运行对（含 capture-1）」，不写死「两次」。

## 4. 反证分支与失败处置

- 结局③（c 类差异）→ H-stable 拒绝：结论写「跨 run 输入组装不稳定」，保留全部差异证据；不增加重复次数替代机制解释。
- 结局② → 如实记录分类明细，capture-1 与本页不因结局②改写任何「稳定」表述。
- 出现截断/重组标记 → 在报告相应节从「未观察到」改为如实记录，并回溯检查 capture-1 是否存在同类漏检可能。
- 「R-A 恒等/结局② 但 R-B 出现标记」的组合如实分列：组装稳定与无截断是两个独立命题。
- 运行失败/基础设施事故 → 记入执行记录已知差异，与 capture-1 同口径；0 请求的失败按 §2 重试规则处理。
