## 1. 研究问题与旧结论的差异

本研究问：**同次原始SSE工具调用的参数是否已缺少顶层`command`，还是该差异出现在SSE到本地调用/后续请求历史的链上？**它检验旧报告“模型首轮误调bash”这句归因，不重判仅追加、13/13对齐、旧门或任何成绩。

先验：请求侧缺参、错误文案、错误对驻留与跨run对齐结果已知；采集meta与文件清单已读；**目标001.response.bin的SSE工具参数未读**。因此是已知请求侧结果下的新端点预声明，不宣称全程盲预测。

## 3. 冻结解析与关联规则

### G0：原档绑定门

1. 请求/响应实际长度与SHA须与固定锚、meta互相硬等；status200；请求必须为主任务而非标题请求。请求字段/schema与后续历史格式须通过严格JSON解析。
2. 同编号请求与响应以meta中的seq、request_body_sha256和response_body_sha256共同关联；不是按相邻文件或时间接近猜测。事件日志另留实际SHA与序号/调用id关联；当前版本字样不认证历史runtime。
3. 同一目标调用在各层必须唯一；不以“都是bash”、近似参数或跨run调用id代替同次关联。无法唯一绑定进入UNKNOWN_BINDING，不拣一个可用匹配。

### G1：SSE重建门

- 严格UTF-8；按SSE空行分帧并合并同帧data行，允许标准注释与CRLF；JSON拒重复键、NaN/Infinity/溢出非有限数。不是用字符串搜`command`或只读最后一个含字段行。
- 按choice index与tool_call index依线序重建；function.arguments只拼接协议声明的字符串片段，function.name同样按片段顺序重建；调用id取首个非空值，后续重复须一致。保留片段序号、字节数和SHA以供独审，不公开正文。
- 目标调用须有目标choice的`finish_reason="tool_calls"`完成终态，随后有`data: [DONE]`，其后不得再有JSON数据帧。仅HTTP EOF不作完整性证明。重复/相冲突的终态、缺终态、截断片段或不支持的delta类型均不可当作“缺command”。
- 拼接后arguments必须为可严格解析的单个JSON对象；不递归猜解多重JSON字符串，不从自然语言中补参数。若出现字段别名、大小写异形、嵌套command或非标准参数载体，记录该形状并进入UNKNOWN_SHAPE，不临时扩词表。

### G2：三层关联与比较门

- W = 001响应中唯一绑定目标bash调用的重建参数对象。
- L = 同次本地tool/call的实际参数对象（事件层存在且能唯一绑定时）；只解析日志，不执行。
- H = 最早后续主请求历史中同一调用的assistant.tool_calls参数对象；对应tool结果须以同次tool_call_id绑定到旧错误对。保存该H请求的实际SHA。
- 逐层登记：`command`顶层键是否存在、值是否为字符串及是否符合当次请求中bash工具的声明schema；同时比较**整个参数对象**的canonical值，不只比较该字段。JSON对象键排序差异不计值差，但原始参数串SHA单列。canonical一致不声称原始序列化字节一致。
- L若缺失/不唯一，W↔H仍可登记已绑定对象的字段差，但不得声称定位具体适配器/工具模块；三层保真结论记UNKNOWN_BINDING。W/H本身不唯一则主归因也UNKNOWN_BINDING。

## 4. 主要终点与固定分支

E1：目标W/H能否完整、唯一重建，以及两端是否具有声明要求的顶层`command`。E2：W→L→H整个参数对象逐值保真性与可定位区间。**“args为完整JSON”与“包含合法command”是两件事；完整`{}`仍是缺参。**

| W（SSE） | H（后续历史） | 归因结局与允许措辞 |
|---|---|---|
| 顶层command缺失，参数为完整JSON对象 | 同样缺失，且整个对象canonical相等 | `SOURCE_MISSING_PRESERVED`：缺参已见于捕获的上游响应，未在所见W→H链新引入；L也同值时三层证据闭合。维持旧“源头缺参”的解释并提升观测层级；不认证模型内部意图或provider生成者身份 |
| 含符合声明schema的command | 顶层command缺失 | `COMMAND_LOST_IN_CHAIN`：字段在W→H区间丢失，改写旧“模型误调缺command”归因；有L时再区分W→L或L→H，不能只凭时间猜模块 |
| 顶层command缺失 | 含command | `COMMAND_ADDED_IN_CHAIN`：字段被补入/改写，**不是丢失**；若它与旧历史缺参事实矛盾，公开该绑定矛盾，不强维持原归因 |
| 两端均含合法command且整个对象同值 | 两端同值 | `MISSING_NOT_REPRODUCED`：本端点未复现旧“缺字段”事实；核对唯一目标/错误对关联，不能宣称模型缺参；不因已有错误文本而覆盖实测 |
| 两端均含command但值非法且整个对象同值 | 两端同值 | `SOURCE_INVALID_VALUE_PRESERVED`：是上游可见非法值，不是缺字段；按请求schema说明，改写缺参措辞，不把null/数字/空串一律当缺字段 |
| 两端其他字段或command值不同，未落上列 | 任意 | `ARGUMENT_CHANGED_IN_CHAIN`：只报告整个对象变化及首个可定位区间；与实际缺参错误的因果关系不作认证 |

以下UNKNOWN优先于任何实质归因，不用零值或“字段缺失”代填：

1. `UNKNOWN_STREAM`：正文解码、帧/JSON重建、完整终态或参数闭合失败；可能是截断/丢帧，不能记源头缺参。
2. `UNKNOWN_BINDING`：SHA/seq/目标调用/错误对不能唯一绑定，或三层中必要层缺失；必要层的未知范围分别登记。W/H可比较而L不可得时，只给区间级观察、不认证三层闭合。
3. `UNKNOWN_SHAPE`：字段异形/嵌套、多重编码、参数非对象或delta协议不在预声明内；不能在见结果后增加同义字段规则。

如果W完整但不含目标bash调用，记录“目标未定位”并归UNKNOWN_BINDING，不因`command`搜索零命中记SOURCE_MISSING。

## 5. 如何改变原报告

- `SOURCE_MISSING_PRESERVED`且三层闭合：把“根据后续历史推断模型缺参”提升为“同次捕获SSE已缺、DSH调用与后续历史逐值保持”；模型内部、provider真实性仍未知。
- `COMMAND_LOST_IN_CHAIN`：撤下该例“模型侧缺参”句，换成链内字段丢失，按L有无仅定位可证区间；不改仅追加/永久携带事实。
- `COMMAND_ADDED_IN_CHAIN`、`MISSING_NOT_REPRODUCED`或非法值分支：据实修正旧例的缺参表述与关联，不为保旧结论重配目标。
- UNKNOWN：保留“请求历史与错误返回中观察到缺参”，将来源归因标为未认证；研究未回答不充作通过。
