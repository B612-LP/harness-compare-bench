# 五个首请求逐字节相同，仍能分别对回会话吗？（2026-11-29）

**在这五份固定旧档里，可以用响应和工具承接对回会话；不能仅凭相同首包或闭集淘汰，认证孤立文件的来源。** [旧复核](<../续请求无法复原首响应-2026-11-23/README.md>)已证明相同首请求可得到不同响应形状，归一化后的后续历史不能复原原始响应。本页新增的是五份本地会话与五套客户端捕获的全交叉对照，以及删掉归属证据后的判定边界。

## 1. 哪些信息能筛掉错配

固定五套既有 DSH 捕获，各取首主请求、标题请求、首主续请求及其响应，并取各自的 v4 会话副本。[较早双体账](<../请求侧计数与缓存抖动-2026-11-17/evidence.json>)支持 15/15 对原体；[较晚逐槽旁证](<../捕获旁证与内容归属-2026-11-27/README.md>)所在范围只重叠 12 对，不给第二套补旁证。两份账及目录仅用于选择、校验和标明旧档的基准配对；下面的匹配规则不用文件名、槽号或时间相近作为归属依据。单一捕获链的既有承诺也不是第二套独立测量。

| 拿一份本地会话与一套捕获比较 | 基准配对（5 格） | 交叉配对（20 格） |
| --- | ---: | ---: |
| 首主已选消息、标题请求的已选投影、首续的已选前缀 | 5 相合 | 20 相合 |
| 忽略工具标识，仅看工具名及参数、结果值 | 5 相合 | 20 相合 |
| 首主的共享响应键；首批有序调用；首续有序调用及逐 ID 归属的结果；末主的共享响应键（分别计） | 各 5 相合 | 各 20 不符 |
| 与本地后出标题逐字相合 | 5 相合 | 20 不符 |
| 标题响应有可与本地直接对上的共享响应键 | 5 不可核 | 20 不可核 |
| 末主文本相同 | 5 相合 | 8 相合，12 不同 |

共享响应键是本地助手回放中记录的响应标识，不是本地助手消息的标识；首组两条调用的本地结果也要能对上来源事件与首续的同一调用。闭合流须先成立。标题文字在这批能辨开五份，但不补直接键；复制一个正确标题仍可与主链冲突。反过来，响应键相符不能替代结果值：保留调用和响应键、仅替换该调用的结果，结果比较仍应拒绝。只改变工具**结果**的排列时，逐 ID 的结果归属与是否保留列表原序应分报；真正改变工具**调用**顺序不算同一有序组。

## 2. 唯一剩下，不等于有本行正证

先假定池内恰好这五套、每套和每条本地会话各用一次。两项遮盖对照中，被遮行只保留跨档相同的首主与标题请求的已选输入投影；其余辨别证据（包括后出的标题文字和末响应）都不参与该行判定。未知不算正证；「可行分配」是在该假设下没有被已知冲突排除的完整一一匹配。

| 对照 | 每条被遮会话的本行正证 / 池内候选 | 可行分配数 |
| --- | ---: | ---: |
| 材料齐 | 每条 1 / 1 | 1 |
| 遮 1 行 | 0 / 5 | 1 |
| 遮 2 行 | 各 0 / 5 | 2 |
| 一行与池内五套均有明确冲突（不遮） | 0 / 0 | 0 |

遮一行时的唯一解来自其余四条已占的候选，不是被遮会话本身有证。非作者在该情形加一个未被排除的池外候选后，被遮会话就有两个选项；无损复制一套捕获的三对请求／响应，也能产生两个内容和跨层信号相同的候选实例。只撤掉首续的历史投影而仍保留末响应，与整对续请求和响应都缺失也不同：后者不能保留本地与末响应的共享键比较。**观察到一致的跨层关系，只证这些面之间的相容归属；它不把一个相同字节的散件或复制件认证为历史原件。** 要认证物理实例，还需要可追溯的先存保管或逐件记录。

以上 25 格是五份档案的重复交叉检查，不是 25 次运行。项目内非作者以另一实现从原件复算；附加的流信封改写、结果来源字段冲突等合成近错暴露投影器支持范围，固定五档未出现这些近错，因此不能把结果扩大为通用鉴定规则。合成拆链、移槽与复制不是新运行，不认证上游接收或生成方，不替代受控外部第三方，也不改旧盲验错绑门、冻结件或历史成绩。参见[历史位置与终态复核](<../盲验错绑与终态覆盖复核-2026-11-28/README.md>)及[部分历史凭据的覆盖边界](<../部分历史凭据的错绑检出-2026-11-29/README.md>)。
