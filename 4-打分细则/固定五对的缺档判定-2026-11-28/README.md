# 固定五对的字节比较：缺档时删对会改变判定

五对已经固定，哪怕只缺一臂的同事实端点，也不能用剩下四对的中位数替代。在这份历史账的遮蔽复算里，只遮一对时，无论只遮 A、只遮 B 还是两侧皆遮，各有 **36/240** 种遮法，使「删整对」判到与揭遮后五对不同的阈带；遮两对时各为 **144/480**。这些是同一批便于复核的历史场景的人为遮蔽结果，不是实测缺档比例。

## 用什么衡量

沿[外溢字节端点复核](<../外溢字节端点敏感性-2026-11-28/README.md>)和[公开逐包账](<../端点支持与请求字节-2026-11-23/evidence.json>)：E2 是同一完整校验值首次由合格的新绑定工具结果进入主请求的位置，统计到这个请求为止的累计客户端正文字节，排除标题请求。A 是内联侧，B 是初回包短侧；不是正式评分轨。每对用 `B/A`，固定五对的中位数为第三顺位。低带 `<0.90`，中带 `0.90–1.10`（含边界），高带 `>1.10`；中带不是统计等效。

三组的 14 条比较边涉及 14 个历史场景。每套五对内部不共享运行，但 48 套之间复用原场景，不能当作 48 次试验。原账均有 E2，48 套基线判带为低 / 中 / 高 = **0 / 12 / 36**。对每套遮一个或两个配对，每案统一只遮 A、只遮 B 或两侧全遮。从每个被遮臂的 E2 包起隐藏其后缀，不用当时之后可见的包兜底；标题不计入前缀。遮一有 48 × 5 个位置，遮二有 48 × 10 个位置，不混合不同遮蔽侧型。

## 不删对时能判断什么

**实际数值与条件判带分开。** 只知道一个通过归属核对、尚未达到 E2 的主请求前缀 `p`，而**且假定同一次尝试后来确实由一个新的正确绑定主请求交付该事实**，累计量才满足 `T ≥ p+1`。`+1` 仅来自新请求正文大于零的保守下界，不是协议允许的实际包长。没有可证累计上限时不填上界；被遮住的实际数值不参与计算。若完整记录证明该臂已终止且事实未送达，比值未定义；若只是缺档，则实际值未知。两者都不填 0 或无穷，也不拿另一场补位。

对于每对的正累计量区间，`B/A` 的下、上界分别为 `B_min/A_max` 和 `B_max/A_min`；分母无有限上界给出下确界 0，分子无有限上界给出无穷上界。因中位数对每个坐标单调，五个下界、五个上界分别取第三顺位。**整段落在同一阈带**才给条件判带。若各臂补全集合确为独立区间，这两界是可行中位数的上下缘；现实协议的联动约束可能收紧，两界不表示中间每个数值都可达。即使条件带唯一，只要有受遮臂，表中的**实际五对中位仍未观察到**。

| 遮几对 | 遮哪侧 | 案例数 | 条件低 / 中 / 高 / 未识别 | 删整对与揭遮后的固定五对不同带 | 条件未识别但删对报高 |
| ---: | :---: | ---: | :--- | ---: | ---: |
| 1 | A | 240 | 0 / 24 / 72 / 144 | 36 | 144 |
| 1 | B | 240 | 0 / 24 / 84 / 132 | 36 | 132 |
| 1 | 两侧 | 240 | 0 / 24 / 72 / 144 | 36 | 144 |
| 2 | A | 480 | 0 / 12 / 36 / 432 | 144 | 252 |
| 2 | B | 480 | 0 / 12 / 60 / 408 | 144 | 228 |
| 2 | 两侧 | 480 | 0 / 12 / 36 / 432 | 144 | 252 |

两列错判诊断有重叠，不相加。删一对后按剩余四对的中间两值取平均，删二对后按剩余三对取第二顺位；这是有意计算另一个量。已识别的条件带在这些重放里均不与揭遮后的完整结果冲突。以公开账从 1 起编号的第 1、5、9、11、14 边为例：仅遮第 1 边 A 侧时，条件界 `[136649/127293, 67315/49118]` 跨中／高带。删整对会报约 `1.2220`（高），揭遮后的五对为 `136649/127293`（中）。

## 两个会改变结论的反例

- **有关联的预算不能拆成互不相关的上限。** 三个完整比值 `0.8, 1, 1.2`；其余两对的 A 均为 `100`，B 的有效前缀均为 `100`。无上限的条件界为 `[1.01, 1.20]`。若另有同层的可证累计上限 `B₄+B₅≤220`，两个各自的边际上限 `119` 仍给出跨带的 `[1.01, 1.19]`；190 个满足联合预算的整数组合则只到 `1.10`，因为要进入高带两者都需至少 `111`。该预算是合成对照，不是历史约束，也不能从单包上限推出。
- **错绑前缀不是保守估计。** 四个完整比值 `0.8, 1, 1.2, 1.25`；第五对 `A=100`，合法 B 前缀 `90`。正确界 `[1, 1.2]` 不定带，合法补全可得中位 `1`。换接别场的 `110` 字节前缀，会误得 `[1.11, 1.2]` 而报高。请求必须先有有效的运行、角色及同对象新结果归属，不能只凭全文搜值或捕获编号。

**复核。** 在仓库根用 Python 3.9+ 运行 `python3 -B '4-打分细则/固定五对的缺档判定-2026-11-28/verify.py'`。脚本只使用已钉定且已有 E2 标签的公开账，复算累计量、遮蔽、判带及两个合成反例；不认证新场的端点与前缀。聚合及代表见证由项目内非作者独立复算，不是外部第三方核验。这只支持以后把缺档、确证未达、实际已达和条件界分账；不能作为 M1 放行、成本或 token 结论，不估未来达成或缺档率，不改观察规范、历史成绩和正式评分。
