# Harness 竞品评测

课题：独立设计并产出一套 Harness 竞品评测报告，比较对象为 **Codex、WorkBuddy、DSH、元宝专家模式、豆包办公**。

**当前进度 = 方法验证阶段（CLI 赛道）**：本仓已用 Codex / DSH 两款有 CLI 的产品，把「出题 → 闸门 → 判卷 → 取证 → 归因」整条链路跑通，这属于学习方法与验证流程的部分，**不是最终横向评测**。公告要求的正式评测对象是五款桌面端，其中 WorkBuddy、元宝、豆包无 CLI，评测与取证方式（GUI 手工执行 + 录屏 + 提示词留档 + 产物判卷）仍在设计中；本仓当前不含桌面端数据，阶段报告按此边界撰写并明示局限。

## 贯穿原则：归因定责

公告「注意」项：必须说明 **模型 / SKILL / Harness** 三层如何归因定责，确保评测主体是 Harness。设计见 [`4-打分细则/归因定责.md`](4-打分细则/归因定责.md)；落地手段是 A 组同模型对照 + C 组裸模型基线，差值即脚手架贡献。
