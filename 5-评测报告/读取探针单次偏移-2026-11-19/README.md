# 增加文件偏移，也不能仅凭这次 FD 快照辨认内容读取（2026-11-19）

## 结论

在一次事前固定的本机普通文件对照中，四个同一非 root 用户的自有进程各自打开同一个普通文件，且有共同的持有时间窗。一次限定在这四个进程及目标描述符的 `lsof` 采样，报告的偏移为 **0、0、512、512 字节**。0 和 512 两组都同时包含一个真实读和一个没有读内容的进程。因此，就本夹具而言，即使匹配了同一对象、同一持有窗，再加入该次快照的偏移也**不是内容读取的充分判据**。结论依赖的是有独立真值的两种冲突，不是估算一个错误率。

| 同窗臂 | 针对目标的动作 | 独立内容真值 | 原生偏移：动作前 → 后 → 关前 | `lsof` 偏移 |
|---|---|---|---|---|
| A | `os.pread(fd, 512, 0)` 一次 | 实际返回 512 B | 0 → 0 → 0 | **0** |
| B | 仅打开；不读、不改变偏移 | 无内容读取 | 0 → 0 → 0 | **0** |
| C | `os.lseek(fd, 512, SEEK_SET)` 一次，返回 512；不读 | 无内容读取 | 0 → 512 → 512 | **512** |
| D | `os.read(fd, 512)` 一次 | 实际返回 512 B | 0 → 512 → 512 | **512** |

A、D 返回字节的 SHA-256 都是 `110009dcee21620b166f3abfecb5eff7a873be729d1c2d53822e7acc5f34eb9b`，与预定 1024 B 合成内容的前 512 B 一致。C 移到文件中间，不是 EOF；B、C 不调用目标文件内容访问。四臂都用 `SEEK_CUR` 的零位移查询原生位置，使用同样的只读打开、对象元数据检查及关前确认。`pread` 返回字节但不移动该描述符的位置；`lseek` 可以移动位置而不返回内容。从偏移零断言「没读」和从偏移非零断言「读了」，都在本对照中失败。

## 同对象、同窗如何证实

父进程生成不含用户数据的普通文件；独立子进程分别新开目标而不共享打开文件描述。创建后元数据、每臂打开后及关前的 `fstat`，与采样行的普通文件类型、设备和 inode 对账；采样 PID/FD 精确绑定实例。相位事前固定：从共享单调时钟基准 T 起，+100 ms 开、+260 ms 动作、+420 ms 启动一次采样、+900 ms 关闭；各相位的指定标记向后容差 35 ms，采样命令全包络最长 250 ms。先收齐四个 ready，再由父进程选择并发送同一个 T。

实际四臂共同确认持有窗 **[+110.413, +901.441] ms**。四个动作全部发生在该窗内，最晚完成 **+267.833 ms**。从启动前标记到回收输出后标记，`lsof` 的完整包络 **[+430.116, +467.734] ms**；它完整落在动作已完成、任一关前检查尚未开始的共同持有期内。采样退出码为 0、stderr 空，四臂都提供精确身份和 `o` 字段；不猜命令内部的瞬时取样点，也不声称四行原子采集。四个自有 worker 和采样进程均已回收，合成文件已清理；唯一预定试次，无补发。

实际内容由 worker 调用返回值独立定真值；偏移的外部证据只取 `lsof -o` 的结构化 `o` 字段，不用 worker 的偏移代填。若对象、窗口、真值或外部字段缺失、类型不明或相冲，按预定规则记 `unknown`；不能记录为没有读。

## 可复核材料与边界

- [匿名派生](evidence.json)：只保留相对单调时戳、四臂操作/真值、偏移、受控对账布尔和源摘要，不包含原始进程、对象或路径标识，不是原始轨迹。
- [离线复算](verify.py)：`python3 -B verify.py --self-test` 重算时窗、真假对照及两组冲突，并在内存拒绝缺字段、错类型、窗口触边和重复键等反例。不运行夹具；公开材料不能单独认证原始进程、标识、调用或原始输出。

一次内部校核构造了父进程回收时标逆序的反例：原裁定未拒绝该不可能的顺序。修订的原档检查要求父进程依序取得各子进程输出的返回标记非递减；它不要求各进程的实际退出时刻按同一顺序。独立复核还检查了真实原档均为先启动四进程、再接收首个 ready；当前判读器没有把这一跨进程次序全部编码成自动准入。真实原档满足这些次序，结论与公开派生数据均不变，未再运行夹具；公开派生不含这些时标，不能独立重核上述次序。

本试验与此前[同对象同窗 FD 存在对照](../同对象同窗读取检测校准-2026-11-19/README.md)以及[前后采样间隙对照](../读取探针窗口空隙-2026-11-19/README.md)分别检验不同问题，不补早期作废短窗。它只反驳「这里已经匹配的 FD 存在 + 该次快照位置足以证明有无内容读取」，不检验其他遥测或真实产品，也不判定数据是否来自物理磁盘。既有[产品读取支持集](../读取正例与检测支持集-2026-11-14/README.md)仍然不能据此补出真实漏检、召回、污染上界或正式分数。
