# 文件描述符采样间隙：同一普通文件的读／仅打开对照（2026-11-19）

**用一个实际本地配对复现了“两个有用的 FD 快照都没有目标记录，但中间发生了读取”。** 两个快照均成功，且各自精确观测到两臂的专用见证 FD；整个目标 FD 生命周期位于两次命令包络之间，未被采样。两臂在共同窗口持有同一文件；正臂 `os.read` 实际返回 512 B，负臂只打开文件、未读取内容。两个快照在两臂的目标投影都是零。这是一个定时覆盖缺口的反例，不是一次覆盖内漏检或概率估计。

## 证据与判定

两独立、同一非 root 有效用户的自有子进程分别打开同一普通目标；父进程创建目标和另一普通见证文件时分别用 `fstat` 保存设备号、inode 和类型，两臂各自 `fstat` 核同源，结束时复核，父进程清理前以路径元数据核对。两次 `lsof` 都由同一父进程以同一参数只选择两个自有 PID 和预留的目标/见证 FD，匹配见证的确切 PID、数值 FD、`REG`、设备号、inode。两臂都保持见证打开到第二次采样结束之后。正臂对实际返回字节取 SHA-256 并复核偏移 0→512；负臂代码只开/查元数据、查偏移和关目标 FD，不调用文件内容读取，偏移 0→0、内容字节 0、无内容哈希。见证仅打开，两臂均不读。固定共用单调时钟 T 和操作相位；原始时钟、身份值与输出不公开。

以下均为相对 T 的实际毫秒，采样区间为命令启动前标记至取回退出/输出，不假定某个瞬时点或原子快照：

| 证据 | 实际区间或结果 |
| --- | --- |
| BEFORE 采样 | +34.830–52.483；退出 0、stderr 空、两臂见证各一精确命中、目标各零行 |
| 两臂整个目标生命周期的外包区间（开始打开至最后一臂确认关闭） | +225.975–470.115 |
| 两臂共同确证持有目标（较晚确认打开至较早开始关闭） | +230.091–470.054 |
| 负臂动作区间（偏移核验，无内容读取） | +342.618–342.623 |
| 正臂实际 `os.read` 调用区间 | +345.227–345.231；512 B，SHA-256 `110009dcee21620b166f3abfecb5eff7a873be729d1c2d53822e7acc5f34eb9b` |
| AFTER 采样 | +626.809–651.521；退出 0、stderr 空、两臂见证各一精确命中、目标各零行 |

实测目标完全落在 `(52.483, 626.809)` 毫秒的未采样区间；两样本都位于双方共同见证持有期。见证能够排除这两次采样对指定两个 PID/见证 FD 完全无效，不能保证未采样区间或其他对象的可见性。若任一见证、对象/时间绑定、独立读真值、健康状态、严格包夹或清理不能证实，事前规则判 `unknown`，不能用零行代替证据。本次只运行一次、一配对，正常回收两 worker 和两采样进程，删除两个新建文件。

## 能说明什么，不能说明什么

这将[读取观测裁定的 W0/W1 逻辑反例](<../../4-打分细则/读取观测裁定-2026-11-12/README.md>)落实到一次受控普通文件过程：目标零行不能区分「间隙内确实读过」和「间隙内只打开未读」。这里只比较目标 FD 投影，不主张两次命令完整输出字节逐一等同；源里保留专用见证。不同于[旧的合成传感器校准](<../../3-表现现场/r20261104-read-detection/README.md>)，此处同对象配对且验证两个有效采样的完整包络。它不补跑既有未能配对的短窗，也不改变[既有产品读取支持集](<../../5-评测报告/读取正例与检测支持集-2026-11-14/README.md>)。不证明产品读过或没读、实际磁盘 I/O、权限隔离，也不估读漏检率、召回率、污染上界或任何概率。产品调用 0，产品真值分母/率/上界均空值；不改正式结果。

[匿名派生数据](<evidence.json>)只留相对时间、匿名角色、合成内容哈希、身份匹配布尔和原件摘要承诺。`python3 verify.py --self-test` 用[公开复算](<verify.py>)重算时间几何和派生判定，拒绝派生 JSON 的重复键，并验证 11 个内存反例不能通过。公开不能由此重新校验原始 PID/设备号/inode、两臂执行源或采样输出；摘要承诺不等于原件验真，离线复算不等于受控第三方核验。

**原件解析的已知缺口与增补（v2）。** 原冻结判定器以普通 JSON 解码比较子进程原始终包与收据中的镜像，未拒绝重复键。非作者复核构造的内存反例在负臂终包中依次放入 `"content_reads":1`、`"content_reads":0`；旧解析保留末值 `0`，错误接受该歧义包。事后另增只读严格入口，递归拒重，要求子进程原包是单行 LF 结尾、字段形状和类型正确并与镜像一致。同一反例改判 `unknown`；未修改的实际原档通过严格复核，结论及派生数据不变。这个增补没有重跑夹具或改写原收据，公开复算只读匿名派生，不验证私有原始终包。
