# 独立判卷的时间口径：加了硬截止，旧通过还能保住吗？

**结论：现有八份 LCB 公开收据不能证明新硬截止与旧判卷等价。** 旧判卷只在每组开始前看 240 秒；即使每组都在名义 10 秒内且答案相同，最后一组也可能在 240 秒后判完而仍得旧通过。用旧成绩试着验证新环境时，须先声明要保持哪种时钟、是仅保二值达标还是也保题级及加权分。以下只有源码、公开旧账和数值合成，没有重跑真实判卷。

## 1. 相同旧收据可对应不同决定

[锁定 checker](<../../2-用例/lcb-recent-hard-4/checker.py#L136-L175>)每组开始前查 `elapsed > 240`，再执行名义超时 10 秒的单组检查，末组通过后没有整题时钟复查；此前已在[超时边界](<../超时结果与实现边界-2026-11-15/README.md#L13-L17>)记载。这里另作**同迹比较**：题钟及起点、输入守卫、组顺序、单组资格和输出判定都不变，只多一条「某组完成裁定时已严格超过 240 秒就失败」。等于 240 秒不算越界。在这个比较里，新规则通过必然也是旧规则通过；不把加门说成当前设施的终止行为。

- 合成 42 或 43 组，都在题内 238 秒进入末组；末组判完可在 239.5、240 或 241 秒。三种旧收据同为全过，新规则仅在 241 秒翻成未过。
- 合成末两组前已用 235 秒，之后用时为 2 秒、6 秒。同一个 243 秒的计划总量，长组最后时旧规则全过；反序则下一组在 241 秒做预检，旧规则不再运行它。后者的「243 秒」是计划总量，不是实际观测完成时刻。
- 把候选耗时当整题钟也不成立：保持候选用时 238 秒不变，末组执行结束到裁定多出的 3 秒可令新钟越界。这里的数值是合成对照，不是对真实解释器开销的测量；名义单组 timeout 也不担保进程启动、回收、比较合计正好受其围住。

## 2. 一个合格整次上界能保到哪里

令 `T` 是**同次判卷**的可信耗时上界，覆盖从每题起点到裁定末端的全部收费区间，所用计量已证足以包住同一时钟口径，且题间区间不重叠。取预算 `B=240s`，若有 `k>0` 个旧通过在同迹硬截止下翻转，实际计入的时长必严格大于 `kB`。对连续时间，仅凭这样的 `T` 和原通过数 `p`，可上界翻转数为 `min(p, max(0, ceil(T/B)-1))`。这是信息条件下的上界，不是翻转概率；若明知存在非零下界或更细的时序记录，可以收紧。只有判定时钟的**精确**耗时确为整数毫秒（不是显示值取整）时，每项翻转才至少要 240,001 ms，翻转数上界改为 `min(p, floor(T_ms/240001))`；此时 720,002 ms 仍排除三翻，720,003 ms 就不能只靠上界排除。

| 同次整次判卷的合格连续时间上界 | 同迹下原四题已过、输入守卫通过且保持为真时至少保住 | 在此条件下二值达标是否保证 |
| --- | --- | --- |
| ≤240 秒 | 4 题 / 100 分 | 是 |
| >240 且 ≤480 秒 | 3 题 / 75 分 | 是 |
| >480 且 ≤720 秒 | 2 题 / 50 分 | 是 |
| >720 秒 | 不能由这张表保证 2 题 | 否，意为未获保证，不等于失败 |

比如恰好 720 秒不能容下 3 个各自严格超过 240 秒的**串行**区间；三题并行就不能这样加总。即便同次且同一单调钟，晚开记录、提前停止或只累计候选执行而漏掉组间和末判定，都不能当作 `T`。合成反例：实际串行共 720,046 ms，记录晚开 46 ms 后却只有 720,000 ms。三题的末组都在各自题钟恰好 240,000 ms 时启动、用时 1 ms；余下一题 43 组各用 1 ms。同迹下旧规则四题全过，加门后只剩一题。这个推论只隔离一种计分规则改动；实际新设施可能还改变输出、耗时、终止与任务隔离，需另验，无法靠该表放行。

## 3. 旧账有判分，没有这个时间证据

[r1030 正式批](<../../3-表现现场/r1030-formal-a1/README.md>)选两款 CLI 的该题各一槽；[r1109 重复批](<../../3-表现现场/r1109-mech-n3/README.md>)选两款 CLI 各三槽。选定的 **8/8** 份 `checker.stdout` 和分数收据都报旧规则四题全过、守卫通过；逐题共 32 个通过，累计 1,368 次已记通过的测试组（不是新增测试，也不合并为正式成绩）。八份元数据有产品运行时间字段，嵌套判卷结果没有可用的题级裁定时点；在此固定选样，没有一份证据能作为同次判卷的合格整次上界。**就硬截止而言，0 槽证实通过、0 槽证实失败、8 槽未知**。未知不是零耗时或失败。 产品生成耗时、另一机器上测的 oracle 用时，均不得代填。内容摘要一致只固定这些公开记录，不认证当时进程实际加载的文件。

未来若要保持旧分判据，应分别确定：同次逐题起点和末端、确切钟及其覆盖、串行还是重叠、真实输出判定与隔离开销，以及更改规则是否另版预先声明。外部安全验收、真实判卷放行、正式 25 格和历史分数均不随本复算改变。
