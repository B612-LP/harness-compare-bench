# 输入减少去了哪里：源区间覆盖与机制区分

## 一、观察

**判断前**：已有请求字节减少、双键成功及精确 L/Q/E/R/A 分解，仍不能把“外溢、历史截断、消息重组”混作同一解释。**新证据**：逐场源字节覆盖与完整记录内容、全请求历史/非历史身份核对、两个离线预览形状的中部突变反例。**判断后**：本批减少不只是同文本重组；工具返回正文省略与包装/新模型侧历史差异共存，所捕获 Req1→Req2 的旧历史删除/换序不成立。

| 既有批次／臂（不合并 n） | 场数 | 源拷贝 S bytes | 呈现包装 W bytes | 已解码文本 L=S+W | 完整 noise 记录内容／420 |
|---|---:|---:|---:|---:|---:|
| 同 DSH 六对／inline | 6 | 35767 | 0 | 35767 | 420 |
| 同 DSH 六对／bounded | 6 | 1728 | 253 | 1981 | 18 |
| 原生三 block／Codex | 3 | 11964 | 57 | 12021 | 139 |
| 原生三 block／DSH | 3 | 1728 | 253 | 1981 | 18 |

原生 L 差 10040 可细分为 **源拷贝差 10236 + 包装差 −196**，只是事后描述恒等式，不是等文本受控残差、token/成本或普遍因果。原配对指标、阈值、双键终点、正式 25 格和样本分母不变；新产品／模型请求 **0**。

## 二、证据

[机器结果](<result.json>)由[独立标准库验证器](<verify.py>)实际生成，pin **75 个公开源相对路径＋SHA-256**，绑定源基线提交 `38b2e13f63c5aeacb58094d2e977980ab12e8041`。逐场记录真实 fixture、前后请求路径、文本 JSON pointer、覆盖区间、canonical 历史/非历史 hash、请求字节和原生 usage 事件；usage 单列、不求和，缺失不填 0。不是数百 KB 请求副本，也不是新原封印。

所有区间为**源 UTF-8 bytes 的半开区间**，分母为该特制源的 35767 bytes：

- inline：`[0,35767)`；bounded：`[0,864)`＋`[34903,35767)`，原文缺口 34039B。
- Codex：`[0,5982)`＋`[29785,35767)`，原文缺口 23803B；33B 时间叶与 11988B 输出叶分开重构，后者含 24B 间隔包装。
- 每个实际文本叶均由按序源片段＋明确包装**逐字节重构**，不是只检查 contains。片段的所有源出现位置均列出；重复子串不能假定唯一，也不把多个候选位置全部算成确定覆盖。当前实际片段均唯一。
- noise 分母是源中 420 条 `noise-NNNN checksum=<64hex>\n` 记录；主列“完整记录内容”要求行内容全部源字节，不含 LF。完整含原 LF 整行另计：inline 420、DSH 18、Codex **138**。Codex 的 noise-0069 内容 `[5898,5982)` 完整，但其 LF `[5982,5983)` 被切掉，故内容计 139、含 LF 计 138；不足整条内容的边缘片段不计完整。

独立手核：[夹具第202行](<../../3-表现现场/r20261103-input-bytes/runs/confirm-b01-inline/capture/tool-output.txt#L202>)的 noise-0200 值在 `[17053,17117)`；逐场扫描**全请求所有字符串叶**，其原值只在 inline 的 Req2 出现，预览臂没有字面见证。包装 W 是呈现角色的字节划分，不声称其中每个短子串都从未在源出现，也不是信息熵。

已有 [L/Q/E/R/A、前缀门及三残差](<../原生字节分解-2026-11-05/README.md>)不是新贡献；[同 DSH 六对](<../../3-表现现场/r20261103-input-bytes/README.md>)和[原生三 block](<../../3-表现现场/r20261104-native-provenance/README.md>)继续分账。本页是公开投影的事后再分析，不导入或执行旧分析程序。

## 三、解释

| 解释 | 本次裁定及范围 |
|---|---|
| 工具源正文裁剪 | **支持**：实际源区间和中部字面事实缺失，不是只缩小包装。 |
| 旧历史截断／改序 | **排除本次捕获期间的该解释**：12 个同 DSH 场和 6 个原生场，各自 Req1 历史 canonical 与 Req2 等长前缀完全一致，所有其他请求字段及存在性也一致。原生此门已有先例，同 DSH 本次逐对象补核；不外推长历史。 |
| 仅同内容消息重组 | **不能单独解释全部减少**：源覆盖不同；但包装／新模型侧历史差异确实共存。纯分叶合成控制保持有序文本不变却改变 JSON bytes，机制并非互斥单选。 |
| 引用意味着全文可回读 | **未知、未测试**：引用文字不等成功读取。DSH 菜单仅 fixture_output，页脚虽建议 read，却无 read schema，合同还禁止额外工具；Codex 原生菜单不同，也受只准一次 fixture、禁止额外工具的合同约束。 |

[机器结果的合成诊断](<result.json>)是**新写离线形状模型及验证器反例，不是产品内部代码执行或模型实测**：只改 noise-0200 中一个等长 hex 字节，两种预览逐字及 hash 不变、inline 改变；只改可见 HEAD，两种预览必变。源事实不同却得到同一预览，足以否定“此预览唯一决定全部源事实”，但不估通用语义信息量或任务性能。另有同长度历史调序、删历史、非历史字段改动被精确门拒绝。

## 四、未排除因素

- 原生 `information_retained:true` 只指 **HEAD/TAIL 双键**；双键成功不是全文无损，也不因本次新增覆盖指标事后改判旧任务。两臂均缺中部，Codex 不是全文基准。
- 请求中没有中部原文，不等磁盘源原件丢失；全文引用是否有效、允许读时能否恢复及模型是否主动回读均未实测。仅字面缺失也不证明所有可能编码都不含该信息。
- 只覆盖所捕获请求时点；捕获前历史、后台缓存、服务端最终上下文未知。reported usage 不是等控证据，actual reasoning/cache 仍混杂；bytes、token、费用分别解释。
- 原生菜单、协议、输出上限不同；不能估普遍因果、纯 Harness 优劣或总体排名。源字节／noise 覆盖只适用于当前特制夹具，不外推性能或泛化保真率。
- 固定 hash 认证受信代码认识的公开快照，非私档真实性、第三方见证或历史原封印重新通过；本次未重跑旧完整 SSE 技术门。

## 五、可复现与验收

Python 3.9+、仅标准库。仓库根执行，默认只读 stdout；显式输出使用 `--output NEW.json` 独占创建，已有文件拒绝覆盖：

```sh
python3 -I -S -B 5-评测报告/输入源覆盖与机制区分-2026-11-12/verify.py --root .
python3 -I -S -B -O 5-评测报告/输入源覆盖与机制区分-2026-11-12/verify.py --root .
python3 -I -S -B 5-评测报告/输入源覆盖与机制区分-2026-11-12/test_verify.py
python3 -I -S -B -O 5-评测报告/输入源覆盖与机制区分-2026-11-12/test_verify.py
```

2026-11-12 实跑：两次 CLI 均 `PASS_PUBLIC_SOURCE_COVERAGE`、输出逐字相同；[自测](<test_verify.py>)普通／`-O` 均 **29 tests / OK**。覆盖 UTF-8 字符/字节错位、多解重复及重叠子串、部分行与 LF 边界、只引用无回读、中部等价/可见键敏感、同长度调序/删除/替换、非历史值及存在性变化、75 源逐个篡改/缺失、非 contains 重构、指针/调用串联、只读无网络无子进程、输出独占和结果全量精确对账。验收逻辑使用显式异常，不用会被 `-O` 移除的 assert。
