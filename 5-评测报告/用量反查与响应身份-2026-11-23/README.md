# 用量计数相同，能否认出原来的响应？

[既有六对用量复核](<../首包一致与用量漂移-2026-11-19/README.md>)核对的是公开用量附表。本页回到**同一批 12 场每场前两次响应**：先用归档收据固定端点和原件，再核两个有明确位置的用量事件，最后反向问：不看收据时，有几份响应报出相同值？这三个判断不互相替代。

| 所用见证 | 可复核结果（24 条响应） |
|---|---|
| 精确归档端点加阶段位置与用量对象 | 24/24 与附表相合；两阶段位置共 48 个，均可核 |
| 两阶段完整用量对象的值，在本批响应间反查 | 11/24 不唯一，一个值组最多对应 9 条不同响应；限定候选与目标处于同一请求次序，或只留本页所比的四列计数，均未减少这批歧义 |
| 只取明确末段的自报输出数值 | 18/24 不唯一；若限制请求次序，最大组仍有 9 条，不限制时为 11 条 |

同值替换对照只在内存中用另一条已归档响应替换目标副本：两阶段用量仍一致，但原件收据不匹配，不能认作目标响应。另有内存对照表明，少一个阶段角色标签时，已经看见的同值仍可记，不能据此核准附表绑定；流关闭了也不意味着从错误路径取出的计数合格。

上述计数只限这批固定捕获和辅助记录，并非真实计费、模型实际摄入、服务端内部使用量，也不估计按场次划分或其他批次的反查性能。内部非作者从已钉原件独立核验后再复跑代码与反例；不披露正文、逐条计数或标识，不替代受控第三方核验。无新增运行，不改历史分数。
