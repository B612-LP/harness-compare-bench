# 匹配呈现与预定查询

## 1. 结论

本次 **1 个实际确认会话**中，两份已知合成源仅差一个字节。原生 `grep` 对两源执行同一通用模式，均成功报告 1 个匹配，但呈现文本没有目标字段；另一条**事先固定**的谓词查询则成功给出 0 / 1，从而区分这个已知源对。仅能支持“该已知谓词的一 bit 区分”，不是恢复 64 个十六进制字符、未知密钥或一般信息熵，也不是执行了 256 次查询。

原生匹配格式化与后续估算裁剪是两个层次：**2210 B 完整格式化文本只有前 2000 B 源；最终 1978 B 面中实际源覆盖为 1470 B，而非 2000 B。** 完整格式化外存本身已没有位于源字节 8007 的字段；该外存不是原始 16000 B 源。

脚本固定决策并提供本地响应，实际调用原生工具；**0 真实模型、0 远端上游、0 模型策略评分**。这不是智能体自主选择查询或任务质量的评测。独立科学审阅有限 PASS 对应这一次绑定轨迹与这些关系；公开派生包的隐私、复算与来源边界需要单独审阅，不等于原始轨迹全面公开认证。

## 2. 证据

- 合成源：[A](<sources/A.txt>)、[B](<sources/B.txt>)，各 16000 B，单行、无末尾换行；仅字节 8007 从 `0` 变为 `8`。这些安全合成字节保持原样，原源与公开源 hash 相同，明确标记“未变换”。
- [选择性证据](<evidence.json>)：固定顺序 G(A)、G(B)、D(A)、D(B)，匹配数 **1、1、0、1**。G=`TARGET=[0-9a-f]{64}`；D=`TARGET=[89abcdef][0-9a-f]{63}`。四次查询**不是四个独立重复**。
- 最终工具结果：[Q1](<results/Q1.txt>)、[Q2](<results/Q2.txt>)、[Q3](<results/Q3.txt>)、[Q4](<results/Q4.txt>)；三个正匹配的完整格式化外存：[Q1](<formatted/Q1.txt>)、[Q2](<formatted/Q2.txt>)、[Q4](<formatted/Q4.txt>)。Q3 的 16 B `No matches found` 必须同时有完成、无错误、原生与上游文本一致证据；失败、缺失、截断或 unknown 不当作零匹配。
- 同份 JSON 嵌入 2 个 fixture 和 4 个 grep 的**实际原始 schema 形状**的选择性工具面：上游 `content` 为单个纯 text 块组成的列表，`is_error` **字段存在且为 false**；Native 结果均 `completed`，实际**没有** `truncated` 字段。保留角色、消息/块位置以及等长匿名调用 ID；不是改造为不同的 text schema。
- 另有 1 个 catalog 会话、1 次本地请求用于确定实际工具目录；确认会话 6 次本地请求、2 fixture + 4 grep。总计 **2 新会话 / 7 本地请求 / 1 科学确认会话**。目录会话不增加科学样本数。

| 三个正匹配面共用的层次 | 字节或区间 |
|---|---:|
| 原始合成源 | 16000 B |
| 完整格式化文本 | 2210 = 2000 源 + 210 格式 B |
| 裁剪后保留的格式化区间 | `[0,840)` 与 `[1370,2210)`，合计 1680 B |
| 省略的格式化内容 | 530 B |
| 映射回原源的最终区间 | `[0,647)` 与 `[1177,2000)`，合计 **1470 B** |
| 最终结果面 | 1978 = 1470 源 + 210 原格式 + 9 GAP + 289 footer B |
| 最终非源字节 | 508 B |

G(B) 与 D(B) 的原完整格式化文本 hash 相同；它们不是新增独立源或重复样本。G 的呈现相同只指**移除两种经验证定位符后的指定工具结果投影**相同，不指完整模型输入、运行时状态或 whole-context 碰撞。

## 3. 机制解释

读取与匹配确实发生在原生工具链，脚本只控制固定模式和精确源路径。原生匹配先形成带路径、行号与 2000 B 单行预览的文本；超过 `maxInlineTokens=512` 的估算阈值后再做首尾保留和带定位符的省略提示。这里的 512 是配置中的估算阈值，**不是已测实际 tokenizer token 数、成本或严格输入上限**。

完整源不同不妨碍同一个无目标字段的呈现投影相同；能否区分还取决于允许问什么。D 只询问一个已知谓词，成功的 0 / 1 说明这对源在该查询下可区分，不说明已经得到缺失的 64 个十六进制字符。本次仅执行四次固定查询；没有执行 256 次查询，也没有测量未知值熵或恢复复杂度。

## 4. 限制与来源边界

- 选择性派生材料，不是完整 raw 请求、系统/权限快照、会话或真实工作目录。仅替换完整且预先验证的源/格式化定位符为**等 UTF-8 长度**的相对占位符；调用 ID 也等长匿名化。没有宽泛过滤、重写 SSE、重跑产品或修改原始记录。
- JSON 将原 raw HTTP 字节 hash、格式化 JSON 文件 hash、canonical JSON 值 hash、Native JSONL 行 hash、原文本 hash 与派生文本 hash **分别列出**。公开文件内的内容/清单 hash 及值承诺验证一致性，不能独立认证未公开的原始字节、回调原 FD、物理路径归属、cwd 或整段历史。
- 原件独审核对了 194 份绑定原件及前后身份属性、全部增量历史、实际原生/上游结果配对、回调原 FD/固定 ledger、当前会话外存及 12 个内存近错。这里公开的是这些私档关系的有界见证，不把“私档独审已做”冒充公开可完整重演。
- 终态保存类型明确的完成/退出/超时/无错误/原生核对/永不重发/零上游证据。owned-group 清理只见证本次新进程组 signal-0 返回 absent，**不是整个进程树或所有后台进程均已不存在**。
- 源码绑定、版本与默认工具配置不证明完整 runtime 身份；只比较指定控制字段，未比较的 metadata 不能推成整个 wire 输入相同。旧预检失败不因修订后通过而重新判为成功。
- 不推未知 key 恢复率、一般 Harness 能力、长历史稳定性、后端上下文容量、压缩不存在、实际 reasoning/cache 等控、token/成本或跨产品可比评分。

## 5. 公开复算

仅需 Python 3.9+ 标准库。在此目录执行（只读，不联网、不启动产品、不发送模型请求、不生成文件）：

```sh
python3 -B verify.py
python3 -B test_verify.py
python3 -B -O test_verify.py
```

[verify.py](<verify.py>) 从真实公开源和结果/完整格式化字节重新计算模式匹配、二次裁剪、源区间、包装分账、schema/字段存在性、Native 配对与分母；先检查 [清单](<SHA256SUMS.json>) 的全部 14 文件覆盖、hash 与无符号链接/无额外文件。正常与 `-O` 运行均使用显式异常而非可优化掉的 `assert`。[有限反例测试](<test_verify.py>) 在内存中改坏后重新承诺 JSON 值/hash，再确认实质校验仍拒绝；这些软件测试不是新的产品样本。
