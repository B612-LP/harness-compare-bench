## 1. 摘要（结论先行）

1. **同模型条件下（A 组：Codex CLI / DSH CLI，钉 DeepSeek V4.1-Flash）未观察到稳定 Harness 结果面差异**：正式表 A 组 10 行双产品 headline 同为 3/5，weighted 总分 444.81 vs 444.07，差异由两次单项波动构成；n=3 重复批逐场同结果（§6.1、§8 结论一）。
2. **机制面上捕获到可复制的 Harness 差异**：工具结果外溢（spill）机制的有无，决定同一模型第二次调用输入量级骤降是否出现——跨 Harness 复制成立（§8 结论二）。过程成本统一口径后为 1.18–2.09×，因混入 SKILL 层不能作编排规模证据。
3. **SKILL 层单变量消融为阴性**：在两道稳定未达标题上，注入统一技能五臂（含换模型臂）reward/失败项完全一致——技能层不是这两题失败的瓶颈（§8 结论三）。
4. **B 组（元宝专家模式/豆包办公）正式准入 9 行**：结果呈真实分化（§6.2），可见差异集中在产品层属性——交付路径可用性（元宝深度思考档服务端截断）与检索管控能力（两产品均无法技术断网，按三件套口径执行）；豆包×exercism 经作废重跑补齐 B 组最后一格（83.33，V clean）。
5. **桌面越界风险被实证并已前置收敛**：豆包×cargo 曾出工作区读取判卷物料，按判定纪律 X 整场排除；自 r1102 起桌面批前置执行工作区边界判定线（§5.3、§9）。
6. **判卷合同缺陷与产品能力可分离**：BIRD q26 题面-金标缺陷走全套修订纪律并入 v1.2（历史回放零二值翻转）；DAB q2697 歧义题撤出能力归因（§8 结论五）。
7. **WorkBuddy 的正式表位置**：请求级证据显示其桌面端路由与 CLI 直连不同（自家网关），不入同模型 A 组正式表；其能力证据以观察账呈现（§6.3）。

## 3. 归因定责设计（评测主体是 Harness）

三层定责（细则见[归因定责](<../4-打分细则/归因定责.md>)）：

- **模型层**：A 组三款（Codex/DSH/WorkBuddy 语义）统一钉 DeepSeek V4.1-Flash（官方端点 `api.deepseek.com`，chat 与 responses 双实测；Codex 走 responses wire）。同模型下结果差异只能落到 Harness。B 组模型封闭不可证，**不参与同模型归因与排名**。
- **SKILL 层**：CLI 出厂即关闭技能注入（r1025 起双 CLI 无 skills）；消融批以「剥除/统一技能」双臂验证技能层贡献（结论三）。
- **Harness 层**：A − C 对照。C 组为裸 API 直问（零脚手架），早期批次已证裸模型基线远低于 Harness 组。

**检索口径**（B 组关键混杂控制）：三款桌面产品均无法技术性保证断网，统一按 2026-10-27 落表三件套执行——任务书禁止联网条款 + 逐会话检索行为披露（元宝 `speechesV2[].internetSearch` 实值、豆包轨迹）+ 批后 integrity 扫描与人工终审；实证 clean 记 V、实证命中记 X 整场排除不豁免。

## 8. 结论（五段结构）

### 结论一：A 组同模型结果面未观察到稳定 Harness 差异（Codex CLI / DSH CLI / WorkBuddy 桌面）

- **观察**：正式表 A 组 10 行（r1030，n=1/格）headline 双 3/5，失败格局（dabstep 双款 70.00 低于 0.8 线、cargo 为 checker 二值未全过）与 r1025/r1027/r1028 历史完全一致；weighted 总分 444.81 vs 444.07 由 bird/cargo 两次单项波动构成；r1028 重复批（n=3）二值结果逐场相同。
- **证据**：[v2 官方表](<可信冻结-2026-10-29-v2/official-main-table.json>)、[r1030 现场与逐场判分收据](<../3-表现现场/r1030-formal-a1/README.md>)、r1028 重复批收据。
- **解释**：在同一模型、同一冻结判卷、同一闸门下，两款 CLI 的结果面无可复现的稳定差异；差异捕获需转向机制面（结论二）。
- **未排除因素**：n=1/格（重复批仅 2 题）；WorkBuddy 桌面臂因路由不同不在正式表，其同模型语义未在正式账验证；题面饱和（3 题双满分）压缩区分度。
- **可复现实验**：`python3 4-打分细则/可信冻结-2026-10-29-v2/freeze.py verify`；逐场 `python3 2-用例/<case>/checker.py <现场产物> --json` 复算。

### 结论二：二次调用输入骤降跟随 Harness 上下文管理机制（跨 Harness 复制成立）

- **观察**：同一模型、同一 35,767 字节夹具下，有外溢策略的 DSH（spill 512）第二次调用输入 443→1,514/1,495；无外溢策略的 Codex 8,610→15,093（工具结果全量内联）。
- **证据**：[机制复制 RESULTS](<../1-评测方案/机制复制-2026-10-29/RESULTS.md>)——DSH 两段 raw SSE 完整、Codex MCP 日志与会话自报用量、夹具三方同哈希（`fed5759…`）。
- **解释**：「第二次调用输入骤降」跟随 Harness 的工具结果外溢机制出现/消失，而非模型或服务端行为；原 pair-1 缺口由新运行补齐，原六场原样保留。
- **未排除因素**：思考 token 差异混杂（已登记）；跨 Harness 绝对值不可比（可复制的是增量模式）；Codex 用量为产品自报；缓存语义服务端不披露；每臂 n=1。
- **可复现实验**：机制复制目录预注册 + 双运行器 + 离线分析三条命令可复跑。

### 结论三：SKILL 层单变量消融——两道稳定未达标题上技能层零结果改变

- **观察**：r20261027-ablation 五臂（codex base/skill、dsh base/skill、codex 原生模型臂 gpt-6.1-sol）在 dabstep/tb 两题 reward、weighted、失败项完全一致（如 dabstep 五臂同 0/70.0，同失败 q49/q70/q2697）；技能臂处理真实性有轨迹实证（技能提及 4–10 次，base 臂 0）。
- **证据**：[r20261027-ablation 批](<../3-表现现场/README.md>)（五臂 result.json / meta / 会话轨迹）、[未知登记 skill-ablation 结清记录](<未知登记.json>)。
- **解释**：在两道双 CLI 稳定未达标题上，注入统一技能（零金标泄漏、两臂同文）不改变结果——技能层不是这两题失败的瓶颈；换模型臂同败提示失败更多系任务难度/口径而非模型身份（本批内）。
- **未排除因素**：仅 2/5 题、n=1/格；统一技能内容本身可能无效，不能外推「技能层普遍无效」；思考档 low 固定；历史 n=3（r1025/r1027/r1028）仅作先验不作合并推断。
- **可复现实验**：消融批 README 协议（工作区装配/判分只读/幂等续跑）+ 各臂 result.json 逐格对照。

### 结论四：B 组差异主要在交付路径与检索管控能力；正式批暴露桌面文件系统越界风险
