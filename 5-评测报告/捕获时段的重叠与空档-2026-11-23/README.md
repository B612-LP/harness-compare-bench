# 捕获活动时段不能逐包直接相加（11-23）

只读三组既有 DSH Chat 的 34 份客户端捕获元数据（31 份主请求、3 份辅助标题），没有打开请求或响应正文。按每组独立墙钟，以窗口并集计活动，按正长度交集计主辅重叠。窗口宽度之和在三组均大于并集；把标题窗整个再加到主窗上，会重复计算大部分标题窗。

| 组 | 全部活动并集 | 直接求和多算 | 仅标题占用 | 全部未占间隙 |
|---|---:|---:|---:|---:|
| A | 8,103,800 µs | 1,161,679 µs | 216 µs | 35,701 µs |
| B | 69,352,349 µs | 11,382,218 µs | 131 µs | 423,745 µs |
| C | 28,980,261 µs | 1,157,499 µs | 163 µs | 424,713 µs |

在这些归档，峰值并发均为 2，重复计算恰等于主辅重叠；三窗或更多重叠时，不能用两两重叠之和代替重复时间。恰好接触不算正重叠；缺失或无法绑定的时钟只保留可见下界，不回填完整账。捕获器自报时长与墙钟窗宽独立对账，两者的最大绝对差在三组分别为 0.916、0.894、0.944 ms；不以自报时长替代墙钟窗宽或回填缺失端点。内部非作者复算并重放对照，不合并不同归档。

这些只是在捕获边界内可见的活动窗和空档，不是任务耗时、供应商延迟、阻塞顺序或因果效率。未新跑产品、未改冻结状态或历史计分。参见 [主辅角色与时序支持域](<../../4-打分细则/支持域与漂移判定-2026-11-23/README.md>)。
