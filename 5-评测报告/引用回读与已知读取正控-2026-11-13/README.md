## 一、问题与设计

正式批次的捕获显示：DSH 在工具结果超过外溢阈值时把正文替换为短预览加引用路径（bounded），同一产品内联模式（inline）则全量携带。旧批次的合同禁止额外工具，因此**"模型能否顺着引用把全文读回来"从未被测试**——这是输入减少机制三分（工具外溢 / 旧历史截断 / 消息重组）里唯一可实测的缺口。同时，真实产品此前 0 读取命中是"检测面未观察到"，缺已知内容正控来排除"读取路径不可达"这一竞争解释。

设计（预注册后执行，同版本 DSH 0.2.0-rc.2 + deepseek-flash、思考档 low）：

- **C1×2 复制门**：逐字复刻 2026-11-03 bounded 条件（无 read 工具、外溢阈 512），先跑，作为漂移门。验收：首请求输入 1124B±8、bounded 增量 2382B±64、两请求完整。
- **RB×6**：bounded + 工具菜单新增 `read(path,offset,limit)`（512 阈）。提示词只要求三键 JSON，**从不提 read**——测模型是否自发使用恢复路径。键值：HEAD=夹具头尾观测值、MIDDLE=noise-0210 的 checksum（sha256("fixture-v1-210")）、TAIL=尾观测值；MIDDLE 位于预览截断区内，只能经 read 恢复。
- **IMK×2**：同菜单、阈值 1,000,000（等 inline 全量），作成本对照。
- 预注册或有臂 rb-nudge×3（提示词追加 read 提示）：仅当 RB 六场全部未调 read 才发射；实际未触发。

### 二之二、尺寸响应探针（同日 v3 增补，Ring 8）

问题：各产品读取路径在多大尺寸停止"完整携带"。夹具四档（990B / 8,129B / 65,504B / 262,109B，中间记录各不同），每档 n=1，观察面=各产品本地轨迹/回执（**非模型侧字节**）：

| 臂 | 1k | 8k | 64k | 256k | 分支 |
|---|---|---|---|---|---|
| Codex CLI | 内联 | 内联 | 内联 | **内联（首命令 rg 聚合 276,427 字符全量携带）** | no_threshold_found_upto_256k |
| WorkBuddy（glm-5.3-flash） | 内联 | 内联 | **持久化预览展示，usage 增量 +41,988 tok 证模型侧全文摄入** | **拒绝（42,486 tok > 20,000 上限）→自发 offset/limit 定向读，3/3** | threshold_bracketed |
| 豆包工作（2.35.19） | 内联 | 内联 | **内联（68,504 字符）** | **拒绝（65,527 tok > 25,000 上限）→自发 Grep 定向读，3/3** | threshold_bracketed |

读数：第一个非内联点都在 256KB 且都是**工具显式 token 上限拒绝**而非静默截断；两种拒绝后模型都按错误消息指引自发补偿且三键仍全对。WorkBuddy 64k 显示**轨迹展示形态≠模型摄入**（持久化预览只是展示面）。WB 首轮事故（prompt 路径写错）与豆包 1k 前置失败各按预注册修订重跑，不新增计划槽位。边界：观察面各产品不同、不横比产品能力；256KB 以上未探。

### 二之三、外溢阈值扫描（同日 v4 增补，Ring 10）

问题：Ring 1 的 512 外溢阈是单点；把 DSH 外溢阈（maxInlineTokens cap）扫大，自发 read 与会话字节成本如何变？同 35,767B 夹具、同提示词（从不提 read）、同工具菜单，五档 cap × 2 槽 = 10 会话（全 live，预注册 seal 035ac8ca…，零重试零替换）：

| 臂（cap） | 有效槽 | 分支 | read 次数 | MIDDLE | 会话总输入中位 |
|---|---|---|---|---|---|
| 512 | 2/2 | recovered_via_read | 2 | 2/2 | **13,128.5B（最省）** |
| 2048 | 2/2 | recovered_via_read | 2 | 2/2 | 24,966.5B |
| 8192 | 2/2 | recovered_via_read | 2 | 2/2 | **74,846B（最贵）** |
| 32768 | 2/2 | answered_without_read | 0 | 2/2 | 40,196.5B |
| 131072 | 2/2 | answered_without_read | 0 | 2/2 | 40,211.5B |

读数：**交叉点落在 [8192, 32768]**——cap≤8192 每场自发 read（3 请求），cap≥32768 每场直接从预览/内联作答（2 请求零 read）；三键 10/10 全对、MIDDLE 10/10 恢复。会话字节成本对 cap **非单调**：512 最省，8192 最贵（8k 预览内联 + read 往返双重开销）；Ring 1 的 512 配置是受测臂中最优。停用规则的两种解释（「无外溢残留」vs「答案已可见」）在 8192 档上倾向前者（预览可能已含 MIDDLE 但模型仍 read），16384 档不在冻结阶梯内、留待新预注册。边界：机制面单一夹具、n=2/臂、字节≠token≠成本。


### 二之四、MIDDLE 位置对照与头+尾预览（同日 v5 增补，Ring 12）

问题：Ring 10 交叉点 [8192, 32768] 留下两解释（「无外溢残留」vs「答案已可见」）。对照：同 35,767B 夹具、cap 8192，两臂各 2 槽，所问记录分别在头段（noise-0019@L21≈4.6%）与尾段（noise-0405@L407≈96.3%），提示词从不提 read（预注册 seal 2eddfd15…，零重试零替换）：

| 臂 | 所问记录位置 | 预览内可见 | read 次数 | 三键 |
|---|---|---|---|---|
| mp-near ×2 | L21 头段（4.6%） | 是 | 0 | 2/2 |
| mp-far ×2 | L407 尾段（96.3%） | 是 | 0 | 2/2 |

**关键捕获证据**：mp-far-01 请求 2 的工具结果 32,700 字符，尾部含 `Omitted 3319 bytes. … Use read with offset/limit, or grep this path` 页脚——**noise-0405（96.3% 位置）在预览里、noise-0210（50% 位置）不在**。即 **DSH 的 bounded 预览是「头+尾保留、省略中段」，不是纯头截断**；1103 cap=512 时预览仅 1,981B、尾段被吞，才造成「head-only」的旧印象。

**合并 Ring 10+12 的机制结论：模型恰在「所问记录位于被省略中段」时才调用 read；记录可见（头段/尾段/全量）则直接作答。** Ring 10 的 8192 档 read 并非「无外溢残留习惯」——该档预览为中段省略形态，所问记录确实不可见；「答案可见性」作为 read 决策门的两解释就此裁决。边界：单一夹具、cap 8192 单点、三个探针位置（4.6%/50%/96.3%）、n=2/臂；read 动机（自我验证 vs 效率）不可直接观测。


### 二之五、外溢边界细化（同日 v6 增补，Ring 14）

问题：Ring 10/12 之后仍差一步——外溢恰好在哪一档消失？两档 × 2 槽（预注册 seal bd0bacce…，零重试零替换）：rb-c9216（近界预测：外溢缩小、read 保持）与 rb-c16384（预测：无外溢、全量内联、0 read），提示词仍问中段记录 noise-0210@L212、从不提 read：

| 臂（cap） | 外溢页脚 | MIDDLE 在请求 2 | read | 三键 | B2 |
|---|---|---|---|---|---|
| rb-c9216 ×2 | 无 | 是 | 0 | 2/2 | 38,425 / 38,794 |
| rb-c16384 ×2 | 无 | 是 | 0 | 2/2 | 38,491 / 38,465 |

读数：c16384 预测成立；**c9216 预测不成立（如实记录）——实测无外溢**。合并 Ring 10 实测（cap 8192 预览 32,768 字符 + 省略 3,319B）：本夹具的 token 数 ≈ 8,942（ASCII 文本 ≈4.0 字符/token），预算≈cap×4 字符公式与 Ring 12 的 32,768=8192×4 对齐，**外溢消失边界 ∈ (8192, 9216]**。E1 答案可见性门由此覆盖全部六个实测条件（无外溢时问中段记录也 0 read，4/4）。边界：单一夹具（≈4.0 字符/token）、8,942 为推算值非直接测量、n=2/臂、头+尾预览的精确分割比例未测。

## 四、边界与私档

- 单一夹具几何（422 行 / 35,767B / 单一中段记录）；不外推其他尺寸、任务或产品。
- 字节为客户端组装口径；真实 thinking、cache、后端历史改写不可观测、未控制。
- n=2/n=3/n=6 描述性样本；仅 RB MIDDLE 命中给区间；不做排名或分数推断。
- WB/豆包/Codex/元宝运行不入 A/B/W 正式格；模型档位披露见上；Codex 会话按设计启用 shell 工具（被测路径本身）。
- 尺寸响应（Ring 8）观察面=各产品本地轨迹/回执，非模型侧字节；WB 用 usage 增量旁证模型摄入，豆包/Codex 无 usage 面；每槽 n=1、无重试、256KB 以上未探；WB 20,000 / 豆包 25,000 token 上限是观察面上的工具侧限制，不构成产品能力结论。
- 元宝数据为单场中期样本（partial 2/3），TAIL 异常只登记观察与待检验假设，不构成产品缺陷结论；其余场次补齐前不更新该行。
- 原始捕获（relay 逐请求、产品轨迹、桥回执）留私档；本目录只含发布级数值，不复原原文。公开复算入口：`python3 verify.py`（只读、无网络、无第三方依赖），`python3 test_verify.py` 为其单元测试。
