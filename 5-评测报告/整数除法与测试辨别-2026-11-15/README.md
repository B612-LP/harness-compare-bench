# 整数除法与固定测试的辨别范围

2026-11-15 事后探索。只对已公开源码的临时副本进行离线执行，不新增产品试验，不重判正式成绩；旧测试、参考解和收据均不修改。

## 1. 观察与新判断

固定 Forth **54 个测试通过，不足以识别负数除法采用向下取整还是截向零**。裸模型同一配置的 r2、r3 历史收据均为 Forth 54/54，但当前归档源码在 `-8 3 /` 上分别返回 `-3`、`-2`。这不是两个值都“通过了负数除法测试”：原测试没有该用例。

另一个独立盲区是中间转浮点的精度。旧 WorkBuddy 归档源码在本次临时副本执行中通过 54/54，却将正整数 `9007199254740993 1 /` 算成 `9007199254740992`。以小字面数 `2` 连续倍增 52 次，再 `1 + 1 /`，也出现相同误差。不能仅以“大字面数没声明支持”解释这个反例，但题面也没有明确整数范围，故它是**选定扩展域的数学反例，不是追补的正式扣分项**。

## 2. 固定测试究竟覆盖什么

[原测试](<../../2-用例/exercism-py-6/tests/forth_test.py>) 中含 `/` 操作的调用共 7 个：

| 类型 | 程序 |
|---|---|
| 成功路径，4 个 | `12 3 /`、`8 3 /`、`1 12 3 /`、`2 4 * 3 /` |
| 错误路径，3 个 | `4 0 /`、`/`、`1 /` |

成功路径的被除数/除数均为小正整数；所有 Forth 用例共 54 个，不是 54 个除法用例。[本地题面](<../../2-用例/exercism-py-6/inputs/exercises/forth/README.md>) 允许负数、要求整数运算，但没有明确负商舍入方向或整数范围。因此参考解采用截零可以作为一种实现参照，**不能事后把它升格为本题唯一规定**。
