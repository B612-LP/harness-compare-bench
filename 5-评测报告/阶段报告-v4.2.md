## 二、核心结论五段集（每条含未排除因素与可复现实验）

### 结论一：A 组同模型结果面未观察到稳定 Harness 差异（Codex CLI / DSH CLI / WorkBuddy 桌面）

- **观察**：正式表 A 组 10 行（r1030，n=1/格）headline 双 3/5，失败格局（dabstep、cargo 低于 0.8 线）与 r1025/r1027/r1028 历史完全一致；weighted 总分 444.81 vs 444.07 由 bird/cargo 两次单项波动构成；r1028 重复批（n=3）二值结果逐场相同。
- **证据**：[official-main-table.json](<可信冻结-2026-10-29-v2/official-main-table.json>)、[r1030 现场判分矩阵](<../3-表现现场/r1030-formal-a1/README.md>)、[r1028 重复批](<../3-表现现场/r1028-repeats/>)、机器账逐行 adjudication。
- **解释**：同一模型（DeepSeek V4.1-Flash、思考档 low、SKILL 关、联网关）下，三形态在结果面（二值 + 半程分）无稳定可测差异；可测差异集中于过程成本与取证能力维（过程成本差异不能进 Harness 归因，统一口径后 1.18–2.09× 只表述为「差异存在」）。
- **未排除因素**：正式批 n=1/格，单场方差未量化（[r1031 n=3 结论](<可重复性-n3-2026-10-29/RESULTS.md>)为描述性判断、非等效性证明）；五题中两题结果面饱和，区分度有上限；时段/次序效应未控制；WorkBuddy 因「请求级上游主机无公开证据 + 模型 id 不等价」两项受管未知未入正式表。
- **可复现实验**：`freeze.py verify`（v1/v2）+ r1030 逐场 `checker.py <ws> --json` 复算（命令见批次 README）+ [verify_var_n3.py](<可重复性-n3-2026-10-29/verify_var_n3.py>)。

### 结论二：二次调用输入骤降跟随 Harness 上下文管理机制（跨 Harness 复制成立）

- **观察**：同一模型、同一 35,767 字节夹具下，有外溢策略的 DSH（spill 512）第二次调用输入 443→1,514/1,495；无外溢策略的 Codex 8,610→15,093（工具结果全量内联）。
- **证据**：[机制复制 RESULTS](<../1-评测方案/机制复制-2026-10-29/RESULTS.md>)——DSH 两段 raw SSE 完整、Codex MCP 日志与会话自报用量、夹具三方同哈希（`fed5759…`）。
- **解释**：「第二次调用输入骤降」跟随 Harness 的工具结果外溢机制出现/消失，而非模型或服务端行为；原 pair-1 缺口由新运行补齐，原六场原样保留。
- **未排除因素**：思考 token 差异混杂（已登记）；跨 Harness 绝对值不可比（可复制的是增量模式）；Codex 用量为产品自报；缓存语义服务端不披露；每臂 n=1。
- **可复现实验**：机制复制目录预注册 + 双运行器 + 离线分析三条命令可复跑。

### 结论三：SKILL 层单变量消融——两道稳定未达标题上技能层零结果改变

- **观察**：r20261027-ablation 五臂（codex base/skill、dsh base/skill、codex 原生模型臂 gpt-6.1-sol）在 dabstep/tb 两题 reward、weighted、失败项完全一致（如 dabstep 五臂同 0/70.0，同失败 q49/q70/q2697）；技能臂处理真实性有轨迹实证（技能提及 4–10 次，base 臂 0）。
- **证据**：[r20261027-ablation 批](<../3-表现现场/README.md>)（五臂 result.json / meta / 会话轨迹）、[未知登记 skill-ablation 结清记录](<未知登记.json>)。
- **解释**：在两道双 CLI 稳定未达标题上，注入统一技能（零金标泄漏、两臂同文）不改变结果——技能层不是这两题失败的瓶颈；换模型臂同败提示失败更多系任务难度/口径而非模型身份（本批内）。
- **未排除因素**：仅 2/5 题、n=1/格；统一技能内容本身可能无效，不能外推「技能层普遍无效」；思考档 low 固定；历史 n=3（r1025/r1027/r1028）仅作先验不作合并推断。
- **可复现实验**：消融批 README 协议（工作区装配/判分只读/幂等续跑）+ 各臂 result.json 逐格对照。

### 结论四：B 组差异主要在交付路径与检索管控能力（25 格观察矩阵收满）

- **观察**：元宝深度思考档思维链被服务端在约 50–55KB 截断（10/10 会话复现），专家模式为唯一可行交付路径；专家模式五场 clean 口径 2/5 达标（bird 1/93.33、exercism 1/83.33；dabstep 0/40、cargo 0/40.74、lcb 0/0）；WB×LCB 经网络级隔离取得首个有效样本 1/100；豆包默认档 10 场全部记 V（r1029 的 1 场排除系 WorkBuddy×LCB 检索命中，非豆包）；三款桌面产品均无法技术性保证断网，按[落表口径](<../4-打分细则/检索口径-2026-10-27-落表.md>)以三件套（任务书禁网 + 逐会话披露 + 批后实证）执行。
- **证据**：机器账 B12–B24 逐行 adjudication 与 evidence_grade、[integrity 扫描与人工终审收据](<../3-表现现场/README.md>)、B24 沙盒批（`sandbox-exec` deny network-outbound + 白名单代理 + Clash 代理剔除记录）。
- **解释**：B 组与 A 组的可见差异集中在产品层属性——交付路径可用性（深度思考截断）、检索管控能力（不可关闭 → 三件套；WB 需网络级隔离才可达 clean）——而非可归因的模型差异；B 组模型封闭，不参与同模型排名。
- **未排除因素**：元宝/豆包模型 id 封闭不可证；桌面形态与 CLI 形态不可横排；元宝深度思考截断为服务端行为，恢复时间不可控；B24 editorial 接触为 thinking 回忆（已登记判据并如实披露）。
- **可复现实验**：逐会话 `speechesV2[].internetSearch` 披露 + integrity-scan 脚本重扫 + B24 沙盒 profile/代理白名单重放（工具档案见私有入口，公开侧为派生说明）。

### 结论五：判卷合同缺陷与产品能力可分离（BIRD v1.2 并入 / DAB q2697 撤出归因）

- **观察**：BIRD q26 题面「免费或减价餐」与金标「仅免费餐」字段不一致——修正合同并入正式 v1.2（5 所→6 所），自测 25/25 含负例，10 场历史有效运行逐题回放仅该题翻转、二值达标全部不变（含一场对转错的如实披露）；DAB q2697 题面字段歧义——维持官方兼容判分，该题通过与失分一律撤出能力归因（实测六组格式负例现行判卷全部放行为技术依据）。
- **证据**：[判卷审计 2026-10-26（bird-q26 并入）](<../4-打分细则/判卷审计-2026-10-26/bird-q26-并入/README.md>)、[DAB q2697 裁定](<../4-打分细则/裁定-2026-10-26-dab-q2697.md>)、checker `--selftest` 收据。
- **解释**：判卷器修订按全套纪律执行（修前/修后代码、正例、近似错误例、独立验收、历史复算影响），历史分与四元组不回写；题面-金标缺陷须与产品能力分离，否则归因被判卷噪声污染。
- **未排除因素**：q27 经机器验证金标自洽但标注为已知尖角；BIRD 官方 gold 本身的语义权威不可证；合同敏感性行另列，不并入主表。
- **可复现实验**：五题 `checker.py --selftest` + 判卷审计目录的修前/修后回放脚本。
