# 树重定位：成功编辑不等于验证闭环

> **事后、零产品发射的派生纯算法研究（2026-11-15）。** 只复算这里披露的代码字节，不重新评判正式运行或修改历史分数；不是私有原始轨迹、完整历史封印或 Harness 因果认证。

## 1. 问题与当前判断

树的换根应改变父子方向，却保留无向相邻关系。一次编辑修正了“仍返回原根”的错误，是否也恢复了整棵树的拓扑？当前证据支持**部分修复，而非完全修复**：前版 canonical 15 项中通过 5 项，后版通过 12 项；深层祖先仍错误地并列挂到目标根下。

| 安全派生版本 | canonical 通过/运行 | 独立换根不变量通过/目标 | 独立路径通过/节点对 | 错误类型与消息通过/检查 |
|---|---:|---:|---:|---:|
| 编辑前 | 5/15 | 4/16 | 16/90 | 12/12 |
| 编辑后 | 12/15 | 10/16 | 67/90 | 12/12 |
| 参考实现（实际复验） | 15/15 | 16/16 | 90/90 | 12/12 |

这不是对所有树的统计估计。结论限于唯一标签、所列小型树和当前代码；不扩展到重复标签、超深递归或一般产品能力。所有版本在本次调用后均保持输入树结构不变；未检验返回树与原树完全不共享对象。

## 3. 能区分解释的最小反例

### 编辑前：边仍在，根错了

输入为 `A—B—C`、原根 A、目标 C。前版从目标开始重建，却每轮执行 `Tree(original.label, siblings + [rebuilt])`，最终仍把 A 设为根。因此，保留了无向边 A—B、B—C，也不等于正确换根。单看边集合会漏检这一错误。

### 编辑后：根对了，深层边错了

后版创建 `parent_node`，但每轮都执行 `Tree(rebuilt.label, list(rebuilt.children) + [parent_node])`。目标标签 C 保持为根；B 与 A 却成为 C 的并列子节点：

| 目标 C 的检查 | 合同真值 | 编辑后观察 |
|---|---|---|
| 根 | C | C（正确） |
| 无向边 | A—B、B—C | A—C、B—C（错误） |
| C 到 A 路径 | C、B、A | C、A（错误） |

浅层（目标深度 0/1）的 10 个目标全部通过，深层（2/3）的 6 个目标全部未满足完整换根不变量。带兄弟、堂亲的分支树也出现同类原边改变，排除了“只要新根正确即修复”的解释。参考实现沿 `current.children.append(new_parent); current = new_parent` 逐层延伸反向链，并经同一独立 oracle 实际通过；这不是把参考输出当真值。

独立 oracle 从输入嵌套结构建立无向邻接表，BFS 给出所有节点对路径；**不调用任何候选的 `_find_path` 或 `from_pov` 来建立真值**。四棵树为单点、三子浅树、三点链、带兄弟/堂亲的 8 点树，共 16 个目标、90 个原树有序节点对。每次换根后另对输出图全节点对比较，同时检查根、节点集、边集、边数、连通性及原树不变。

## 4. 反馈—编辑—复验：哪些能说，哪些不能

归档中的失败反馈属于**编辑前**：列出 10 个失败 ID；当前前版复算的 10 个 ID 与之相符。随后浅层诊断显示根仍为原父节点；再发生编辑及成功写入回执。这支持“针对根标签错误作修补”，不支持“修补已完全验证”。该 65 记录局部快照末尾是编辑成功回执，未见其后的复验或终答；**不能推出后台从未继续、没有产物、也没有其他导出**。

当前后版的三个失败 ID 为：

- `test_can_find_path_to_cousin`
- `test_can_reroot_a_complex_tree_with_cousins`
- `test_can_reroot_a_tree_with_new_root_deeply_nested_in_tree`

[既有正式摘要](<3-表现现场/r1102-formal-b2/runs/doubao__exercism-py-6/checker.stdout.json>)记录 POV 运行 15、成功 12、失败 3、错误 0，并保留 **`identities_match=false`**；没有逐失败 ID。[旧评分收据](<3-表现现场/r1102-formal-b2/runs/doubao__exercism-py-6/score-receipt.json>)中的 `checker` 与 `checker_command` 指向也不一致。此处不修旧记录、不猜其成因、不据此复原正式身份。

因此，“当前也是 12/15”仅是**计数一致**；这三个**当前**失败 ID 不冒称当年三个失败的已认证身份。旧元数据仅记文件尺寸而没有当时源码哈希，当前字节相符和现存归档重建不能补齐历史原件认证。完整私档真实性与取样覆盖仍有公开无法验证的缺口。

## 5. 复核、反证与结论边界

在仓库根目录运行（Python 3.9+，仅标准库；每份算法子进程限时 8 秒）：

```sh
python3 -I -S -B '5-评测报告/树重定位与补丁验证-2026-11-15/verify.py' --optimize 0
python3 -I -S -B '5-评测报告/树重定位与补丁验证-2026-11-15/test_verify.py' --optimize 0
python3 -I -S -B -O '5-评测报告/树重定位与补丁验证-2026-11-15/verify.py' --optimize 1
python3 -I -S -B -O '5-评测报告/树重定位与补丁验证-2026-11-15/test_verify.py' --optimize 1
```

父解释器 `-O` 不自动传给子解释器，所以子优化档必须显式选取并校验。作者曾实际执行验证器的前一版（6005 字节，收据哈希 `475f512f…`）并通过两档；其后验证器被改动 205 字节，前一版字节未归档、无法逐字回放，故当前版本不冒称作者亲验。当前验证器（6210 字节，`8138ac7b…`）已由非作者于 2026-11-16 复算执行：普通/优化两档 [30 个验证测试](<5-评测报告/树重定位与补丁验证-2026-11-15/test_verify.py>)分别通过，固定结果两档一致。覆盖字节近错、前后版本调换、测试改动、布尔/整数不混同、环/重复标签拒绝、浅深负控、参考失败和超时分支。超时/执行不可用保留 unknown 与 null；不能填 0，更不能取得比较通过。这里测试的是纯算法实验设施，不是 mock 产品。

复算在临时目录中仅执行已读、固定哈希的纯模块与测试副本；`-I -S -B` 不代表恶意代码安全沙箱。公开验证只认证**所披露派生代码、表和计算逻辑的内部一致性**，不是全部文档字段的封印，也不认证未公开私档或历史运行。若代码/测试身份改变、参考未通过或子进程不可观察，必须拒绝或保留未知，不为维持当前结论调 pin。

**结论：** 在当前派生载荷上，“完全修复”受到反证，“根标签修复但深链拓扑仍错”获得代码与多反例的有限支持。源码错误与一次局部复验缺口均不足以归责为 Harness 根因。正式 25 格及本场原分不变；成本、后台继续情况和历史逐失败身份不由本研究推定。
