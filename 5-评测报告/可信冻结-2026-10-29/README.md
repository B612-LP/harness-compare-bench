## 解释

[冻结合同与操作说明](<../../4-打分细则/可信冻结-2026-10-29/README.md>)、[配置](<../../4-打分细则/可信冻结-2026-10-29/config.json>)、[schema](<../../4-打分细则/可信冻结-2026-10-29/import-schema.json>)、[验证器](<../../4-打分细则/可信冻结-2026-10-29/freeze.py>)和[封条](<../../4-打分细则/可信冻结-2026-10-29/freeze.lock.json>)共同约束新正式运行。

历史缺失版本、规则冻结与预注册信息不能用现在的配置 hash 倒填。原 `main_table_eligible`、V、clean、判卷 reward 都是不同轴，不自动满足新版规则冻结＋题面有效＋可复核评分＋有效证据＋无污染五门。每门都要明确出处；分数也要原始评分收据 SHA、规则及 checker 身份，不按已评部分折满。

DAB2697 的兼容分保留，题面／聚合／金标歧义仍禁止能力归因，不因停止调查就把混杂排除。本表没有把研究结果转成官方能力排名。

## 未排除因素

- 历史自测／复算／回归／接口预检并不完整，只登记能定位的事件；未登记不等于从未执行。覆盖截止与范围见汇总，后续独立验收不循环回灌成“冻结前完整计数”。
- 84 条私有引用不是公开证据包；不读取 home 补齐、不把源 hash 列表等同拿到原件。
- 10-27 归档复算原脚本存在私有 fallback，故这里只称既存归档，不冒认本轮 fresh-copy 公共重判。当前分数 unknown 不等于不能另开公有复算。
- 精确 pointer 与 SHA 只能验证可定位、值绑定和完整性，不自动证明语义无污染、裁定正确或因果混杂已排除。
- 本地可写封条不是数字签名；需要外部可信代码／封条版本锚点来识别“代码＋配置＋封条”一并改写。

## 可复现实验

在仓库根目录执行：

```sh
python3 -B 4-打分细则/可信冻结-2026-10-29/freeze.py verify
python3 -B 4-打分细则/可信冻结-2026-10-29/freeze.py build --output-dir 5-评测报告/可信冻结-2026-10-29/rebuilt
python3 -B 4-打分细则/可信冻结-2026-10-29/test_freeze.py
```

先 verify 已发布物，再重建，避免先 build 掩盖发布物漂移。导入列表和文件 SHA 保存在[构建配方](<build-recipe.json>)，完整确定性产物指纹见[产物清单](<output-manifest.json>)。仅标准库，不发模型请求、不联网、不写历史原件；可在空 HOME、拒绝原仓和私有目录、禁止网络的公开 fresh copy 中复验。

负例涵盖：缺字段、源哈希漂移、错误事实 pointer、污染、题面无效、版本未冻、完整 inputs 变化、重复 event_id／原始 run_id、研究身份篡改、重试择优／上限、遗漏预注册事件、另换计划冒充首样、部分评估折满、完整分母篡改、未知无管理与混杂三轴混淆。合成正例只测试准入机制，不伪造实际产品场。
