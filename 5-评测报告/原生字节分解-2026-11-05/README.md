# 原生请求字节差的精确组成与账面敏感性

## 一、观察

对[原生来源链现场](<../../3-表现现场/r20261104-native-provenance/README.md>)已有 **3 block / 6 场确认数据**作事后分解，不增加样本，不与同 DSH 六对合并为 n=9。原 `D = ΔB_input(Codex) − ΔB_input(DSH)` 仍为 **10382 / 10005 / 10351 bytes**；3/3 为正、中位数 10351、原预注册阈值 4096 及方向分支全部不变。

把已解码返回文本的长度差 10040 bytes 从各块 D 中作**纯代数减法**，余 **342 / −35 / 311 bytes**。第 2 块反向是账面敏感性反例，不是控制后效应，也不推翻原观察。[报告 v1.8](<../竞品评测报告-v1.8.md>)已经披露双方返回均截断及条件不等；本页新增的是各层精确闭合，不把该已知限制重算成新机制发现。

## 二、证据

## 三、解释

采用与[原指标定义](<../../3-表现现场/r20261104-native-provenance/projection_protocol.py>)相同的 canonicalization：

```python
J(x) = json.dumps(x, ensure_ascii=False, sort_keys=True,
                  separators=(',', ':'), allow_nan=False).encode('utf-8')
```

被选字段为 Codex 的 `instructions/input/tools/previous_response_id` 中实际存在者，或 DSH 的 `system/messages/tools`。设返回历史整项为 U，其中实际文本叶子为 `t_1…t_m`，前面追加的模型侧历史项为 `a_i`：

```text
L = Σ |UTF8(t_j)|
Q = 2m
E = Σ (|J(t_j)| − |UTF8(t_j)| − 2)
R = |J(U)| + 1 − Σ |J(t_j)|
A = Σ (|J(a_i)| + 1)
ΔB_input = L + Q + E + R + A
```

原历史列表非空、前缀逐字 canonical 不变、其他被选字段及存在性不变时，每个追加列表项贡献 `|J(item)|+1`，其中 `+1` 是一个新增逗号。R 含返回项的逗号及类型、身份、text-block/list 等包络，但**不再含文本叶子的 JSON 标量**；A 含各模型侧项及其逗号。Codex 的 `reasoning/function_call` 是模型侧历史而非带 `role=assistant` 的通用消息；DSH 则有真实 assistant 消息。该划分不重复计数。

两类残差只是同一三块数据的事后账面展示，不是两个额外预注册检验。特别是 4096 阈值**只适用于原 D**，不迁移给残差；−35/−152 也不证明协议效率方向反转。

## 四、未排除因素

- L 包含原生返回的时间/截断包装或结果引用页脚，不是原始 fixture 的保留字节数；A 包含可见文本、opaque 字段和调用结构，不是实际思考 token。
- 原菜单/协议/输出上限不等、实际 thinking/cache 未控、客户端/模型组合差异仍在。因此不能从分解或残差推断纯 Harness 因果、协议效率、token/成本、服务端最终输入或跨产品总排名。
- 固定 hash 只认证受信验证器所认识的**公开快照**，不认证私档、后端身份或第三方见证；第三方见证仍 pending。此工具不重新执行完整 SSE/技术门协议，原门状态只是固定源里的已有记录；其独立完整复算入口仍为[原验证器](<../../3-表现现场/r20261104-native-provenance/verify.py>)。
- 相同长度且合法 schema 的文本替换，单靠算术不能识别；固定源层会拒绝。若把本验证器及其固定锚也协同替换，已越过其信任边界。正式 25 行、n、旧预算及历史未知均不升级。

## 五、可复现实验

Python 3.9+、仅标准库；在仓库根执行以下命令。默认只读、stdout 返回结果；`--root` 可指向另一仓内快照，不运行产品、模型、候选、checker、历史 runner，不发网络请求，也不导入旧规范源码。

```bash
python3 -I -S -B 5-评测报告/原生字节分解-2026-11-05/verify.py --root .
python3 -I -S -B -O 5-评测报告/原生字节分解-2026-11-05/verify.py --root .
python3 -I -S -B 5-评测报告/原生字节分解-2026-11-05/test_verify.py
python3 -I -S -B -O 5-评测报告/原生字节分解-2026-11-05/test_verify.py
```

2026-11-05 实测：两次 CLI 均 exit 0、`PASS_PUBLIC_BYTE_PARTITION`，stdout 逐字节一致；[测试](<test_verify.py>)普通与 `-O` 均 **22 tests / OK / exit 0**。测试只在临时副本造负例，分固定锚与直接语义两层：覆盖 22 个源逐个篡改（含全部 6 个 metric 源）、同长度 assistant 替换后重封、来源/指针错配、空/漂移前缀、被选字段及 controls 改变、伪 assistant/重复返回、call ID/schema/字符串数错误、UTF-8/引号/转义、虚拟拼接标量仍闭合的错误分配、重复计数/删组件、残差或阈值偷换、JSON 重复键/非有限数/布尔数值混淆、缺件与路径/符号链接逸出；正例限制写盘/网络/子进程并核对前后文件 hash。

[只读验证器](<verify.py>)先验 22 个固定源 hash，再从公开请求独立重算完整原 metric 与观察值对应、严格确认真实追加 schema，最后重建全部派生并与[派生 JSON](<decomposition.json>)精确比较；不是只验派生自封 hash。负例通过表示这些造假被拒绝，不表示原始历史或未观测因果被补证。
