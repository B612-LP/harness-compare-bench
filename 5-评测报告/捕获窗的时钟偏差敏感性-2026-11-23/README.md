# 捕获区间包含对时钟偏差有多敏感（11-23）

复用 [三组 Chat 停止归档](<../../4-打分细则/Chat停止与本地轮尾-2026-11-23/README.md>)，只取六份捕获计时收据与三份本地轨迹；不读请求或响应正文。三条主请求和三条辅助标题记录，按封内给定端点，旧口径仅将代理端点向下取整到毫秒、精确到微秒的闭区间及不允许同点的严格顺序这三种口径，均有 **6/6** 数值包含。主请求有直接共享的记录键；标题定位沿用此前核验，没有新增直接共享键或重验标题引用链。

| 假设的误差方式 | 可以保证包含 | 仍可能包含，但不保证 |
|---|---:|---:|
| 每条记录四个端点各自可在 ±1 ms 内移动 | 4/6 | 2/6 |
| 本地端点固定，同组主辅的四个代理端点加同一个 ±1 ms 内的偏移；各组单独判断 | 1/3 | 2/3 |
| 同一恒偏移模型放宽到 ±5 ms 或 ±10 ms | 0/3 | 3/3 |

判定完全基于固定端点和假设误差。独审复核了 1,999/2,000 µs 的独立误差边界，还验证了合成对照的预算边界：唯一可行偏移为 +1,000 µs 时，±1 ms 内仍可能包含；为 +1,001 µs 时则不能。错路由、时间倒序或记录错位即使还可读到数字，也不给合格裁定。数值包含不能证成共享时钟、真实偏差、任务时长或 Harness 因果效果。
