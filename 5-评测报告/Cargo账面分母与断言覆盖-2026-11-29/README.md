# Cargo：账面评估数不等于可见断言覆盖

固定旧正式五格都记 `possible=assessed=27`，历史二值均为 0。其中**元宝一格的收据止于结构门，没有内容断言结果；另外四格各有 27 条内容结果，均过数量线，但未过关键项**。因此旧零分不能直接解释成内容全错，也不能用来区分结构早退与内容失败。不改分、不补判。

## 分开三种计数

- **名义分母 P=27**：[冻结判卷规则](<../../2-用例/tb-cargo-plan/checker.py#L381-L417>)过滤输入检查、代码复跑、方案结构三个前置条目。`finish` 判二值 1 的条件是过滤后行数恰为 27、通过的行数至少为 20、五个关键 ID 各有通过记录，且未被强制置零；它不校验完整 ID 集或顺序。前两个门早退时显式强制置零；结构门停止时过滤后行数为零，二值也是 0。
- **账面 A**：取同槽计分收据的 `score.assessed`。字段未写就记缺，不用 27 代填。
- **可见覆盖 C**：在绑定到登记槽的逐项记录中核对前置门路径和冻结源码规定的有序唯一内容 ID；这是证据复核条件，不是 `finish` 的输入校验。不能按条数、得分或 `reward` 猜。见到结构门明确停止且没有下游行时，C=0；逐项记录缺失则 C 未知。C=0 时，内容阈值、关键项真值和 `通过数/C` 都未定义；旧 `weighted=0` 不是内容准确率 0%。

## 旧记录勘误与取证边界

- [旧失败剖面](<../失败解剖与裸底数-2026-11-03/failure-taxonomy.md#L42-L53>)写「下游 26 项」。冻结源码和完整收据都有 **27 个不同的内容 ID**；这里勘误，保留旧页和历史成绩。`route=6 legs=5` 只记录长度；[结构门](<../../2-用例/tb-cargo-plan/checker.py#L209-L226>)还查归一后的摘要类型、顶层键集和首段必需键。长度正确不能指认是哪项导致失败，更不能判断下游内容。
- 一份[收据的 `checker` 字面路径](<../../3-表现现场/r1104-formal-b3/runs/doubao__tb-cargo-plan/score-receipt.json#L9-L13>)指向另一题；同槽命令、冻结指纹和逐项 ID 支持它是 Cargo **记录**，不认证历史实际启动程序。另一份[旧 stdout 摘要](<../../3-表现现场/r20261031-wb-replacement/runs/tb-cargo-plan/score-receipt.json#L33-L43>)不匹配当前格式化的公开字节；同一 JSON 值保留键序序列化为单行可复得旧行摘要，再加一个 LF 可复得旧整串摘要。两种表示相容，不等于找回经认证的原档，也不重写摘要。
- 合成对照保留相同的 `assessed=27`、通过数 0 和二值 0，既可表示结构早退，也可表示 27 项齐全但全未过。另一个对照即使有全部 27 个正确 ID，第一前置门失败后仍跟有内容也不是这份规则的正常执行路径。完整 ID 与可达门序是两项检查。

复核固定 33 个公开输入，核 Git 字节与摘要；项目内非作者先独立计算，再按登记槽对比，196 个已对齐的字段值无实质差异。只读旧记录和静态源码，没有执行候选、判卷器或参考实现，也没有新产品试验。这不认证历史进程、隔离或真实读取，不替代外部第三方核验。
