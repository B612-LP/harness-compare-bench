# 字段选取与路线可达性

## 1. 结论：一条预定路线能呈现字段，不是 Agent 自主恢复

在这一对已知合成源上，脚本通过 DSH 原生 `bash` 工具，执行通用字段匹配命令，分别得到 **72 字节解码文本**：`TARGET=`、完整 64 位十六进制字段以及末尾 LF。两份实际输出均与对应源逐字一致，原生事件与下一份请求中的工具结果一致。

科学样本是 **1 个 confirm 会话中的 2 次非独立工具调用**，不是两次独立重复。另有 1 个只取原生声明的 catalog 会话；合计 2 个新会话、4 次本地请求、2 次 `bash`、0 次 fixture 回调、0 次真实模型调用、0 次上游转发。脚本预定工具和参数，没有测 Agent 会不会自主选择这条路线，不能计为自主策略成功或产品排名。

本包提供选定证据及一致性复算；科学有限复核的哈希承诺列于[证据表](<evidence.json>)，不把它扩张为对完整运行时或所有过程的认证。

## 2. 证据：源、原始返回文本与观测面分列

| 源别名 | 安全合成源 | 实际解码返回文本 | 源与返回关系 |
|---|---|---|---|
| A | [A.txt](<sources/A.txt>) | [A.txt](<outputs/A.txt>) | 完整字段 + LF，72 B |
| B | [B.txt](<sources/B.txt>) | [B.txt](<outputs/B.txt>) | 完整字段 + LF，72 B |

两源各 16000 B、ASCII、单行且没有 LF；只有字节偏移 8007 从 `0` 变为 `8`。字段位于半开区间 `[8000,8071)`。源本身是可公开的合成材料，**原字节未改写**，故源的 original/derived 哈希相同，并明确标为 `safe_synthetic_bytes_unchanged`。两份返回文本直接取自实际 Native 事件和原始请求工具结果，不是根据真值重建的回答。

[证据表](<evidence.json>)保留两项逐调用记录：原始 text 列表 schema、`is_error:false` 的原有存在性、Native `completed` 事件与无 `truncated` 字段的实际形态，以及所选 user 消息位置 `[2,4]`。它还分列 4 份请求的 **raw 请求体 hash、格式化 JSON 文件 hash、规范 JSON 值 hash、SSE hash**。这些是私档承诺；72 B 不是 HTTP 请求体长度，更不是 token 或成本。

实际路径和调用 ID 分别替换为等 UTF-8 长度的完整别名，原始字符串、原始参数/事件/块的哈希与派生参数哈希分列。匿名路径不是可执行路径或物理对象身份证明。未公开完整初始上下文、会话标识、私有目录、凭据、PID 或 FD 身份。公开校验器无法只凭哈希认证未公开原件。

## 3. 解释：先选字段，呈现面随之改变

命令的结构是 `/usr/bin/grep -oE 'TARGET=[0-9a-f]{64}' -- <源路径>`；模式没有填入具体答案。与先呈现长行再裁剪的路线不同，这条原生 `bash` 路线先产生很短的字段文本，才进入工具结果呈现。观察支持“本例存在能呈现完整字段的预定路线”，不支持“此前短投影没有丢信息”，也不等于全工具、全上下文透明。

默认权限仍为 `workspace-write/ask`，没有覆盖原生工具 cap；但控制面不是完全等控：本次原生菜单为 7 工具，上一个带两个 fixture 的菜单为 8 工具；默认系统文字仍建议优先使用 `grep` 而非 shell。工具及命令由控制脚本固定，不能归因于模型作出了更好的决策。

这对候选只有已知 `0/8` 差异，结合候选映射，一个区分位就足够确定成员。返回文本虽然含有 64 个十六进制字符，**并不证明新获得了未知 256 bit**，更不证明恢复了一个完全未知的 64 位密钥。此前局部 `Read`、`grep` 呈现反例和各自条件化布尔信息界不因此撤销；本次没有执行 256 次查询。

## 4. 限制：严格接受计数不冒充活动计数

冻结判定要求两个结果都完整正确、来源稳定、协议/Native/结束与清理门全部通过才接纳数据；否则是 `unknown`。因此本实现可达的是“2 项完整正确”或“unknown”，**没有覆盖有效 0/1 项的反证分支**。unknown 时观察活动数为 null，完整接纳行数 0 只是验收计数，不表示没有发生调用。不能把这种只接纳完整正例的设计当作 0/1/2 分支都已验证。

`numeric_inner_exit_code_observed:false`、`inner_exit_code:null` 始终保留。`renderer_inferred_zero` 是渲染契约推断；Native `completed`、外围进程退出 0 和没有错误标记，都不等于观测到了内层数字退出码 0。清理记录仅涉及此次拥有的进程组 token 的缺席回执，不认证全部进程树或后台活动。

没有真实模型比较、随机独立重复、未知字段信息量估计、token/成本等控、完整上下文碰撞证明、通用恢复能力或产品排名。已披露的失败、未知和既有观察面限制不因这两个正例而改写。源码封印、有限科学复核、选定派生包的一致性复算，是三个不同范围。

## 5. 公开离线复算

在本目录运行 Python 3.9 或更新版本，仅用标准库：

```sh
python3 -B verify.py
python3 -B test_verify.py
python3 -B -O test_verify.py
```

[校验器](<verify.py>)重算两源哈希、唯一差异、字段区间、两份实际文本及 LF，核对逐调用 schema/ID/位置/Native 对应、类型严格的计数与内层退出码边界、源/派生哈希分列和精确九文件清单。[测试](<test_verify.py>)包含改源后重哈希、把 A 返回连同 Native/请求块一起移给 B、漏 LF、错误结果或丢 `is_error`、伪造退出码/清理/计数、缺失或重复记录、原始与派生混淆、隐私残留和清单/符号链接反例；关键检查不依赖 `assert`，优化模式同样执行。

[SHA256SUMS.json](<SHA256SUMS.json>)覆盖其余八文件；校验器另嵌证据值的一致性承诺。它们不是对未公开原件的独立真实性证明。三个命令只读取本包，不发起请求、不运行被测 CLI/selector、不联网、不写回原件或产品状态。
