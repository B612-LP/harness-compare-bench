# 产品同对象同窗读取配对：DSH / WB / Codex / 豆包 四臂（2026-11-19）

第五轮反馈第 4 条要求读取检测先构造**同对象、同时间窗**的真阳/真阴配对，配不上报未知、不估召回。前一篇[非产品夹具校准](<../同对象同窗读取检测校准-2026-11-19/README.md>)只完成仪器与判定语义；本次把同一夹具协议绑定到**产品真实测试任务**：同一对 512 B 合成夹具（`0600`，预先固定字节与 SHA-256，设备号与 inode 预先登记）在产品工作区内，两臂同窗在场：正臂任务读 fixture-a 并报 SHA 前 16 字符，负臂同形任务只读 fixture-b。判定规则在发射前预注册（PREREG）：正臂出现夹具 a 的 FD 精确匹配计真阳检出；负臂 fixture-b 出现且 fixture-a 全程未见计真阴（fixture-b 即灵敏度正控）；负臂误见 fixture-a 将记对象错绑（本次未出现）；任一未知按配对未知处理，不点估计召回率。

## 对象与运行

三个产品臂各在隔离配置下实跑：DSH CLI 用独立 `DSH_HOME` 基准档案（无个人技能/指令注入）；Codex CLI 用独立 `CODEX_HOME`；WorkBuddy 桌面 5.9.5 经原生测试入口（精确会话与请求 ID 对账）；豆包工作桌面经原生 UI 链路动词逐步对账（模型 DeepSeek V4.1 Flash/低，本地执行在独立 XPC 常驻树 AgentInfraService→file_utils_host，root 覆盖按「命令含 DoubaoWork.app 且 ppid=1」全家族闭包）。每臂运行由同一台非 root 采样机观察：kqueue `EVFILT_PROC`（fork/exec/exit）唤醒 + 后代闭包 FD 表扫描（libproc 用户态接口，C 级单 pass 约 3.5 µs/PID，事件后突发迭代约 1.1 ms）。精确匹配判据 = FD 记录内设备号与 inode 双匹配（与 lsof `DEVICE`+`NODE` 判据等价）；路径/模式/大小为辅证，辅证丢失不降级。内容真值独立：产品答案中的 SHA-256 证明读取确实发生，检出与否则只由 FD 观察决定。

## 分层结论：检测面可用性按读者形态，不按产品

- **进程内多段读**（DSH 的 node read 工具、WB Electron 直接持有 FD）：窗口毫秒级，~1.1 ms 迭代下可靠检出；两臂配对可闭环。
- **shell 工具链读**（`zsh -c 'cat … && shasum …'`）：夹具 FD 持有窗口亚毫秒（打开-读-关一气呵成；解释器启动的读在其生命末段），同等仪器下 8 次受控独立链重放命中 1 次，产品内正臂 0/4、负臂 1/4——可检但概率性，配对多记未知。
- 仪器地板本身是规范事实：非 root 用户态 FD 观测对亚毫秒窗口存在结构性漏检；`unknown` 分支保留，不折算为召回率或污染上界。
- **常驻执行器读**（豆包 AgentInfraService/file_utils_host 家族）：同一产品两次运行呈现两种可检性——短命 shell 子进程以 stdin 重定向持有夹具（约几十毫秒窗口）被检出 1 次（真阴正控满足）；守护进程内读在 7659 个全家族闭包 pass（~1-4 ms/pass）中零观察。可检性取决于执行器当次的读法（子进程 vs 进程内），不取决于读取是否发生——两次读取都有证据级真值。

## 尺寸敏感性探测（同日追加，Ring 5）

把唯一变量换成夹具尺寸（512B → 8 MiB 随机字节，提示词同形，DSH/豆包预注册在先、Codex 与全部 s2 为标注后的同配置重复）后，三种读者形态全部进入可靠可检区（判定规则与预注册见私有档案；fd 持有者全部为执行器家族的摘要工具子进程，fixture-a 全程 0 见，对象错绑 0/6）：

| 臂 | 8 MiB hits（两轮） | 同臂 512B 对照 |
|---|---|---|
| DSH CLI | 20 / 18 | 概率性（三对中 1 对检出） |
| Codex CLI | 37 / 35 | 0 检出（四对全未检出） |
| 豆包桌面（全家族 roots） | 8 / 9 | 正臂 0 检出、负臂 1 检出 |

结论：可检性由 **FD 持有时长**主导（8 MiB 摘要计算持有 fd 数十毫秒），不由读者形态主导；512B 尺度下的「形态差异」本质是窗口长度差异，豆包正臂 512B 零检出不是结构盲区。守护进程内读路径在任意尺寸下的可检性仍未单独验证（本探测证明的是家族子进程摘要路径），该边界如实保留。仪器地板语义收窄：约 1.1 ms 地板只对亚毫秒 FD 持有构成结构性漏检，毫秒级以上持有可靠可检。

## 尺寸矩阵补全、纯内容读与检出率（同日追加，Ring 6-8）

三项后续把第 6 节的统一律补成四臂矩阵并剥离混淆变量：

- **WB 臂 8 MiB**（两轮 8/15 检出，持有者同为沙箱内摘要工具子进程）：四臂尺寸矩阵补全——DSH 20/18、WB 8/15、豆包 8/9、Codex 37/35，全部 size-sensitive-detect，统一律（可检性由 FD 持有时长主导）四臂成立。
- **纯内容读路径**（提示词明说不要哈希/摘要，剥离摘要工具混淆）：512B 内容读真值逐字节成立但 0 检出（亚地板）；8 MiB 内容读真值成立（字节数 8388608、首/末 16 字节十六进制均与 xxd 一致、明说未计算哈希）且 **1 检出**——内容路径自身在长窗口下可检，但显著窄于摘要路径（8-37 hits），量化差如实记录。
- **DSH 512B 检出率定量**（同配置 20 跑，真值 20/20）：单跑检出 **13/20 = 65%**，Wilson 95% CI ≈ [41%, 83%]——512B 的漏检是常态成分而非尾部；独立链重放 1/6 与产品臂 13/20 的差异证明检测敏感度必须按产品实测、不能互换外推。检出率是给定读取已发生时的检测面敏感度，不折算召回，512B 协议判定不改判。

## 尺寸尺度负控与错绑检查（同日追加，Ring 9）

新造 8 MiB 负控夹具（独立 inode，SHA 预记录）并让负臂读取它、正臂 8 MiB 夹具同窗在场监控，把尺寸律补上极性维度：DSH 两轮（18/19 hits）与 Codex 一轮（37 hits）的全部命中都精确落在负控夹具 inode 上，正臂夹具与 512B 夹具全程 0 见，三跑真值独立成立（答案报出的 SHA 与负控夹具预记录一致）——三跑均 **true-negative-detect-at-size**，对象错绑 0/3。结论：对象绑定在两尺度（512B/8 MiB）× 两极性（正/负）下均未见错绑；8 MiB 读入的摘要子进程 FD 持有在两 CLI 臂稳定可检，与统一律一致。豆包臂不参与本环（其常驻执行器读路径与遗留会话状态如实保留，见前节边界）。

## 纯内容路径检出率定量与协议包排练（同日追加，Ring 10 / Ring 3 排练）

- **纯内容路径 512B 检出率定量**（提示词明说不要哈希、报最前/最后 16 字节，DSH 同配置 n=10，真值 10/10）：检出 3/10 = 30%（Wilson 95% CI 约 [11%, 60%]），命中全部精确落在目标 inode，对照夹具 0 见。与摘要路径同尺寸定量（13/20 = 65%，CI 约 [41%, 83%]）并列：点估计方向与纯内容读窗口更窄一致，但两组样本量小、区间重叠，**不声称两路径差异统计显著**。
- **纯内容路径检出率跨臂补全与一次证伪**（Codex 臂同协议 n=10，真值 11/11 含冒烟跑）：Codex 内容路径检出 **8/10 = 80%**（Wilson 95% CI 约 [49%, 94%]），命中全部精确落在目标 inode——其同产品摘要路径 512B 此前四对全未检出，**预注册方向预测被推翻**：提示词类型不等于读取实现，产品按提示词选择不同工具链，可检性仍由所选实现的 FD 持有时长决定（统一律被强化而非推翻）；跨臂内容率点估计（DSH 30% vs Codex 80%）进一步证明检测敏感度必须按「产品 × 提示词」实测。n 小不声称显著差异。
- **采样根配置敏感性（WB 臂，n=10×2 序列）**：同一产品、同一内容提示词、同一夹具与完成判定，仅事件采样根不同（渲染层 node 辅助进程 vs Electron 主进程+sandbox-center），检出率 0/10 vs 4/10 = 40%（Wilson 95% CI 约 [17%, 69%]，真值 10/10，绑定 0 错）——检出率是检测器采样配置的函数。结合「提示词不等于读取实现」，检出率测量须登记（产品 × 提示词 × 采样根集合）三元组，缺任一维的率不可比。
- **受控第三方协议包排练**：三链核验协议包由内部非作者代理在硬隔离作者结论条件下完整排练一遍，9/9 项与登记一致（0 disagree、0 cannot-verify）；排练暴露六项协议缺陷（登记值来源未入移交集、一处事实不可字节直推、格式规则来源节未限定、pins 无基路径且盘上有同名副本、交叉对照时序条款冲突、无中断恢复检查点），已修订为协议包 v2。**内部排练不充作外部第三方验收**，公开状态仍为「待执行」。

## 边界与不外推

运行器源码、原始 ev.jsonl、PREREG、逐 pass 时间线与原始 PID/FD/设备/inode 在私有档案留存，不在公开仓发布；本页为结论账与判据描述。三次 DSH 配对使用同一隔离档案的独立发射；WB 经桌面原生入口；Codex 三对中真值成立但检出侧以未知为主；豆包经原生 UI 链路动词逐步对账（发射前失败尝试与适配器修复全部留档，读取准入修复不弱化内容绑定：仍要求精确提示词哈希绑定的回合证据 + 单一真实会话路由 + 渲染/轨迹回复合一），其正臂真值成立但常驻执行器读不可检、负臂真阴闭环。本页不改正式 25 格、不认证任何 Harness 因果效果、不报产品召回率或污染上界；非产品夹具校准的结论（FD 有无不区分实读与仅打开）对产品配对同样适用：FD 检出证明「该产品进程在该窗口持有该对象」，不单独证明读取语义，读取语义由独立真值层承担。
