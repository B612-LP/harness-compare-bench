# 产品同对象同窗读取配对：DSH / WB / Codex 三臂（2026-11-19）

第五轮反馈第 4 条要求读取检测先构造**同对象、同时间窗**的真阳/真阴配对，配不上报未知、不估召回。前一篇[非产品夹具校准](<../同对象同窗读取检测校准-2026-11-19/README.md>)只完成仪器与判定语义；本次把同一夹具协议绑定到**产品真实测试任务**：同一对 512 B 合成夹具（`0600`，预先固定字节与 SHA-256，设备号与 inode 预先登记）在产品工作区内，两臂同窗在场：正臂任务读 fixture-a 并报 SHA 前 16 字符，负臂同形任务只读 fixture-b。判定规则在发射前预注册（PREREG）：正臂出现夹具 a 的 FD 精确匹配计真阳检出；负臂 fixture-b 出现且 fixture-a 全程未见计真阴（fixture-b 即灵敏度正控）；负臂误见 fixture-a 将记对象错绑（本次未出现）；任一未知按配对未知处理，不点估计召回率。

## 对象与运行

三个产品臂各在隔离配置下实跑：DSH CLI 用独立 `DSH_HOME` 基准档案（无个人技能/指令注入）；Codex CLI 用独立 `CODEX_HOME`；WorkBuddy 桌面 5.9.5 经原生测试入口（精确会话与请求 ID 对账）。每臂运行由同一台非 root 采样机观察：kqueue `EVFILT_PROC`（fork/exec/exit）唤醒 + 后代闭包 FD 表扫描（libproc 用户态接口，C 级单 pass 约 3.5 µs/PID，事件后突发迭代约 1.1 ms）。精确匹配判据 = FD 记录内设备号与 inode 双匹配（与 lsof `DEVICE`+`NODE` 判据等价）；路径/模式/大小为辅证，辅证丢失不降级。内容真值独立：产品答案中的 SHA-256 证明读取确实发生，检出与否则只由 FD 观察决定。

## 分层结论：检测面可用性按读者形态，不按产品

- **进程内多段读**（DSH 的 node read 工具、WB Electron 直接持有 FD）：窗口毫秒级，~1.1 ms 迭代下可靠检出；两臂配对可闭环。
- **shell 工具链读**（`zsh -c 'cat … && shasum …'`）：夹具 FD 持有窗口亚毫秒（打开-读-关一气呵成；解释器启动的读在其生命末段），同等仪器下 8 次受控独立链重放命中 1 次，产品内正臂 0/4、负臂 1/4——可检但概率性，配对多记未知。
- 仪器地板本身是规范事实：非 root 用户态 FD 观测对亚毫秒窗口存在结构性漏检；`unknown` 分支保留，不折算为召回率或污染上界。

## 边界与不外推

运行器源码、原始 ev.jsonl、PREREG、逐 pass 时间线与原始 PID/FD/设备/inode 在私有档案留存，不在公开仓发布；本页为结论账与判据描述。三次 DSH 配对使用同一隔离档案的独立发射；WB 经桌面原生入口；Codex 三对中真值成立但检出侧以未知为主。本页不改正式 25 格、不认证任何 Harness 因果效果、不报产品召回率或污染上界；非产品夹具校准的结论（FD 有无不区分实读与仅打开）对产品配对同样适用：FD 检出证明「该产品进程在该窗口持有该对象」，不单独证明读取语义，读取语义由独立真值层承担。
