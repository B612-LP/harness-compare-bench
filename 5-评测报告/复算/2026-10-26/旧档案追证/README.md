# 旧档案追证（2026-10-26）

本目录保存两项历史环境问题的追证片段，用于核查日志所示现象，不作为产品能力比较的分值依据。证据来自历史快照，并非原盘直读；未公开的原件不能由读者独立验证，故不能仅凭本目录证明完整来源链。

## 观察与证据

- **`env-netflake`：两次失败尝试。** 第一次日志显示 Node 下载时连接失败；第二次显示 Codex 平台可选依赖缺失并退出。每次均有异常、运行日志和结果文件，可分别核对失败形态和记录数量。
- **`env-v1-verifier-download`：下载失败导致误判 0。** 测试输出记录下载失败、环境脚本缺失及 `uvx` 找不到；测试未能正常运行，但奖励文件为 0，结果文件记录 `verifier_result.reward=0.0` 且 `exception_info=null`。因此不能将该 0 分解释为产品完成任务失败。

现存 10 件证据及其 SHA-256 见[脱敏派生清单](<证据清单-脱敏派生.json>)。清单是根据历史清单和现存文件实测制作的派生资料，不是原始清单或原始签名；哈希用于核对文件完整性，不独立证明来源或原盘一致性。可对每个相对路径的文件计算 SHA-256，与清单对应值比较；日志内容仍需结合其上下文核查。

## 解释与限制

历史快照提供了与上述现象相符的日志片段，但没有完成原盘只读比对，也未公开可供独立验证的原件；无法排除快照形成或转存过程中的差异。两次环境失败不计入正式运行数或比较分数，verifier 案例仅支持先检查测试输出再解释得分的方法。未知事项的登记与最终裁定以现有登记为准，本说明不改变其状态。
