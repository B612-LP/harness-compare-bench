# 读取窗口与粗估单位：既有声明的离线派生复算

> **公开复算不等于原件认证**：原离线科学结果已获独立有限复核 PASS，范围仅为静态 owner 绑定、固定既有声明/源匹配、独立语义重算与20个离线边界向量；不是历史 runtime 认证，也不自动等于本派生包通过验收。本包不是新产品实测，不追认任何旧门、旧分数或未知尝试。所附程序完全自行编写，不含、加载或执行产品专有源码。逐点 JSON 的 pending_at_candidate_generation 如实保留其最初生成时状态。

## 1．结论：减少了哪项不确定性

既有 WorkBuddy 记录中，**13 个合格 Read 粗估声明、来自 12 个会话**，均可由同一默认读取窗口和粗估公式精确解释：最多 2000 行、每行最多 2000 个 UTF16 code units，超长行附截断标记，CRLF 按 LF 拼接，再执行 BMP 特定范围加权、分别向上取整的公式。固定 169860-byte 前缀候选只符合 10/13，全文件 bytes/4 只符合 8/13。

这支持该静态实现作为**已知输入与既有声明的一致解释**，不证明它是唯一可能机制、历史进程必然执行的代码，更不证明整个产品的普遍阈值或实际模型输入上限。13 点全是 ASCII，因此窗口上的 UTF8 bytes / UTF16 units / codepoints 候选都符合 13/13；区分单位靠源码条件语义，而不是这些 ASCII 点本身。

## 3．解释：窗口先于估算，单位并非一般 byte/4

限定为普通 UTF8 文本、源文件小于 262144 bytes、初始无 offset/limit 的默认读取。抽象过程是按 CRLF/LF 拆行，取前 2000 行，每行超过 2000 UTF16 units 时截为 2000 units 并附 `... [truncated]`，再以 LF 拼接。截取 2000 行不必保留第 2000 行之后的边界 LF；本队列没有触发单行截断。

令 `H` 为结果中 U+4E00…U+9FA5 的 BMP 字符个数，`L` 为结果 UTF16 code units：

`estimate = ceil(H / 1.8) + ceil((L − H) / 4)`

两项**分别 ceil**。它发生在行号装饰前，声明里的 `tokens` 是产品自己的粗估命名，**不是实际模型 tokenizer、usage 或费用**。本队列原声明上限均为20000；实现存在环境覆盖入口，不把它说成所有环境下不可变的全产品阈值。空文件还有提示文本分支，不能用空串计为零；本包的空文件等边界仅为实现语义的条件预测。

自行编写的程序按 UTF16 字节截取，不以 Python `len` 或普通切片冒充 substring。若恰切断 surrogate pair，内部字符串仍按原 UTF16 units 计数；UTF8 **展示/哈希测量**以 U+FFFD 替换孤 surrogate，派生 JSON 仅记数值和hash、不直接写入孤 surrogate。测试 `a + 1000 emoji` 得2015 UTF16 units、1016 Python codepoints、4015展示UTF8 bytes、粗估504；这些单位分列，不当成UTF8原文件覆盖量。本队列13个ASCII源不受该边界影响。

P08 的 28978×4=115912 只是 ceil 的覆盖上界，实际选中 115910 bytes；P01 的 42486 与 P09 的 42464 同样反驳统一固定 byte 帽。相同 6000 bytes、不同换行几何可产生 3999 与 6000 bytes 窗口。8 个“汉”预测粗估 5，8 个 emoji 预测 4，“汉a”因分别 ceil 预测 2；这些 **Unicode 预测从未作为新产品校准**。

## 4．限制与反证分支

本包仅检验公开派生几何与已发布承诺是否自洽；原 fixture、参数路径与完整轨迹的真实性/完整性仍依赖私档，公开 hash 不是独立认证。匿名化同一性由私有导出前后比对与 hash 承诺支持，公开者无法只靠匿名源恢复原文。未附任何 HTTP raw request，也不把派生 JSON hash 冒充原请求 hash。

静态 source pin 不等于 runtime attestation：历史版本、环境覆盖与入口 fallback 未观测。全 13 点匹配不排除其他等价解释，不外推产品全集。此前未获验证的 Unicode 产品尝试仍是 **unknown、已停止**；本包新增产品样本数 **0**。计数不提供显著性推断，不更改原实验阈值、判卷或分数。

若声明、最大值、source 绑定或真实窗口任一点不一致，则该点不能计入精确匹配；不能删除 alt、早期大文件或 176k 点来保留固定帽解释。若后来证明历史入口不同，应下调机制归因而不是把 source hash 当运行证明。

## 5．复算与反例

需 Python 3.9+ 标准库，无网络、模型、产品、Node、第三方包、凭据或写权限。程序使用显式异常检查，`-O` 不移除验收逻辑；命令本身只读（`-B` 禁止 bytecode 缓存）。在本目录运行：

```sh
python3 -B verify.py
python3 -B test_verify.py
python3 -B -O test_verify.py
```

[独立复算器](<verify.py>)与[测试](<test_verify.py>)覆盖改声明/阈值/窗口覆盖、长行 UTF16 截断、CRLF、hybrid separate-ceil、Unicode 单位、原/派生 hash 混淆、缺点/重复点及排除计数等反例。[完整清单](<SHA256SUMS.json>)绑定除其自身外的所有文件；拒绝额外文件与 symlink。清单用于本包一致性，不是外部真实性签名。
