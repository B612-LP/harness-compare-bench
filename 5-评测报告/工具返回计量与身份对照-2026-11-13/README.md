# 工具返回计量与身份对照（2026-11-13）

**当前结论：DSH这组客户端记录中的全文保留与工具身份关联，不能只用先后阶段解释；豆包三份已归档Read均是显式头尾窗口，不是仅尾部。** 二者均不证明实际模型摄入，也不改变正式25格或历史分数。

## 1. 断言与可推翻分支

- **身份 vs 阶段**：同一40,000B ASCII正文、同一工具factory/schema/renderer，比较`read`/普通别名`observation_output`分别出现在首次、一次已裁剪warmup之后。若只是阶段门，身份不应在两个阶段稳定分出全文/裁剪；四格混合则保留未知。
- **保留形状**：直接读取完整工具字符串，检查闭合包装和显式Head/Tail标签，逐窗口计量；marker在开头不等于头部为零。ASCII记录的codepoint、UTF16单位、UTF8字节相等，**不能据此认定非ASCII窗口单位**。
- 两个问题是客户端返回表示的机制证据，不是五产品能力或成本排名；正式历史仍按A/B/W分轨。

## 2. 观察与结果

### DSH：四格反证stage-only

记录版本`0.2.0-rc.2`，cap配置`8192`；正常注册的合成工具，native fs禁用。本地脚本响应驱动四个原生CLI会话，10个客户端请求、6份同源工具回调；本relay上游attempt=0、真实模型试验=0，脚本最终OK不作能力得分。

|工具身份|阶段|请求工具面 bytes|保留原文 bytes|包装 bytes|省略 bytes|
|---|---|---:|---:|---:|---:|
|read|首次|40,000|40,000|0|0|
|read|warmup裁剪后|40,000|40,000|0|0|
|observation_output|首次|32,700|32,444|256|7,556|
|observation_output|warmup裁剪后|32,700|32,444|256|7,556|

普通别名保留源区间`[0,16224)+[23780,40000)`；两个warmup各保留`[0,16224)+[23776,40000)`，原文32,448B、包装251B、总32,699B、省略7,552B，各自从r2到r3完整内容hash不变。不同会话路径不同，**不声称跨会话包装hash相同**。

`40000−4×(8192−80)=7552`只吻合warmup；普通别名实为7,556，**+4B残差保留**，包装多5B使总面多1B。不能据主门通过宣布普遍精确常数。

四首请求的格式化JSON文件hash各自一致，wire请求体hash也各自一致，但二者不同，已分列，避免把格式化文件称wire原文。

### 豆包：三份完整ASCII工具字符串

|记录|完整字符串字符/bytes|head|tail|包装|原工具输出声明 bytes|
|---|---:|---:|---:|---:|---:|
|a|4,272|2,048|2,048|176|83,688|
|b|4,272|2,048|2,048|176|83,688|
|c|4,274|2,048|2,048|178|100,569|

窗口之外的176/178是包装；2字符差来自原大小声明，不是窗口扩大。a/b完整工具字符串hash相同，不算独立机制重复。这里只复核表示，历史其中一份夹具的重复记录缺陷没有被恢复为有效任务得分。

另一个易混口径：某次5份工具字符串长度为`4272+346+1300+369+147=6434`；全join的4个换行才得到**6438**。补偿部分净和是**2162**，加3个换行是**2165**；6438不是首Read大小，也不是补偿量。后续带limit的Read还可出现不同表示，不能泛化所有工具固定4.27K。

## 3. 解释、竞争解释与研究前后变化

- **前**：先前“首层受门、后阶段read旁路”的说法把工具身份与阶段混在一起；仅看marker位置又可能误判tail-only。
- **后**：四格足以拒绝本设计中的stage-only解释；支持此版本、此合成请求面的身份关联例外。工具name与包含name的call_id共同变化，未隔离为“纯名字字符串唯一因果”；特殊类映射、关联元数据等实现解释仍未区分。
- 豆包只确认三份本地轨迹Read的显式head+tail，不能从同一前端/日志面区分日志截断、显示层、共享包装组件或模型上下文中的哪个层负责。

## 5. 边界与来源缺口

公开材料是**选择、去标识后的派生文本，不是完整原始轨迹或封印原件**。DSH私人spill路径替换为同UTF8字节数占位符，保留源正文及计量关系；原工具字符串hash与派生hash分列。豆包选择的合成文本无路径改写，其完整content hash可复算，但完整CID/轨迹/执行来源仍只在私档核对。

重算器输出`DERIVED_RELATIONSHIPS_PASS`仅指公开派生内部关系，不认证完整运行、来源真实性、可信执行时间、产品二进制或服务器收件。各格n=1、未跨版本；native fs及实际模型利用未测试，后端上下文、思考与cache未知。bytes≠tokens≠成本；零上游仅限本relay账本，不是整机零网络证明。真实产品检测面结论仍限“在当前检测面未观察到”，不套用合成漏检率。
