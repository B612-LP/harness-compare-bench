# 历史评测复核公开摘要

本摘要是对历史分析中与评测有关内容的中立整理，**不是原始审计报告、认证摘录或新的独立审计**。历史原件不公开，原件内容及其形成、修改的时序无法通过公开材料独立验证；下列历史记录不应视为对现状的重新验收，也不以历史时间或提交记录为本摘要背书。原始评测证据和收据未因本摘要而改写。

## 数字勘误与解释限制

- 历史报告中 r1030 DSH 五题 weighted 合计原发布为 **414.07**，历史复核按五项分数相加得到 **444.07**；Codex 为 **444.81**，两者差值为 **0.74**，而非原先的 **30.74**。原报告将 414.07 的来源列为可能的汇总抄录错误，该解释只是成因假说。
- 每格仅一次运行时，观察到的差异无法与单场波动区分，不能单凭该结果断言差异的成因或稳定性；重复实验应结合其具体证据和限制单独判断。
- 历史验收矩阵中曾同时出现测试汇总通过与针对已作废原始数值的对照不匹配；二者含义不同，不应只凭汇总字段判断原数字正确。

## 历史分析中记录的其他限制

- 历史冻结配置引用的工作台账版本，与另一份台账追加的 5 项自测及 2 项预检记录存在差异；历史复核称这些记录未进入当时的机读六类分账，但不影响所分析的 10 场正式运行得分。该记录不能替代对当前台账的核验。
- B13a 判卷合同历史回放的既有收据所指合同字节与并入后的合同不同；因此，不能仅凭该收据断言并入后的合同已完成同一组历史回放。历史记录还指出报告表格与刷新后 JSON 的匹配数分别为 15/24 与 16/24。后续是否完成补充回放，应查验对应独立收据。
- 批次前缀在历史记录中有复用，人工引用时应以完整运行 ID 和批次消歧。流式响应可能将文本拆分成多个增量，检索前需按顺序拼装；跨产品的绝对 token 数不宜直接比较。
- 历史复核未通过 Git 命令独立核验其所述提交先后关系，也未重新执行所引用的洁净室复核。相关历史时序和原预注册原件无法公开独立核验，不应据此断言先后顺序已经得到公开证明。

## 可复算口径

历史记录给出的总分复算方法为：分别对每款产品五场 `checker.stdout.json` 中的 `weighted` 求和；亦可按相应判卷规则从 `checks[]` 重算各场权重分数。复算结果的意义仍取决于输入、规则版本及证据有效性，不能替代对完整证据链的审查。
