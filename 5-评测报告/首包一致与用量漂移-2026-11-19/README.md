# 历史六对：相同首包，仍可有不同的自报输出

既有六对捕获中，**第一条请求的原字节 6/6 相同，但该首包 `message_delta` 的最终自报输出计数 3/6 不同**。三个差分别为 −5、−5、−40（下表统一为 bounded − inline）。在第一条捕获请求发出时，尚无第一条工具结果可供回传。这反驳了「只凭相同首包，就可假定这两臂的计量轨迹相同」。输入、缓存写入、缓存读取三个首包所报计数各为 6/6 等值；这不是实际思考或实际缓存等控。

次包的输入、缓存读取和最终输出三个计数分别为 6/6 不同，但缓存读取差**方向不一**（4 减、2 增）。首包输出差不是工具回传呈现差的证据，次包计数差也不能由工具正文或请求字节直接换算。[同一批次的包体逐字段复核](<../首包平衡与次包单叶置换-2026-11-19/README.md>)另证次包差异含工具正文、绑定 ID 与第一次响应的回放；它没有把这里的用量归因给任一字段。

## 计数口径与公开复算

- 以[既有公开六对档案](<../../3-表现现场/r20261103-input-bytes/README.md>)的 12 份 `reported-usage.json` 为范围：按块、臂及 `01-request.json` / `02-request.json` 标签核对。首包等值来自已发布的包体派生证明，复算器不会读取捕获原件。24 条派生请求各恰含一个 `message_start` 和一个 `message_delta`，两者不是两次调用。
- 每条请求前三项输入侧计数的 start/delta 值一致（72/72）；比较使用两阶段一致的值，不相加。输出只取显式 `message_delta`，不把两个阶段合加。重复键、错块/请求或阶段标签、布尔冒充整数、缺少已报字段或阶段冲突不补零。
- `python3 -IB verify.py --self-test` 从当前公开树中只重读 13 个由长度和 SHA-256 固定的公开文件，验证表和分母。`-O` 结果相同。内存反例无新请求；非作者也独立从这 13 份公开材料重算过。工具不验证私有捕获内容、服务端响应归属或计量真伪。

**边界：** 这是历史档案的离线负对照，不改变原试验、正式 25 格或成绩。没有真实新干预、模型执行、费率或产品横比；不估 actual reasoning、实际 cache、收费 token/成本、服务端摄入或 Harness 效果。公开 sidecar 是已报告的辅助记录，不当成权威消费账单。
