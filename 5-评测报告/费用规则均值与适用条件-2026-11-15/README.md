## 公开规则重算

[手册](<../../2-用例/dabstep-payments-10/inputs/manual.md>)说 null 表示该字段适用所有可能取值，并给出 `fixed_amount + rate × transaction_value / 10000`；只按 GlobalCard、`is_credit` 分类，下表每条规则取 10 EUR 计算后等权平均。**并未匹配交易的其他条件，也未建立 144 条都适用于同一笔交易。**例如这 144 条中，ACI 列表仅为 `[B]` 的有 23 条、仅为 `[C]` 的有 13 条；一笔交易的同一个 ACI 不可能同时满足这两组。

| `is_credit` | 规则数 | 费用和（EUR） | 规则等权均值（EUR，约） |
|---|---:|---:|---:|
| true | 123 | 14.473 | 0.1176666667 |
| null | 21 | 2.826 | 0.1345714286 |
| true + null | 144 | 17.299 | 0.1201319444 |

用 Decimal 直接对未舍入总和/数量取六位，这里选择 **ROUND_HALF_UP** 得 `0.120132`；题目要求六位，未指定该舍入模式，此选择不作为题目原约定。该计算复现既有 gold，不意味着真实收费表、规则覆盖或优先级已得到验证；null 通配不等于空列表通配，也不能推定未匹配交易收费为零。

## 为什么平均口径需要明确

自造互斥规则 A、B 各收费 0.1、0.3 EUR；三笔自造交易依次只匹配 A、A、B。规则等权平均为 `0.2` EUR，按交易等权平均为 `(0.1 + 0.1 + 0.3) / 3 = 1/6` EUR。它只说明两个定义在一个条件化例子中不恒等，不是历史交易、实际收费或新产品试验。题面没有明确规则总体或实际交易分布；[用例说明](<../../2-用例/dabstep-payments-10/spec.md>)记录的独立规则等权复算与既有 gold 相符，并非其产生来源；说明记载 gold 来自上游 dev 划分，但本次未能直接取得上游原件复验该题。既有真值仍按原规则保存。多条件规则、重叠优先级、真实交易频率和模型实际计算过程仍未知。
